## Дефект 1. Запрет на акции обходился через файл замеров

### Как было

В настройках владельца:

```
AUTO_PICK_GROUPS = ["Forex"]
```

Отбор идёт в два этапа. Первый — дешёвый, по описанию контракта; там
фильтр по разделу работает:

```python
if not in_allowed_group(item.get("path"), groups):
    rejected.append(f"{name}: не из разрешённого раздела ...")
    continue
```

Но окончательный выбор берёт **файл замеров**:

```python
result = symbol_picker.pick(
    symbol_cache.usable_rows(cached, available), equity,
    limit=..., max_risk_percent=..., max_spread_ratio=..., per_currency=...)
```

Ни `usable_rows`, ни `pick` раздел не проверяют. И проверить не могли:
второй этап (`survey_symbol`) возвращал замер **без поля `path`** —

```python
return {
    "symbol": symbol,
    "spread_points": spread_points,
    "atr_points": atr_points,
    "min_lot": ...,
    "stop_points": ...,
    "money_per_point": ...,
    "trade_mode": getattr(info, "trade_mode", None),
}
```

Поле `path` читалось только в `contract_facts` — на первом этапе — и до
файла не доходило.

### Чем это било по шагам

1. Инструмент попадал в файл замеров (например, когда настройки
   `AUTO_PICK_GROUPS` ещё не существовало или она была пустой).
2. При следующем запуске первый этап его отсеивал — но замер уже лежал в
   файле.
3. Окончательный выбор читал файл целиком, раздел проверить было нечем.
4. Инструмент выбирался и торговался — **навсегда**, независимо от
   настройки.

Отсюда акции на валютном счёте. И дело не только в разделе: 7 акций AUPH
по 16,71 — позиция на 117 долларов при счёте 384. Расчёт размера сделки
считался на валютных парах, где минимальный лот стоит копейки.

### Как стало

```python
# survey_symbol
    "trade_mode": getattr(info, "trade_mode", None),
    "path": str(getattr(info, "path", "") or ""),
}
```

```python
# auto_pick_symbols
пригодные, чужой_раздел = symbol_picker.only_allowed_groups(
    symbol_cache.usable_rows(cached, available),
    tuple(getattr(cfg, "AUTO_PICK_GROUPS", symbol_picker.DEFAULT_GROUPS) or ()))
if чужой_раздел:
    log.warning("Отбор пар: отброшено не из разрешённого раздела: %d (%s)", ...)

result = symbol_picker.pick(пригодные, equity, ...)
```

`only_allowed_groups` — новая функция в `symbol_picker.py`,
**отказобезопасная**: замер без известного раздела считается
НЕподходящим.

Версия файла замеров поднята `VERSION = 1` → `2`. Файлы прежнего формата
раздела не содержат, читать их — значит оставить дыру; поэтому они не
читаются, а перемеряются.

### Проверка «наоборот»

| Что сломано | Что упало |
|---|---|
| `survey_symbol` больше не кладёт `path` | `СБОЙ survey_symbol кладёт «path» в замер` → 11/1 |
| `VERSION` возвращена в 1 | `СБОЙ Файл версии 1 не читается -> {'AUPH': ...}`, `СБОЙ Версия формата поднята до 2 -> 1` → 10/2 |

После возврата кода — `Пройдено: 12   Сбоев: 0`.

## Дефект 2. Остановку по происшествию нельзя было снять

### Как было

Механизм разбора написан целиком: `control.сверить_инцидент()` идёт в
`reconcile.выяснить`, смотрит позиции, активные заявки, историю заявок и
историю сделок и выносит вердикт; `control.разрешить_инцидент()` снимает
запрет **только по доказательству**.

`grep` по всему коду: `control.разрешить_инцидент` и
`control.снять_инцидент` не вызываются **ниоткуда** — ни из окна, ни из
дашборда.

### Чем било

Торговля у владельца встала на «4 заявки без позиции» и не могла
возобновиться никаким действием из программы. Правильный, продуманный
предохранитель превратился в тупик.

### Как стало

Кнопка «Разобрать происшествие» на «Обзоре», в ряду «Действия».
Показывает факты с номерами заявок. Снимает запрет только при
`вердикт.доказан`; иначе пишет, почему нет, и оставляет запрет.

Принудительного снятия кнопкой **не сделано** намеренно.

### Проверка «наоборот»

Условие `if not вердикт.доказан:` заменено на `if False:`.

```
СБОЙ ЗАПРЕТ НЕ СНЯТ — программа не поверила «позиции не вижу»
СБОЙ И сказано прямо, что исход не доказан
Пройдено: 7   Сбоев: 2
```

После возврата — `Пройдено: 9   Сбоев: 0`.

## Чего тесты НЕ проверяют

1. **Что у брокера раздел называется именно так.** Проверяется правило
   разбора строки, а не справочник конкретного брокера. Если MetaQuotes
   отдаёт раздел в неожиданном виде, отсев может выбросить лишнее — это
   будет видно как «пар не отобрано» на «Обзоре», а не как молчание.
2. **Верность самого разбора происшествия.** Вердикт выносит `reconcile`
   по данным терминала; терминала в проверке нет. Проверяется решение
   кнопки по готовому вердикту.
3. **Что случилось с четырьмя заявками у владельца.** Это выяснит кнопка
   на его машине. Здесь этого узнать нельзя.
4. **Поведение у настоящего брокера.** Зелёные тесты с поддельным
   брокером **не являются** доказательством. Действует всегда.

## Мои ошибки

**Дефект 1 — мой.** Фильтр `AUTO_PICK_GROUPS` я поставил только на
первый этап и не проверил, что второй путь его обходит. Владелец потерял
на этом часть из 115,29 — точную долю назвать не могу, разбор по сделкам
не делался.

**Дефект 2 — тоже мой.** Написал предохранитель и не оставил способа его
снять. Это второй случай подряд той же породы: до этого так же не было
доступа к настройкам барьера.

Отдельно: я дважды просил владельца прислать данные, вместо того чтобы
сразу сделать так, чтобы программа сама всё показывала.

## Что сознательно не сделано

* **Разбор 115,29 по сделкам не проводился.** Сколько именно потеряно на
  акциях против валюты — не считал. Для этого нужна выгрузка истории с
  машины владельца.
* **Принудительное снятие происшествия кнопкой** не сделано.
* **Размер позиции для не-валютных инструментов** не пересчитывался:
  вместо этого они просто не допускаются к торговле.

## Что работа НЕ меняет

Стратегия, риск, лот, стопы, тейки и индикаторы не тронуты. Сделаны:
отсев инструментов не из разрешённого раздела и доступ к уже
существовавшему разбору происшествия. **Ни одного утверждения об
улучшении прибыльности здесь нет.** Убыток 115,29 этой правкой не
возвращается — она лишь закрывает путь, которым он возник.
