## 2. ДЕФЕКТ ПОДТВЕРЖДЁН

Было:

```python
10023: (ОКОНЧАТЕЛЬНО, "состояние заявки изменилось"),
10028: (ПОВТОРИТЬ, "заявка занята обработкой — попробовать позже"),
```

В документации MetaTrader 5 эти коды описаны как **«Order state changed»**
и **«Request locked for processing»**. Ни то, ни другое не утверждает, что
заявка **не исполнена** — в отличие от «отклонена», «отменена» или
«неверная заявка», где об исходе сказано прямо.

### Вред у обеих ошибок разный, но одинаково реальный

| Код | Что делала программа | Чем это било |
|---|---|---|
| **10023** | считала окончательным отказом → шла дальше | следующая сделка могла открыться поверх уже исполненной заявки |
| **10028** | считала поводом для повтора → слала заявку снова | вторая заявка поверх первой |

Это тот же самый fail-open, который И1-C закрывал для незнакомых кодов.
Разница только в источнике: там код был неизвестен, здесь — известен, но
классифицирован по догадке о его смысле.

## 3. ЧТО СТАЛО

```python
10023: (НЕОПРЕДЕЛЁННО, "состояние заявки изменилось — исполнилась она "
                       "или нет, нужно сверить"),
10028: (НЕОПРЕДЕЛЁННО, "заявка занята обработкой на сервере — "
                       "исполнилась она или нет, нужно сверить"),
```

Оба кода теперь ведут в уже построенный путь: номер заявки сохраняется,
работает доказательная сверка (заявка → сделка → позиция), а неполнота
даёт остановку с показом номера заявки оператору.

**Важно:** это не означает «останавливаться всегда». Если сверка докажет,
что заявка отменена без сделки, — работа продолжается без остановки. Это
проверено отдельным контрольным тестом.
