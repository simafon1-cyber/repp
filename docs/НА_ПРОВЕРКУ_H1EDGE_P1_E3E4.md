## 1. ЗАДАНИЕ СВОИМИ СЛОВАМИ

Аудит принял основу исполнителя, но нашёл два блокирующих дефекта.

**P1-E3.** Написано «OOS не читается, пока не посчитаны train и
validation». Проверено, что порядок ВЫЗОВОВ соблюдён. Но внутри вызова
файл читался ЦЕЛИКОМ, и срез отбирался уже из готового списка. То есть
строки OOS оказывались в памяти с первой секунды прогона. Барьер был
ложный.

**P1-E4.** Написано «OOS открывается один раз». Ничем не обеспечено.
После неудобного числа можно запустить прогон снова: аргумент `--вывод`
принимал любой путь, а запись шла режимом «затереть». Одноразовость была
намерением, а не механизмом.

Требовалось: сделать барьер физическим, одноразовость — принудительной,
доказать это отрицательными тестами и повторно вынести на приёмку. Считать
на настоящих данных — нельзя.

## 2. P1-E3: БАРЬЕР OOS СТАЛ ФИЗИЧЕСКИМ

### Как было (дословно)

```python
def _ряд_из_файла(путь):
    """Свечи в том виде, который понимает entry_lab."""
    бары = []
    with open(путь, encoding="utf-8") as f:
        next(f, None)
        for строка in f:
            ...
            бары.append({...})
    return бары


def сделки_среза(папка_h1, инструмент, часть):
    путь = os.path.join(папка_h1, f"{инструмент}_H1.csv")
    все = _ряд_из_файла(путь)                       # ВЕСЬ файл, включая OOS
    начало = datetime.fromisoformat(часть["начало_utc"]).timestamp()
    конец = datetime.fromisoformat(часть["конец_utc"]).timestamp()
    кусок = [б for б in все if начало <= б["time"] <= конец]
```

### Чем это било по шагам

1. Прогон вызывает `сделки_среза(..., часть=train)`.
2. Первая же строка внутри читает **весь** CSV — четыре года часовых
   свечей, вместе с невиданным последним четвертью.
3. Фильтр отбрасывает лишнее **уже после** чтения.
4. Существовавший тест порядка следил за тем, кого позвали. Он видел
   «позвали train» и был доволен. Он не мог увидеть, что при этом
   прочитано.
5. Итог: заявление «невиданные данные не открывались до финального шага»
   было неверным для любого прогона, включая будущий единственный.

### Как стало (дословно)

```python
def _построчно(путь):
    """Строки файла ПО ОДНОЙ, лениво, без заголовка."""
    with open(путь, encoding="utf-8") as f:
        next(f, None)          # заголовок
        for строка in f:
            yield строка


def _ряд_среза(путь: str, начало: float, конец: float, сколько: int):
    """Свечи ТОЛЬКО внутри [начало; конец], ровно «сколько» штук."""
    бары = []
    поток = _построчно(путь)
    try:
        for строка in поток:
            ...
            t = int(ч[0])
            if t < начало:
                continue
            if t > конец:
                break          # запасной рубеж: данные разошлись с границами
            бары.append({...})
            if len(бары) >= сколько:
                break          # срез набран — дальше файл нас не касается
    finally:
        закрыть = getattr(поток, "close", None)
        if закрыть is not None:
            закрыть()
    return бары
```

Вызов стал: `кусок = _ряд_среза(путь, начало, конец, int(часть["баров"]))`.

Функции `_ряд_из_файла` в файле больше нет — не «не используется», а
удалена. Загрузчика, читающего дальше конца своего среза, в прогоне не
осталось.

### Отдельно: почему остановка по СЧЁТУ, а не «на первой свече правее конца»

Первый вариант обрывал чтение на первой свече с временем больше конца
среза. Он выглядел естественнее — и **он всё ещё протекал**. Мой
собственный тест это показал:

```
СБОЙ До открытия OOS не прочитано НИ ОДНОЙ строки из OOS
     -> прочитано лишних 2, первая 1704794400 при границе 1704794400
```

Чтобы **увидеть** свечу правее конца, её надо **прочитать**. А для
validation эта свеча и есть первая свеча OOS. Одна строка невиданных
данных на каждый инструмент — на настоящем прогоне это три строки.

Число баров каждого среза заранее записано в файле границ и сверяется
проверкой 4, поэтому остановка по счёту законна: срез набран — читать
дальше незачем. Условие «правее конца» оставлено вторым рубежом на случай,
если данные всё же разойдутся с границами.

### Как проверено

Тест `test_при_train_и_validation_ни_одна_строка_oos_не_прочитана`
подменяет **построчный источник** и записывает каждую выданную строку,
а также отмечает, сколько было прочитано к моменту открытия OOS.
Проверяется факт: среди прочитанного до этого момента нет ни одной
отметки времени из OOS.

В тесте есть и обратная страховка: отдельно проверяется, что **после**
открытия OOS его строки действительно читаются. Без неё тест прошёл бы и
на прогоне, который OOS не читает вовсе — «ничего не прочитано» тоже даёт
пустой список лишних.

## 3. P1-E4: ОДНОРАЗОВОСТЬ OOS СТАЛА ПРИНУДИТЕЛЬНОЙ

### Как было (дословно)

```python
    р.add_argument("--вывод", default=os.path.join(КОРЕНЬ, "research",
                                                   "h1_edge_results.json"))
...
def _записать(путь: str, ответ: dict):
    os.makedirs(os.path.dirname(путь), exist_ok=True)
    with open(путь, "w", encoding="utf-8") as f:
        json.dump(ответ, f, ensure_ascii=False, indent=1)
```

### Чем это било по шагам

1. Прогон выполнен, число не понравилось.
2. `python3 run_h1_edge_study.py` запускается снова — ничто не мешает.
3. OOS читается второй раз. Предрегистрация после этого недействительна:
   невиданные данные перестали быть невиданными.
4. Даже путь менять не надо — режим `"w"` затрёт прошлый файл молча. А
   если хочется сохранить оба, есть `--вывод` с любым путём.
5. История git делает сокрытие труднее, но не делает контроль
   fail-closed: она фиксирует то, что закоммитили, а не то, что запускали.

### Как стало (дословно)

Путь зафиксирован в коде, аргументов у прогона больше нет:

```python
РЕЗУЛЬТАТ = os.path.join(КОРЕНЬ, "research", "h1_edge_results.json")
МАРКЕР = os.path.join(КОРЕНЬ, "research", "h1_edge_oos_открыт.json")
...
    # Ни одного аргумента. Раньше был --вывод, и он же был дырой.
    р.parse_args(аргументы)
```

Отметка ставится **до первого чтения OOS**, атомарно:

```python
def _занять_oos(паспорт: dict) -> dict:
    отметка = dict(_отпечатки(паспорт))
    отметка["ревизия"] = _ревизия()
    отметка["когда_utc"] = datetime.now(timezone.utc).isoformat()
    os.makedirs(os.path.dirname(МАРКЕР), exist_ok=True)
    ф = os.open(МАРКЕР, os.O_CREAT | os.O_EXCL | os.O_WRONLY, 0o444)
    with os.fdopen(ф, "w", encoding="utf-8") as f:
        json.dump(отметка, f, ensure_ascii=False, indent=1)
    return отметка
```

Результат пишется тем же режимом:

```python
    ф = os.open(путь, os.O_CREAT | os.O_EXCL | os.O_WRONLY, 0o444)
```

`проверка_6_одноразовость` разбирает четыре состояния, и три из них —
отказ:

| Состояние | Решение |
|---|---|
| отметки нет, результата нет | первая попытка — можно |
| отметка есть и совпала с входами | уже смотрели — **отказ, код 5** |
| отметка есть, но от других входов | не про этот прогон — **отказ, код 5** |
| отметки нет, а результат есть | отметку удалили — **ИНЦИДЕНТ, код 5** |

Последняя строка — суть требования. Если удаление файла работает как
разрешение начать заново, вся защита стоит одну команду.

`УжеОткрывали` — отдельная ошибка, наследник `Стоп`, со своим кодом
возврата **5**. Её ветка в `main()` стоит **выше** общей: при обратном
порядке её ловила бы общая ветка, и «вы это уже смотрели» выглядело бы
как «данные не сошлись».

### Коды возврата

```
0  прогон прошёл, решение принято
2  проверка не сошлась (данные, паспорт, срезы, издержки)
3  непредвиденная ошибка
4  сделок меньше порога — НЕТ ВЫВОДА, это не провал гипотезы
5  OOS уже открывали, либо результат уже существует
```

### Отметка и результат теперь коммитятся

`research/` был целиком скрыт от git. Отметка, лежащая вне репозитория,
внешнему проверяющему ничего не доказывает. В `.gitignore` сделаны два
именных исключения:

```
research/*
!research/h1_edge_results.json
!research/h1_edge_oos_открыт.json
```

Написано `research/*`, а не `research/`: из скрытого **каталога** git не
позволяет вернуть отдельный файл. Проверено фактом — `мусор.json` в том же
каталоге остаётся скрытым, а эти два файла видны.

## 4. ПАСПОРТ ЗАВЕРЕН ЗАНОВО

Раздел `исполнитель` описывал девять требований словами, и оба дефекта
помещались внутрь этих слов. Теперь там записаны механизмы:

* чтение среза построчно с обрывом по числу баров; загрузка файла целиком
  с последующей фильтрацией **запрещена прямо**;
* отметка на диске режимом «создать, только если файла нет» до первого
  чтения OOS; отказ **до чтения** при её наличии; запись результата тем же
  режимом; путь результата в коде, аргумента нет;
* отметка от чужих данных и результат без отметки — **инцидент**.

Печать: `37e3146d…` → `7e21726c…`. Паспорт закоммичен **отдельным
коммитом, предшествующим правке исполнителя** — порядок коммитов виден в
истории и подделать его нельзя. Результатов в ветке нет.

Исходное: **67 из 67, сбоев 0**.

| Что сломал | Стало | Что упало |
|---|---|---|

| Убрал `проверка_6_одноразовость` | 65 из 67, сбоев 2 | «ни один срез не читался → прочитано срезов **4**»; «OOS второй раз не открывали → прочитано срезов **6**» |
| Результат пишется режимом `"w"` | 65 из 67, сбоев 2 | «Вторая запись отвергнута ошибкой» — не отвергнута |
| Результат без отметки считается разрешением | 66 из 67, сбоев 1 | «OOS второй раз не открывали → прочитано срезов **6**» |
| Отметка ставится режимом `"w"`, не атомарно | 65 из 67, сбоев 2 | «на диске осталась ПЕРВАЯ отметка → **bbbbbbbb**» |

Все шесть поломок ловятся.

### Два теста проходили по ЧУЖОЙ причине — шестой и седьмой случай подряд

Пишу это отдельно, потому что это уже закономерность, а не случайность.

**Первый.** `test_удалённая_отметка_это_инцидент` при выключенной защите
дал **67 из 67 без сбоев**. Разбор: без защиты прогон доходил до конца,
**читал OOS второй раз** и спотыкался лишь на записи результата. Код
возврата всё равно 5, файл результата всё равно цел — а невиданные данные
уже посмотрели дважды. Тест проверял код и целость файла, то есть
последствия, а не то, что должен был: факт чтения. Переписан на слежение
за чтением срезов.

**Второй.** Поломка «отметка ставится режимом `"w"`» тоже не роняла
ничего: до неё срабатывала `проверка_6`, и защита выглядела рабочей, хотя
её последний рубеж был снят. Добавлен отдельный тест
`test_отметка_ставится_атомарно_а_не_поверх_старой`, который проверяет
само создание, минуя проверку 6.

Прежние случаи: подделка, игнорировавшая фильтр; тест, не включённый в
список запуска; проверка, не поймавшая расчёт по тику; два инструмента
вместо трёх; порча архива вместо записи в паспорте; «любой ненулевой код»
вместо конкретного.

Закономерность своя и одна и та же: **я проверяю последствие, а не сам
запрещённый поступок.** Код возврата, целость файла, возвращённое
значение — всё это может совпасть и при сломанной защите. Ловит только
проверка самого действия: что прочитано, что записано, в каком порядке.

## 7. ЧЕГО ЭТИ ТЕСТЫ НЕ ПРОВЕРЯЮТ

1. **Результат исследования.** Он не считался.
2. **Настоящие данные.** Все тесты идут на синтетических рядах. Зелёный
   тест на подделке **не является** доказательством поведения на
   настоящем архиве и у настоящего брокера.
3. **Одновременный запуск двух копий.** `O_EXCL` защищает от гонки на
   одной файловой системе; сетевые файловые системы сюда не входят.
4. **Злой умысел с правами root.** Файл можно удалить вместе с
   результатом, и тогда прогон снова сочтёт себя первым. Защита сделана
   от «руки потянулись повторить», а не от подлога. Коммит отметки в git
   закрывает и это — но только если коммит сделан.
