## 3. ЧТО СДЕЛАНО

### 3.1. `costs.py` — модель издержек с версией

Фиксируется до прогона и печатается перед ним. Спред по свече входа,
комиссия за круг, своп по переходам через полночь (разный для покупки и
продажи).

**Стоимость пункта считается по-разному** для пар с долларом справа и
слева. На USDJPY при курсе 150 пункт стоит в 150 раз меньше; считать их
одинаково значило бы ошибиться в разы.

### 3.2. Найдено в данных: нулевой спред

У части свечей выгруженной истории спред записан **нулём**: у EURUSD
таких **67 %**, у USDCHF 31 %, у золота 9 %.

Нулевого спреда не бывает — это «не записано», а не «бесплатно». Считать
по нулю значило бы занизить издержки ровно там, где их больше всего.

Введена нижняя граница по инструментам — медианы **ненулевых** спредов из
той же истории, зафиксированные в модели и печатаемые перед прогоном.

### 3.3. `entry_lab.сделка()` — полная запись

Время входа и выхода, инструмент, направление, цены, причина выхода,
грязная прибыль, спред, комиссия, своп, издержки всего, чистая прибыль,
результат в R. Параметра `издержки_r`, который никто не передавал, больше
нет — проверяется тестом по дереву разбора.

### 3.4. `ledger.py` — журнал и сверка

После прогона файл читается **заново**, метрики пересчитываются из него и
сравниваются с напечатанными. Расхождение объявляется провалом прогона.

### 3.5. Найдено первым полным прогоном: журнал не влезал в память

Журнал за **один** отрезок из трёх весит 144 МБ, а сверка читала его
целиком. На трёх отрезках это уронило бы прогон в самом конце, когда всё
уже посчитано.

Сверка переведена на **потоковый счёт**: файл читается один раз, суммы
накапливаются по ходу. Совпадение потокового и обычного расчётов до
копейки проверяется отдельным тестом — иначе сверка сравнивала бы два
разных расчёта.

Память на полном прогоне: **891 МБ из 16 ГБ**.

## 5. ГЛАВНОЕ: НАСКОЛЬКО Я ОШИБАЛСЯ

### 5.1. Движение цены измерялось верно

Грязные числа нового прогона совпали с первой версией отчёта **до
последнего знака**:

| Инструмент | TRAIN | VALIDATION | OOS |
|---|---|---|---|
| EURUSD | +0.0214 | +0.0030 | +0.0254 |
| XAUUSD | −0.0264 | −0.0631 | −0.0293 |

Значит, ошибка была **только** в издержках.

### 5.2. Издержки были занижены впятеро

| | Старая ручная оценка | Новый прогон |
|---|---|---|
| EURUSD | 0.0316 R | **0.1348 R** |
| USDCHF | 0.1714 R | **0.2796 R** |
| XAUUSD | 0.0038 R | **0.0102 R** |

Причина: **я считал только спред**. А на валютах решает **комиссия**.

Стоп в 2 ATR на M5 — это 40–90 долларов риска. Комиссия 7 долларов за
круг съедает 8–16 % такого риска, то есть втрое-впятеро больше спреда.

### 5.3. Что стало с итоговой таблицей

| Инструмент | Старая (ручная) OOS | Новая (прогоном) OOS |
|---|---|---|
| EURUSD | −0.0062 | **−0.1433** |
| USDJPY | −0.0250 | **−0.2036** |
| USDCAD | **+0.0054** | **−0.1825** |
| AUDUSD | **+0.0192** | **−0.1612** |
| XAUUSD | −0.0331 | −0.0453 |

Два инструмента в старой таблице были на OOS **в плюсе**. В настоящем
расчёте они глубоко в минусе. Вывод «0 из 7» держался и тогда — но
держался он на «частично», а не на «все в минусе».

### 5.4. Что стало видно нового

Провал оказался **двойным и по разным причинам**:

* **Валюты** — движение цены в плюс, но меньше издержек в 3–10 раз.
  Преимущество есть, но оно дешевле, чем право в нём поучаствовать.
* **Золото** — издержки почти нулевые (1 % риска), а результат всё равно
  отрицательный. Там нет самого преимущества.

Этого в первой версии отчёта не было видно вовсе: там всё сводилось к
«преимущество меньше спреда». Оказалось не так.

### 5.5. Что из этого следует для дальнейшей работы

Раз на валютах решает комиссия, а она **фиксирована на лот и не зависит
от размера стопа**, — единственное направление, где издержки перестают
съедать всё, это **более длинный горизонт**. На часовом графике риск
сделки в разы больше, а комиссия та же.

Это не обещание преимущества. Это единственное место, где его ещё имеет
смысл искать.

## 6. ТЕСТЫ

`tests/test_cost_model.py` — **60 проверок**.

| Группа | Что проверено |
|---|---|
| Стоимость пункта | различие для пар с долларом слева и справа; масштаб по лоту |
| Спред | ноль в данных заменяется нижней границей; спред меньше границы поднимается; настоящий берётся как есть; граница задана для всех инструментов прогона |
| Своп | считается по полуночам, а не по суткам; зависит от направления; выход раньше входа не даёт отрицательных ночей |
| Сделка | все столбцы на месте; издержки = спред + комиссия − своп; чистая = грязная − издержки; **чистый результат всегда хуже грязного** |
| **Лот** | **издержки в R не зависят от размера лота** — иначе вывод зависел бы от произвольного числа |
| Бар | в спорной свече засчитывается стоп, а не цель |
| Журнал | метрики из файла совпадают с метриками таблицы; **потоковый счёт совпадает с обычным до копейки**; чтение потоком не грузит файл |
| **Контроль** | **проверка сходимости действительно ловит расхождение** — иначе предыдущий тест был бы зелёным у проверки, которая всегда говорит «сошлось» |
| Порядок | условия печатаются **раньше** результатов (по дереву разбора) |
| Структура | прогон сам сверяет таблицу с журналом; старого параметра `издержки_r` нет ни у одной функции |

### Проверка «наоборот»

Убрал издержки из сделки и вернул «нулевой спред = бесплатно». Падают
**пять** проверок:

```
СБОЙ  Издержки = спред + комиссия − своп
СБОЙ  И чистый результат ХУЖЕ грязного — издержки не бывают в плюс -> 1.0 против 1.0
СБОЙ  Ноль заменяется нижней границей (2 пт) -> 0.0
СБОЙ  И пустое значение тоже
СБОЙ  Спред МЕНЬШЕ границы поднимается до неё
```

## 8. ПРИЗНАННЫЕ ОГРАНИЧЕНИЯ МОДЕЛИ

| Чего нет | Почему |
|---|---|
| Проскальзывание и реквоты | из свечей не восстановить; выдуманное число сделало бы модель хуже |
| Тройной своп по средам | точных значений брокера нет |
| Курс пересчёта для пар с долларом слева берётся по цене входа, а не выхода | ошибка меньше десятой доли процента: издержки и прибыль переводятся по одному курсу |

Первые два делают оценку издержек **заниженной**. Значит, все результаты
— оценка **сверху**: настоящий результат не лучше.
