## Про `LIVE_TRADING` — что сделано и чего НЕ сделано

**В репозитории `LIVE_TRADING` остался `False`.** Включить его за
владельца невозможно технически: программа читает `config.py` на его
компьютере, а обновление этот файл никогда не перезаписывает — он в
списке `PROTECTED` в `updater.py`. Ставить `True` в `config.py.example`
было бы вредно: значение уехало бы во все будущие установки как
умолчание, а владельцу не помогло бы никак.

Поэтому владельцу выданы шаги, которые он выполняет у себя. Удалённое
включение по-прежнему запрещено: в `remote_settings.ALLOWED` для
`LIVE_TRADING` разрешено только выключение.

## Дефект 1. Настройки барьера нельзя было задать из программы

### Как было

Четырёх настроек `DEMO_ACCEPTANCE_*` не было в списке `ADVANCED_PARAMS`
вообще. В `remote_settings.py` при этом стоял комментарий:

```
# и поставлен. Задаётся только руками, в config.py, на своём компьютере.
```

### Чем било

Барьер отказобезопасный: пока номер счёта и сервер не заданы,
`pretrade_gate.проверить` возвращает запрет —

```
если номер <= 0: return False, "режим демо-приёмки включён, но ожидаемый
счёт не задан (DEMO_ACCEPTANCE_LOGIN). Пока не задан — торговать нельзя"
```

Заводские значения — `DEMO_ACCEPTANCE_MODE = True`,
`DEMO_ACCEPTANCE_LOGIN = 0`, `DEMO_ACCEPTANCE_SERVER = ""`. То есть у
владельца барьер был **включён и закрыт**. Он мог сколько угодно ставить
галочку «Реальная торговля» — ни одна заявка не ушла бы, а единственный
способ это исправить (правка `config.py` в блокноте) сам код называет
тем, «чего владелец делать не должен».

### Как стало

Четыре настройки добавлены в `ADVANCED_PARAMS` группой «Демо-приёмка»,
группа положена на вкладку «Защита», к каждой написана справка в
`param_help.py` и раздел в `docs/ПАРАМЕТРЫ.md`. Комментарий в
`remote_settings.py` исправлен — он стал неверным.

Список `FORBIDDEN` не тронут: удалённо эти настройки менять по-прежнему
нельзя ни в какую сторону.

### Как проверено

Три поломки, каждая валит свою проверку:

| Что сломано | Что упало |
|---|---|
| убрана справка `DEMO_ACCEPTANCE_LOGIN` | «Все параметры интерфейса описаны» |
| убран `DEMO_ACCEPTANCE_SERVER` из документации | «Каждый параметр описан в документации» |
| убрана группа «Демо-приёмка» с вкладки | «Каждая группа лежит на своей вкладке» |

## Дефект 2. Программа знала, почему нет сделок, и молчала

### Как было

Ответ был разбросан:

* цикл запущен или нет — надпись на «Обзоре»;
* барьер — строка в логе **при запуске**, дальше видна только через
  «Недавние события», и то если ничего не вытеснило;
* пары — вкладка «Символы»;
* **выключенная «Реальная торговля» — нигде.**

`_silence_reasons` отвечал только на вопрос «почему не входим по парам» и
работал лишь после первого круга цикла, когда снимок уже есть.

### Чем било

Дословно от владельца: «все сделал как надо выше, сделки не вижу!». Он
выполнил инструкцию, результата не увидел и не имел способа узнать
причину, кроме как спрашивать меня.

### Как стало

Добавлен `App._почему_нет_сделок(snap)`. Он даёт причины, которые делают
сделки невозможными **до всякого разбора пар**, и каждая написана вместе
с тем, что нажать:

```python
if not (self.bot_thread and self.bot_thread.is_alive()):
    строки.append("СДЕЛОК НЕ БУДЕТ: торговый цикл не запущен. "
                  "Нажмите «Старт» здесь, на «Обзоре».")

if not bool(getattr(cfg, "LIVE_TRADING", False)):
    строки.append("СДЕЛОК НЕ БУДЕТ: «Реальная торговля» выключена — ...")

if pretrade_gate.включён(cfg) and not pretrade_gate.открыт():
    ...  # и НАЗЫВАЕТ, чего именно не хватает
```

Барьер спрашивается у самого модуля, а не из снимка: снимок делает
торговый цикл, а барьер закрывается **до** первого круга — тогда снимка
ещё нет и причина не показалась бы вовсе.

Строки ставятся **первыми** и не зависят от снимка.

### Как проверено

`tests/test_silence_diagnosis.py`, 10 проверок. Вызывается настоящий
метод настоящего класса при разных состояниях, проверяется текст, который
увидит человек.

**Проверка «наоборот»:** в метод добавлен `return строки` сразу после
`строки = []`.

```
СБОЙ Сказано, что цикл не запущен  -> []
СБОЙ И сказано, что нажать — «Старт»  -> []
СБОЙ Сказано, что заявки не уходят  -> []
СБОЙ И сказано, где включить  -> []
СБОЙ Сказано, что барьер закрыт  -> []
СБОЙ Названо, ЧЕГО не хватает — номера счёта  -> []
СБОЙ И имени сервера  -> []
СБОЙ Сказано, что пар нет  -> []
Пройдено: 2   Сбоев: 8
```

После возврата кода — `Пройдено: 10   Сбоев: 0`.

Отдельно проверяется, что при полностью настроенной программе строк
**ноль**: предупреждение, которое горит всегда, перестают читать.

## Дефект 3. Черновик С-001 нельзя было открыть, не сломав регламент

### Как было

```python
if strategies_mod.черновик(strategy):
    messagebox.showwarning(... "Кнопкой это не делается. Ничего не изменено.")
    return
```

Запрет наглухо. Владелец паспорт принял — значит запрет надо снимать. Но
снять его «просто так» означало убрать регламент вместе с ним.

### Как стало

Запрет **привязан к паспорту**, а не снят:

```python
def паспорт_заверен(strategy_or_key) -> tuple:
    ...
    записанная = str(паспорт.get("хеш_паспорта", "")).strip()
    if not записанная:
        return False, "паспорт не заверен: печати нет"
    если_бы = research_manifest.хеш(паспорт)
    if если_бы != записанная:
        return False, ("печать паспорта НЕ СХОДИТСЯ с его содержимым — "
                       "паспорт меняли после заверения")
    return True, ""
```

Проверяются три вещи, и каждая по отдельности закрывает кнопку: файл на
месте, печать стоит, печать сходится. Третье важнее всего — без сверки
паспорт можно было бы поправить в блокноте и выписать разрешение самому
себе.

`titles()` показывает черновик только с заверенным паспортом.
`черновик()` по-прежнему возвращает `True`: разрешение применить — не то
же самое, что «стратегия готова».

### Отдельно найденный дефект

Папка `preregistration/` **не вкладывалась в сборку**. На машине
владельца проверка печати не нашла бы файл, и С-001 осталась бы закрыта
навсегда — при формально пройденном регламенте. Добавлено
`--add-data "../preregistration;preregistration"` в **обе** сборки.

### Как проверено

`tests/test_c001_passport.py`, 14 проверок. Паспорт портится на диске
по-настоящему, спрашивается настоящая функция:

| Что сделано с паспортом | Решение программы |
|---|---|
| цел | пускает, С-001 в списке |
| файл убран | не пускает, «паспорт не найден» |
| печать удалена | не пускает, «печати нет» |
| **минимум сделок подменён с «20…» на «1»** | **не пускает, «печать НЕ СХОДИТСЯ»** |
| файл превращён в мусор | не пускает, «не читается» |

**Проверка «наоборот»:** сверка печати заменена на `если_бы = записанная`.

```
СБОЙ Подправленный паспорт НЕ пускает (минимум сделок подменён с «20. Порог пр...» на «1»)
СБОЙ И названа причина — печать не сходится
СБОЙ И из списка выбора она пропала
Пройдено: 11   Сбоев: 3
```

## Мои ошибки по дороге

1. **Требовал точные имена символов с суффиксами.** Программа уже умеет
   сама: `resolve_symbol` находит `EURUSD` как `EURUSDs`, `EURUSD.a`,
   `EURUSDm`. Владелец указал на это раньше, чем я проверил код.
2. **Сказал «сегодня воскресенье»** по проверке даты, сделанной больше
   суток назад. Был понедельник, рынок работал.
3. **Не собрал программу сразу** после того, как добавил настройки
   барьера: ждал приёмки паспорта, хотя настройки нужны были независимо.
4. **Забыл `import os`** в переписанной проверке `test_ui_theme.py` —
   весь набор упал с `NameError`. Поймано прогоном, исправлено.

## Что сознательно не сделано

* `LIVE_TRADING` в репозитории не менялся — см. выше.
* Фактические условия счёта (комиссия, свопы) не сняты: нужен Windows с
