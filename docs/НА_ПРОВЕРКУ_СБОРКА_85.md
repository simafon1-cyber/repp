### Чем это било, по шагам

1. В прошлой работе я добавил в самопроверку сборки печать русских слов и
   названий стратегий — чтобы ловить пропажу «Зеркала» до владельца.
2. На сборочной машине Windows вывод перенаправляется в файл с кодировкой
   **cp1252**. Русских букв в ней нет вовсе.
3. Печать бросила `UnicodeEncodeError`.
4. Обработчик ошибки попытался напечатать текст исключения — а в нём тоже
   русские буквы. Упал и он: «During handling of the above exception,
   another exception occurred».
5. Программа собрана **оконной**. Необработанное исключение в такой
   программе Windows показывает окном с ошибкой. Нажать «ОК» на
   сборочной машине некому.
6. Сборка простояла 180 секунд, была убита, попробовала ещё раз, снова
   180 секунд — и провалилась. Шесть минут тишины без внятной причины.

**Обиднее всего, ЧТО именно упало:** проверка, добавленная чтобы ловить
ошибки ДО владельца, сама стала ошибкой, доехавшей до сборки.

### Про номер 85

Сборки 85 **не существует**. Она провалилась на самопроверке, а шаги
«Приложить сборку» и «Опубликовать в Releases» идут ПОСЛЕ проверки и не
выполнились. В Releases подряд идут: 84, затем **86**.

Значит: если в заголовке окна у владельца стоит 85 — этот файл получен
не из Releases. Установить надо **сборку 86**.

## Что исправлено

### 1. Печать внутри самопроверки защищена

Было — голый `print` с русским текстом. Стало — вложенная функция:

```python
    def напечатать(текст: str) -> None:
        try:
            print(текст)
            return
        except Exception:
            pass
        try:
            print(текст.encode("ascii", "backslashreplace").decode("ascii"))
        except Exception:
            # Даже это не прошло — молчим. Самопроверка обязана вернуть
            # код, а не упасть: упавшая проверка не проверяет ничего.
            pass
```

Три ступени: как есть → латиницей с экранированием → молча. Упасть
негде.

### 2. Помощник ВЛОЖЕН в самопроверку, а не вынесен в модуль

Сначала я вынес его отдельной функцией модуля — и получил **второй
дефект**: `test_system.py` исполняет `selftest` в одиночку, вырезая её из
дерева кода. Вынесенная функция там недоступна:

```
NameError: name '_печать_для_сборки' is not defined
```

Это поймал полный прогон, а не я. Правильное решение — вложить: это
последняя проверка перед выдачей сборки человеку, и зависеть от соседей
по модулю ей нельзя. Сломается сосед — проверка не отработает вовсе.

### 3. Падение теперь даёт КОД, а не зависшее окно

```python
        try:
            _код = selftest()
        except BaseException as e:
            try:
                print(f"SELFTEST FAILED: {type(e).__name__}: {e}"
                      .encode("ascii", "backslashreplace").decode("ascii"))
            except Exception:
                pass
            _код = 1
        sys.exit(_код)
```

Раньше любое исключение вешало сборку на шесть минут. Теперь оно
сообщает причину и завершает процесс.

## Как проверено

`tests/test_selftest_encoding.py` — берёт **настоящую** `selftest` из
дерева кода, исполняет её в чистом пространстве имён (как это делает
`test_system`) и подставляет поток вывода, который кириллицу не
принимает — как консоль сборочной машины:

```python
    def write(self, текст):
        текст.encode("cp1252")     # бросит, если есть кириллица
```

| Что проверяется по факту | Итог |
|---|---|
| Подделка потока действительно не принимает русский | пройден |
| Настоящая самопроверка не падает на таком потоке | пройден |
| И отвечает «годно» | пройден |
| Окно при этом действительно создавалось | пройден |
| В вывод попало понятное слово `SELFTEST OK` | пройден |
| Самопроверка выполняется в одиночку, без модуля вокруг | пройден |
| В теле самопроверки нет незащищённой печати | пройден |
| Падение даёт код, а не зависшее окно | пройден |
