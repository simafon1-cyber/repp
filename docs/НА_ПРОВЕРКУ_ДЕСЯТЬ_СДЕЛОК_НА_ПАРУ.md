## Что изменено

### Отдельная помеченная настройка, а не правка профилей

```python
# ВРЕМЕННОЕ ПОСЛАБЛЕНИЕ — ПОМЕЧЕНО ОТДЕЛЬНО, СНИМАЕТСЯ ОДНОЙ СТРОКОЙ
# Владелец 03.09.2026, дословно: «Давай разрешим открытые на одной паре
# до 10 сделок. Пометь это, если что просто дальше уберем».
#   0  = не вмешиваться, действует лимит профиля риска (было так всегда);
#   10 = решение владельца от 03.09.2026.
MAX_POSITIONS_PER_SYMBOL_OVERRIDE = 10
```

**Почему отдельной строкой, а не правкой профиля.** Профили риска —
многострочный блок, который `config_migrate` намеренно не переносит в уже
установленную программу: править такой блок вслепую опасно. Отдельная
строка снимается возвратом нуля, и ни один профиль при этом не страдает.
Это и есть «пометь это, если что просто дальше уберем», сделанное так,
чтобы «убрать» заняло одно движение.

**Профили не тронуты вовсе:** у «Агрессивного» в профиле по-прежнему
`max_open_positions=5`, у «Консервативного» — `1`. На это есть проверка.

### Применение

Помощник `main._лимит_на_пару(profile)` используется в обеих точках, где
лимит проверяется: обычный вход и хедж. Мусор в настройке (строка,
отрицательное число, `None`) **не расширяет** предел — непонятное
значение толкуется в сторону прежнего лимита, а не большего риска.

### Настройка доедет до установленной программы сама

Она новая, поэтому обычный перенос допишет её в `config.py` владельца при
первом запуске. Проверено на живом файле: дописывается, значение 10.

## ГЛАВНОЕ: десяти сделок всё равно НЕ будет, и вот почему

Лимит сделок на пару — не единственное ограничение. Выше него стоит
**потолок совокупного риска**:

| Величина | Значение у «Агрессивного» |
|---|---|
| Риск на одну сделку | 1,2 % счёта |
| Потолок совокупного риска | 6,5 % счёта |
| **Фактически откроется** | **5 сделок** (6,0 % счёта) |
| Шестая потребовала бы | 7,2 % — больше потолка |

**То есть после этой правки число сделок на паре не изменится.**
Останавливает их не лимит сделок, а потолок риска, и владелец его не
поднимал. Сам я его не трогаю: поднять 6,5 % до 12 % — это решение
другого масштаба, и оно не прозвучало.

### Чтобы это не выглядело как «настройка не работает»

Раньше программа говорила просто «Превышен общий риск по открытым
позициям». Человек поднял бы лимит до десяти, увидел пять и решил бы,
что правка не сработала.

Теперь сообщение называет числа:

```
Превышен общий риск по открытым позициям: уже 6.00% + новая 1.20% >
потолок 6.50%. Именно этот потолок, а не лимит сделок на пару,
ограничивает их число
```

## Чего эта работа НЕ проверяет — честно

1. **Не проверено, что десять сделок лучше пяти.** Измерения говорят
   обратное: ожидание входа отрицательно, значит больше сделок —
   больше потерь, а не прибыли.
2. **Не проверено, что программа умеет отличать «прибыльную пару».**
   Измеренный вклад направления входа ±0,008 R и меняет знак между
   периодами — это шум.
3. **Ничего не проверялось у настоящего брокера.** Пакет MetaTrader5
   работает только под Windows, терминала в облаке нет. Зелёные тесты с
   поддельным брокером **не являются** доказательством поведения у
   настоящего.
4. **Не проверено поведение при десяти реально открытых сделках** — при
   нынешнем потолке риска их столько не бывает.

# ДОПОЛНЕНИЕ: владелец выбрал путь «1» — поднять потолок риска

## Задание — дословно

Я предложил два пути и спросил, какой. Ответ владельца: **«1»** — то есть
поднять потолок совокупного риска, а не уменьшать лот.

## МОЯ ОШИБКА, НАЙДЕННАЯ ПРИ ЭТОМ

В первой части отчёта я написал, что сегодня открывается **пять** сделок
на паре. **Это неверно. Открывается три.**

Я не заметил третьего ограничения — потолка по валюте:

```python
MAX_POSITIONS_PER_CURRENCY = 3
```

Он срабатывает **раньше** потолка риска: три сделки по EURUSD дают три
«ставки» и на EUR, и на USD, и четвёртая не проходит. Значит подъём
одного лишь потолка риска не дал бы ничего вовсе.

## Что изменено дополнительно

| Настройка | Было | Стало | Зачем |
|---|---|---|---|
| `MAX_POSITIONS_PER_SYMBOL_OVERRIDE` | (не было) | 10 | сделок на одной паре |
| `MAX_TOTAL_RISK_PERCENT_OVERRIDE` | (не было) | 12.0 | потолок совокупного риска, % счёта |
| `MAX_POSITIONS_PER_CURRENCY` | 3 | 10 | иначе четвёртая сделка не пройдёт |

Почему 12,0: десять сделок по 1,2 % риска = ровно 12,0 %. Одиннадцатая
потребовала бы 13,2 % и не пройдёт.

**Теперь десять сделок действительно откроются**, и под ударом
одновременно будет 12 % счёта.

## ЧТО НАДО ЗНАТЬ ПРО СТРАХОВКИ

Прежними решениями владельца выключены:

```python
USE_DAILY_LOSS_LIMIT = False        # дневной лимит убытка
USE_MAX_DRAWDOWN_LIMIT = False      # лимит просадки
PAUSE_MINUTES_AFTER_LOSS_STREAK = 0 # пауза после серии убытков
```

Значит **потолок совокупного риска — последняя оставшаяся страховка по
совокупному риску**, и здесь она поднимается почти вдвое: с 6,5 % до
12 %.

Простыми словами: на счёте 1000 долларов под ударом одновременно будет
до 120 долларов. Если все десять сделок закроются по стопу, счёт
потеряет около 12 % за один заход.

Что остаётся работать: снижение объёма по серии убытков
(`USE_LOSS_STREAK_RISK_SCALING`), потолок риска на одну сделку
(`MAX_TRADE_RISK_PERCENT_OF_EQUITY = 2.0`) и самоотключение
инструмента, который стабильно тянет вниз (`USE_SYMBOL_AUTO_OFF`).

## Побочное действие подъёма потолка по валюте

Потолок считает валюту по **всем парам сразу**. Подняв его до 10, мы
разрешаем не только десять сделок по одной паре, но и до десяти сделок,
завязанных на одну валюту, — например десять разных пар против доллара.
Это одна и та же ставка десять раз.

Записано в самой настройке, чтобы не выяснилось потом.

## Как снять всё это

Три строки в `config.py`:

```python
MAX_POSITIONS_PER_SYMBOL_OVERRIDE = 0    # вернёт лимит профиля (5)
MAX_TOTAL_RISK_PERCENT_OVERRIDE = 0      # вернёт потолок профиля (6,5 %)
MAX_POSITIONS_PER_CURRENCY = 3           # вернёт прежнюю защиту по валюте
```
