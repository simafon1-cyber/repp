## Дефект, найденный владельцем по снимку экрана (исправлен, `0809456`)

На «Обзоре» одновременно стояло:

```
Торговля разрешена. Помех нет.
• СДЕЛОК НЕ БУДЕТ: предторговый барьер закрыт...
```

Два взаимоисключающих утверждения в одной рамке.

**Причина моя.** Список помех (`_почему_нет_сделок`) я добавил ОТДЕЛЬНО от
состояния (`ui_status.собрать`); они считались двумя кусками кода, не
знающими друг о друге.

**Стало:** помехи считаются первыми, состояние — уже зная о них. «Помех
нет» может появиться, только когда их действительно нет.

**Проверка «наоборот»:** отключить передачу помех — падают 3 проверки, и
зелёное «Помех нет» возвращается рядом с закрытым барьером.

## 1. Барьер: режим «любой демо-счёт»

### Как было

Барьер сверял три вещи: номер счёта, сервер, признак «демо». Номер и
сервер записывались заранее. Каждый новый демо-счёт закрывал барьер
наглухо: «ожидаемый счёт не задан — торговать нельзя».

### Как стало

Новая настройка `DEMO_ACCEPTANCE_ANY_DEMO`, **по умолчанию выключена**:

| Что сверяется | С настройкой |
|---|---|
| Номер счёта | **не сверяется** |
| Сервер | **не сверяется** |
| Счёт демонстрационный | **сверяется жёстко** |

Настройка отдельная и явная, а не «пусто = можно всё»: послабление не
должно включаться по недосмотру.

### Ловушка, закрытая заранее

Два послабления вместе — «любой демо» и снятое
`DEMO_ACCEPTANCE_REQUIRE_DEMO` — открыли бы дорогу к реальному счёту.
Барьер такое сочетание **отказывает** и называет причину.

### Проверка «наоборот»

| Что сломано | Что упало |
|---|---|
| «любой демо» пускает и реальный счёт | 2 проверки |
| сочетание двух послаблений разрешено | 2 проверки |

## Тест-матрица

| Сценарий | Что проверяется по факту | Итог |
|---|---|---|
| Новый демо-счёт, номер не записан | пропущен, номер назван в причине | ОК |
| Другой сервер | пропущен — сервер не сверяется | ОК |
| **Реальный счёт** | **НЕ пропущен**, сказано почему | ОК |
| «любой демо» + снято требование демо | запрещено даже на демо-счёте | ОК |
| Терминал молчит / режим счёта неизвестен | запрет | ОК |
| Прежний режим (по номеру) | все старые проверки целы | ОК |
| Помеха есть | «Помех нет» не говорится, помеха первой как СТОП | ОК |
| Помех нет | прежний ответ сохранён | ОК |
| Кнопки окна | 43 проверки, все нажимаются | ОК |
| Раскладка окна | 161 проверка | ОК |
| Весь набор | **5174 проверки, 0 сбоев** | ОК |

## Чего эти изменения НЕ делают

1. **Не разрешают реальный счёт.** Требование «счёт демонстрационный»
   осталось жёстким, и сочетание послаблений запрещено.
2. **Не меняют риск.** Убран только выбор из окна.
3. **Не улучшают прибыльность.** Ни одно изменение здесь не про это.
4. **Не доказывают поведение у настоящего брокера.** Зелёные тесты с
   заглушкой MT5 доказательством не являются — действует всегда.

## Что владельцу нужно сделать самому

Настройка `DEMO_ACCEPTANCE_ANY_DEMO` **выключена**. Включить —
«Настройка» → «Защита» → «Демо-приёмка». Молча включать послабление я не
стал.

## Отдельно, для проверяющего: о чём владелец попросил и что НЕ сделано

Владелец просит разрешить работу **на реальном счёте** и говорит, что
программа «должна просто работать в прибыль». Запрет на реальные счета —
его собственное правило в `CLAUDE.md`, и снят он **не был**: такие вещи
меняются только отдельным согласованием, и владельцу переданы измеренные
числа (ожидание −0,0244 R на сделку до издержек; 0 плюсовых из 54
проверенных сочетаний; вход неотличим от случайного). Решение за ним, но
принято оно должно быть с этими числами перед глазами.
