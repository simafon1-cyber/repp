## 2. P0-1: ТРЕБОВАНИЕ ЖИЛО В ДОКУМЕНТЕ, А НЕ В КОДЕ

### Как было

Единственный барьер перед отправкой заявки — `main.py`, строка 1952:

```python
    if not cfg.LIVE_TRADING:
        log.warning("LIVE_TRADING=False — это СУХОЙ ПРОГОН, реальные ордера отправляться НЕ будут.")
```

И всё. `mt5_connector.send_market_order()` начинался прямо с работы:

```python
def send_market_order(symbol, direction, lot, sl_price, tp_price,
                      magic, comment="", deviation=20):
    tick = mt5.symbol_info_tick(symbol)
```

### Чем это било, по шагам

1. Владелец ставит `LIVE_TRADING = True` для этапа Б.
2. Программа подключается. Если `MT5_LOGIN` не заполнен, срабатывает
   `auto_login_account()` — вход в **первый готовый счёт** из хранилища
   терминала.
3. Первым может оказаться не тот счёт. В том числе реальный.
4. Заявки уходят туда. Ни одна строка кода этому не мешает.
5. Протокол требовал MetaQuotes-Demo 5054028014 — но требование было
   **текстом в документе**. Ручная инструкция «проверьте счёт» защищает
   ровно до первой невнимательности.

Аудит нашёл, что номер `5054028014` встречается в коде только в
исследовательском модуле издержек — то есть в предторговом барьере его не
было вообще.

### Как стало

Новый файл `ai_scalper_standalone/pretrade_gate.py`. Начальное состояние:

```python
# Состояние процесса. None — разрешения нет. Это НАЧАЛЬНОЕ значение, и
# именно поэтому барьер fail-closed: чтобы торговать, надо что-то сделать;
# чтобы не торговать, достаточно ничего не делать.
_разрешение = None
```

Разрешение выдаётся, только если совпало **сразу всё**:

```python
    if счёт is None:
        return False, (
            "терминал не ответил на вопрос о счёте. Мы НЕ ЗНАЕМ, к какому "
            "счёту подключены. Торговать вслепую нельзя.")
    ...
    if факт_номер != номер:
        return False, (
            f"счёт НЕ ТОТ: подключены к {факт_номер}, а разрешён только "
            f"{номер}. Заявки могли бы уйти на чужой счёт.")
    ...
    if str(факт_сервер).strip() != сервер:
        return False, (
            f"сервер НЕ ТОТ: ... Номер счёта может совпасть у разных "
            f"брокеров — само по себе совпадение номера ничего не значит.")
    ...
        if факт_режим != СЧЁТ_ДЕМО:
            return False, (
                f"режим счёта — {имя}, а разрешён только демонстрационный. "
                f"Демо-приёмка на реальных деньгах не проводится.")
```

И барьер стоит **внутри самих отправляющих функций**, а не рядом с ними —
как и потребовал аудит:

```python
def send_market_order(symbol, direction, lot, sl_price, tp_price,
                      magic, comment="", deviation=20):
    # ПРЕДТОРГОВЫЙ БАРЬЕР. Стоит ПЕРВОЙ строкой, до чтения цены и до сборки
    # заявки: проверка, которую можно обойти, добравшись до кода ниже, —
    # не проверка.
    pretrade_gate.требовать("открытие позиции")
    tick = mt5.symbol_info_tick(symbol)
```

Всего таких мест четыре, и закрыты все четыре: `send_market_order`,
`modify_position`, `close_position_partial` в `mt5_connector.py` и
`close_ticket` в `account_supervisor.py`.

Четыре новые настройки внесены в список **запрещённых к удалённой
правке** (`remote_settings.py`): тот, кто может выключить барьер по сети,
может увести заявки на чужой счёт.

### Как проверено

`tests/test_pretrade_gate.py`, 43 проверки. Главное доказательство —
**счётчик обращений** к `order_send` у поддельного терминала: он обязан
остаться нулевым. Проверяется факт, что заявка никуда не пошла, а не
возвращённое значение.

### Моя собственная ошибка внутри этой правки

Первая версия `требовать()` запрещала торговлю **всегда**, если барьер не
открывали, — не глядя на то, включён ли режим приёмки. Это сломало бы
обычную работу программы у любого, кто демо-приёмку не проводит: раздел 4
правил проекта прямо запрещает трогать торговую логику без согласования, а
я бы её сломал.

Исправлено: при выключенном режиме вызов проходит ровно как раньше. Но
если **настройки прочитать не удалось** — запрет, потому что тогда
неизвестно даже, идёт ли приёмка. На оба случая написаны отдельные
проверки (`test_с_выключенным_режимом_торговля_идёт_как_раньше`,
`test_нечитаемые_настройки_это_запрет`).

## 3. P0-2: УСЛОВИЯ О1 И О2 БЫЛО НЕЧЕМ ДОКАЗАТЬ

Два разных дефекта, оба в одном месте.

### 3а. Чужие позиции не попадали в снимок вообще

**Как было:**

```python
    записать("позиции", "positions_get",
             lambda: mt5c.positions_or_none(magic=magic))
```

**Чем било:** условие О2 звучит «ни одной позиции с чужим `magic`». Но
запрос шёл **сразу с фильтром**. Чужих позиций в файле не было
**по устройству**, а не по факту. На счёте с чужой позицией условие
отчиталось бы выполненным.

**Как стало:** спрашивается всё без фильтра, деление делается по
записанному, обе части лежат в файле рядом:

```python
    # ПОЗИЦИИ И ЗАЯВКИ — БЕЗ ФИЛЬТРА. Фильтр по magic выбрасывал бы чужие
    # записи ещё до записи в файл, и условие «нет чужих позиций» стало бы
    # непроверяемым. Спрашиваем всё, делим потом.
    все_позиции, поз_есть = записать(
        "позиции_все", "positions_get(без фильтра)",
        lambda: mt5c.positions_or_none())
```

### 3б. Связь «позиция ↔ сделка» проверялась совпадением по времени

**Как было:**

```python
    появились = итог.get("позиции_появились")
    сделки = итог.get("сделки_появились")
    if isinstance(появились, list) and isinstance(сделки, list):
        if появились and not сделки:
            итог["предупреждения"].append(...)
```

**Чем било, по шагам:**

1. Условие О1 — «ни одной позиции без соответствующей сделки».
2. Проверялось так: появились ли позиции и появилась ли **хоть одна**
   сделка за то же окно.
3. Одна посторонняя сделка в том же окне — и предупреждение молчит.
   Позиция, у которой своей истории нет вовсе, проходит незамеченной.
4. Сделка, открывшая позицию **раньше окна**, вообще не попадала в
   запрос.

**Как стало:** для каждой своей позиции спрашивается её собственная
история **по номеру**:

```python
    ответ, получилось = _спросить(f"deals_by_position({ключ})",
                                  lambda: mt5c.deals_by_position(ключ))
    if not получилось:
        итог["состояние"] = НЕ_ДОКАЗАНО
        итог["почему"] = "спросить историю этой позиции не удалось"
    if not ответ:
        итог["состояние"] = НЕ_ДОКАЗАНО
        итог["почему"] = ("терминал ответил пустотой: своей истории у этой "
                          "позиции не видно. Это НЕ доказывает, что её нет — "
                          "история может отставать.")
```

Окно истории здесь ни при чём: спрашиваем по номеру, поэтому сделка,
открывшая позицию до начала окна, тоже находится.

**У О1 и О2 теперь три исхода, а не два:** ВЫПОЛНЕНО, НЕ ВЫПОЛНЕНО,
**НЕ ДОКАЗАНО**. Последний выполнением не считается.

### Правка заранее записанных условий — и почему это не подгонка

Условия О1 и О2 в `docs/ДЕМО_ПРИЁМКА.md` переписаны. Это надо назвать
прямо, а не спрятать.

* Они **ужесточены**, а не ослаблены.
* Правка сделана **до того, как появился хоть один результат** —
  подгонять было не подо что.
* Прежние формулировки оставлены в документе **зачёркнутыми**, чтобы
  правку было видно.
* Причина правки — не мой выбор, а требование аудита.

Добавлено новое обязательное условие **О0**: все заявки ушли на тот самый
демо-счёт.

## 4. P1-1: ОТСУТСТВИЕ СВЕДЕНИЙ ВЫГЛЯДЕЛО КАК ЧИСЛА

### Как было

```python
            ("спред_пунктов", "symbol_info",
             lambda с=символ: mt5c.get_spread_points(с)),
            ("пункт", "symbol_info", lambda с=символ: mt5c.get_symbol_point(с)),
```

`get_spread_points()` при молчании терминала возвращает `999999`,
`get_symbol_point()` — `0.0001`, `trading_permission_status()` —
`{"ok": true, "problems": []}`.

### Чем било

В торговой логике это **правильная защита**: огромный спред — и программа
просто не входит в сделку. Но в доказательном снимке это ложь: в файле
оказывается число, и по нему потом судят, каким был спред. А раздел
«разрешено ли торговать» отвечал «да», ничего не спросив.

### Как стало

Сборщик спрашивает терминал напрямую, без защитных значений:

```python
def _строгий_терминал():
    """Прямой доступ к терминалу — БЕЗ защитных значений по умолчанию.
    ...
    Ни одно значение по умолчанию в торговой логике при этом не меняется —
    там всё остаётся как было."""
```

**Ни одно значение по умолчанию в торговой логике не тронуто** — это
требование аудита выполнено буквально.

## 5. P1-2: ОТПЕЧАТОК НАЗЫВАЛСЯ ЗАЩИТОЙ, КОТОРОЙ НЕ БЫЛ

### Как было

```python
def хеш(данные: dict) -> str:
    """Отпечаток снимка. По нему видно, правили ли файл после записи."""
```

А в тестах — раздел «СНИМОК НЕЛЬЗЯ ПОПРАВИТЬ ЗАДНИМ ЧИСЛОМ».

### Чем било

Утверждение технически слишком сильное. SHA-256 считается из тех же
данных и лежит в том же файле: кто правит снимок, тот пересчитает и
отпечаток.

### Как стало

Сделано **и то, и другое**, что предложил аудит.

**Формулировка сужена до правды.** В файле снимка теперь прямо написано,
от чего он защищён:

```json
"защита": "sha256",
"защита_от": "случайной или несогласованной правки; от умышленной подмены НЕ защищает"
```

**И добавлена настоящая подпись.** Если задать переменную окружения
`DEMO_ACCEPTANCE_KEY`, считается HMAC — ключ в файл не попадает. Чтение
подписанного снимка **без ключа отказывается**, а не делает вид, что всё
сошлось.

Отдельная проверка (`test_подделка_с_пересчётом_отпечатка_проходит_без_ключа`)
закрепляет ограничение фактом: подделка с пересчётом обычного отпечатка
действительно проходит. Проверка стоит там затем, чтобы никто позже не
вписал обратно «подделать нельзя».

Возвращаю каждый дефект и показываю, что тест падает. Восстановление

### Отдельно: дефект, найденный в моём же тесте

Первый прогон «наоборот» с возвращённым фильтром `magic` дал **68 из 68,
сбоев 0**. То есть тест, написанный ловить этот дефект, его **не ловил**.

спросили, — фильтр он просто игнорировал. Настоящий
`positions_or_none()` фильтрует.

Подделка исправлена, после чего проверка «наоборот» стала падать как
положено (строка 3 таблицы). Пишу это отдельно: тест, который не падает
на сломанном коде, хуже отсутствующего — он создаёт ложную уверенность.

Было **4312**, стало **4423**. Разница **111**: 43 новые проверки барьера
и 68 проверок снимков (из них 39 существовали раньше — они переписаны под
новое устройство, а не добавлены).

### Одна старая проверка потребовала правки, и это надо назвать

`tests/test_partial_fill.py` перестал работать: он загружает образец
настроек, где режим приёмки включён, и ставит `LIVE_TRADING = True` —
барьер (справедливо) не выпускал ни одной заявки, и тесты про частичное
исполнение перестали проверять то, ради чего написаны.

Добавлена одна строка `cfg.DEMO_ACCEPTANCE_MODE = False` с объяснением
прямо в файле. Барьер проверяется отдельно и там, где ему место.

**Как я убедился, что барьер не глушит молча другие тесты.** Одного
«набор зелёный» тут мало: тест мог поймать исключение и пройти, ничего не
проверив. Поэтому я временно заставил барьер записывать КАЖДУЮ
блокировку со стеком вызовов в отдельный файл и прогнал весь набор.

```
=== блокировок за прогон: 5
     15 tests/test_pretrade_gate.py
```

Все блокировки — только в тесте самого барьера, там, где они и должны
быть. Ни один другой тест барьер не глушит. Временная запись убрана,
итоговый прогон сделан на чистом коде.

## 8. ЧЕГО ЭТИ ТЕСТЫ НЕ ПРОВЕРЯЮТ

1. **Поведение у настоящего брокера.** Подделка отвечает так, как её
   научили. Это ограничение снимается только самим демо-прогоном.
2. **Подмену счёта в середине работы.** Разрешение выдаётся при запуске
   по тому счёту, который тогда ответил. Если счёт переключить в
   терминале уже во время работы, барьер этого не заметит. Записано в
   `pretrade_gate.py` отдельным абзацем, **не исправлено**.
3. **Условия О3–О7** (неясный ответ, обрывы в журнале, порядок сверки
   после перезапуска, объёмы, полнота итогового снимка) проверяются
   самим прогоном, а не этими тестами.
4. **Настоящий `config.py` владельца.** Он спрятан от git — я его не
   вижу. Заполнены ли `DEMO_ACCEPTANCE_LOGIN` и `DEMO_ACCEPTANCE_SERVER`,
   проверить отсюда нельзя. Если не заполнены — барьер запретит торговлю,
   и это правильное поведение, но узнается оно только при запуске.
5. **Стойкость HMAC к внешнему наблюдателю.** Ключ живёт в переменной
   окружения на той же машине. Аудит отдельно отметил, что для сильного
   внешнего доказательства нужен неизменяемый носитель — подписанный
   коммит или архив, созданный до анализа результата. **Не сделано.**

## 11. ЧТО ЭТА РАБОТА НЕ МЕНЯЕТ

* **Стратегию — никак.** Входы, выходы, индикаторы, лот, риск, стопы,
  тейк-профиты, профили не тронуты.
* **Прибыльность — никак.** Отрицательное ожидание остаётся нерешённым.
  Демо-прогон проверяет исполнение, а не результат.
* **Работу тех, кто приёмку не проводит.** При выключенном
  `DEMO_ACCEPTANCE_MODE` поведение ровно то же, что до правки; на это
  есть отдельная проверка.
* **`LIVE_TRADING`** остаётся `False`.
