## 2. P1-H4: Я ПОЧИНИЛ КОД И НЕ ПОЧИНИЛ ДАННЫЕ

### В чём была ошибка

Смещение времени сервера я исправил в `history_export.py`, и тесты это
доказали. Но данные выгружены **до** правки, и в опубликованном снимке
остались старые числа: `−1.0` у валютных пар и `−2.0` у золота.

Аудит сформулировал точно: тесты доказывают исправленную логику для
будущих выгрузок, но не исправляют уже опубликованный артефакт. А
`baseline_engine.session_of()` читает именно это поле — значит
предстоящий прогон получил бы неверные ярлыки сессий.

Это ровно тот же класс ошибки, что и раньше: **правило записано, а
предмет правила не приведён в порядок.**

### Как исправлено

Новый файл `ai_scalper_standalone/migrate_meta.py`. Заново выгружать
нельзя — окно терминала уехало бы вперёд и начало истории потерялось бы.
Значит правится только паспорт.

**Главное правило этого файла: свечи не трогаются.** И это не обещание,
а проверка:

```python
    # ОТПЕЧАТКИ СВЕЧЕЙ ДО. С ними сверяемся после — это и есть
    # доказательство, что данные не тронуты.
    до = {f: отпечаток(os.path.join(папка, f)) for f in файлы}
    ...
    if разошлись:
        raise RuntimeError(
            f"ПЕРЕНОС ИСПОРТИЛ СВЕЧИ: {разошлись}. Это никогда не должно "
            f"происходить — перенос правит только паспорта.")
```

### Результат на настоящем архиве

```
  EURUSD_H1.csv          -1.0 -> 3.0  (изменено)
  XAUUSD_H1.csv          -2.0 -> 3.0  (изменено)
  ...
Паспортов изменено: 32 из 32
Свечи не менялись: ДА, отпечатки всех CSV совпали
```

Рядом со снимком лёг журнал `migration.json`: что было, что стало,
отпечаток каждого CSV и отдельной строкой — что свечи не менялись. Журнал
сам попадает в манифест, иначе его можно было бы подменить незаметно.

**Новый отпечаток архива:**
`53dad468c79b06b7ea368efbebab469ef01fd9c62367fe3d72cf42995563cac1`.

### Одно отступление от буквы замечания — называю прямо

Аудит ожидал изменения **восьми** H1-паспортов. Изменено **тридцать
два** — все паспорта снимка.

Причина: смещение — свойство **сервера**, а не таймфрейма. Считать его
можно только по часовым свечам (на M1/M5/M15 граница недели размыта
пропусками), но сервер тот же, и снимок снят за четыре минуты. В
паспортах M1/M5/M15 сейчас лежит **то же самое заведомо неверное `−1`**,
и оставить его там значило бы починить половину.

Перенос проверяет, что снимок собран за один заход (разбег между первой и
последней выгрузкой меньше суток), и только тогда переносит значение. В
пояснении каждого такого паспорта записано, откуда число взято.

## 3. P1-H5: МОИ ЧИСЛА НЕ ВОСПРОИЗВОДИЛИСЬ

### В чём была ошибка

В отчёте я написал **149 389 (74,7 %)**. Аудит пересчитал и получил
**149 640** при покомпонентной границе и **149 422** при общей. Моё число
не совпало **ни с одним**.

Причина стыдная и простая: я считал по **округлённым датам**
(`«2025-08-15»`), а не по точным отметкам времени самых ранних
сохранённых свечей. Расхождение невелико числом, но велико по сути: до
предрегистрации граница обязана вычисляться программой.

### Проверено у себя до починки

Первым делом воспроизвёл оба числа аудита:

```
ПОКОМПОНЕНТНО: 149640 из 200000 = 74.8200%
ОБЩАЯ ГРАНИЦА: 149422 из 200000 = 74.7110%
В моём отчёте было: 149389 (74.6945%)
```

Сошлось до знака. Ошибка моя, подтверждена.

### Как исправлено

Новый файл `ai_scalper_standalone/unseen_split.py`: одна явно выбранная
договорённость, одна программа, воспроизводимый результат.

**Выбрана покомпонентная строгая** — как и советует аудит: для каждого
инструмента граница есть время самой ранней уже сохранённой свечи
**этого же** инструмента на любом прежнем таймфрейме.

Вторая договорённость считается рядом и печатается — **чтобы выбор был
виден, а не подразумевался**.

### Результат

```
инструмент граница UTC           невидено   train   valid     oos
AUDUSD     2025-08-20T01:30:00      18749    9374    4687    4688
EURUSD     2025-08-15T04:00:00      18678    9339    4669    4670
GBPUSD     2025-08-15T03:00:00      18679    9339    4669    4671
NZDUSD     2025-08-15T04:15:00      18680    9340    4670    4670
USDCAD     2025-08-15T04:15:00      18680    9340    4670    4670
USDCHF     2025-08-20T01:30:00      18749    9374    4687    4688

XAUUSD     2025-07-22T12:30:00      18676    9338    4669    4669

ИТОГО невидено: 149640 из 200000 = 74.8200%
Для сравнения, общая граница: 149422 = 74.7110%  (НЕ используется)
```

Полный итог с отпечатком каждого среза записан в
`preregistration/границы_h1.json`. Паспорт гипотезы будет ссылаться
именно на него.

**Разбиение 50 / 25 / 25 по времени, без перемешивания.** `train` —
самое раннее, `oos` — самое позднее. У каждого среза свой отпечаток,
считаемый по самим строкам: одинаковое число баров бывает у разных
кусков.

## 4. ПРОВЕРКА «НАОБОРОТ» — С ЧИСЛАМИ

Исходное: **35 из 35, сбоев 0**.

| Что сломал | Стало | Что упало |
|---|---|---|
| Перенос дописывает в CSV | 19 из 35, сбоев 4 | «доработала до конца → порча в данных» |
| Смещение не переносится на младшие ТФ | 33 из 35, сбоев 2 | «На M5 записано то же +3 → None» |
| Граница округляется до суток | 33 из 35, сбоев 2 | «Невиданные посчитаны по точной отметке → 3600 вместо 3601» |
| Разрезание перемешивает | 33 из 35, сбоев 2 | «train целиком РАНЬШЕ validation» |

Третья строка — ровно моя исходная ошибка, воспроизведённая нарочно.

### Дефект в моём же тесте, найденный проверкой «наоборот»

Проверка «обе договорённости печатаются рядом» сначала проходила при
**совпадающих** числах: `400 и 400`. Я построил данные всего из двух
инструментов, а при двух «общая граница валютных пар» совпадает с
границей единственной валютной пары — различать нечего.

Добавил третий инструмент, после чего проверка стала осмысленной. Пишу
это отдельно: тест, который не может отличить правильное от
неправильного, — не тест.

## 6. ЧЕГО ЭТО НЕ ДАЁТ

1. **Преимущества.** Три года невиданных данных дают возможность
   гипотезу проверить, а не гарантию, что она подтвердится.
2. **Проверки у настоящего брокера.**
3. **Пересчёта прошлых отчётов** с верным смещением — не делался; ярлыки
   сессий в них остаются смещёнными.
4. **Исправления `session_of`** — он применяет одно смещение ко всей
   истории, а оно меняется дважды в год. На половине данных ярлык сессии
   смещён на час. Ярлык ни на что не влияет; переделка потребовала бы
   трогать движок прогона. **Не сделано.**
5. **Склейки снимков постоянной командой** — по-прежнему **не сделано**.
