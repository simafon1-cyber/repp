## 1. ЗАМЕЧАНИЕ, КОТОРОЕ ОСТАВАЛОСЬ ОТКРЫТЫМ

Повторный аудит принял P0-1, P0-2 и P1-1. Осталось одно:

> Поле `защита` находится в самом подписываемом файле и **не связано с
> HMAC**. В функции чтения оно определяет алгоритм проверки: если его
> заменить с `hmac-sha256` на `sha256`, код принудительно отбрасывает
> имеющийся ключ и принимает новый обычный SHA-256.

Аудитор воспроизвёл это независимо и получил `DOWNGRADE_ACCEPTED`.

Замечание справедливо целиком. Я сделал подпись, накрывающую данные, и
объявил дело закрытым — не заметив, что **запись о том, чем данные
защищены, сама не защищена ничем**.

## 2. ДЕФЕКТ ВОСПРОИЗВЕДЁН ДО ПОЧИНКИ

Сначала повторил у себя, чтобы чинить факт, а не пересказ.

```
$ python3 (сценарий подделывателя БЕЗ ключа)
тип защиты при записи: hmac-sha256
РЕЗУЛЬТАТ: ПОДДЕЛКА ПРИНЯТА, объём стал 9.99
```

### Как было

```python
def хеш(данные: dict, ключ: str = "") -> str:
    текст = json.dumps(данные, ensure_ascii=False, sort_keys=True,
                       separators=(",", ":")).encode("utf-8")
    if ключ:
        return hmac.new(ключ.encode("utf-8"), текст, hashlib.sha256).hexdigest()
    return hashlib.sha256(текст).hexdigest()
```

И в чтении:

```python
    защита = завёрнутый.get("защита", ОБЫЧНЫЙ)
    ...
    if защита != ПОДПИСЬ:
        ключ = ""      # файл без подписи проверяем обычным отпечатком
    стало = хеш(данные, ключ)
```

### Чем это било, по шагам

1. Снимок записан с ключом: `"защита": "hmac-sha256"`.
2. Подделыватель, у которого ключа **нет**, открывает файл.
3. Правит объём позиции: `0.01` → `9.99`.
4. Переставляет `"защита"` на `"sha256"`.
5. Считает обычный SHA-256 — ключ для этого не нужен.
6. Чтение видит `защита == "sha256"`, **само отбрасывает ключ** строкой
   `ключ = ""` и сверяет обычным хешем. Сходится.
7. Файл принят. Подделка выдана за доказательство.

Подпись защищала данные и не защищала запись о том, чем они защищены.

## 3. КАК СТАЛО

Закрыто с двух сторон. Каждая половина закрывает дыру сама по себе;
вместе — с запасом.

### 3а. Метаданные вошли в подпись

```python
# Версия формата подписи. Входит В ПОДПИСЬ — иначе завтрашнее изменение
# правил подсчёта можно будет выдать за вчерашний файл.
ВЕРСИЯ_ФОРМАТА = 2


def _подписываемое(данные: dict, защита: str) -> bytes:
    """Что именно уходит под подпись.
    ...
    Теперь тип защиты и версия формата входят в подписываемые байты.
    Переставить их, не зная ключа, нельзя."""
    тело = json.dumps(данные, ensure_ascii=False, sort_keys=True,
                      separators=(",", ":"))
    return f"{ВЕРСИЯ_ФОРМАТА}\n{защита}\n{тело}".encode("utf-8")
```

### 3б. Понижение защиты запрещено — и отказ идёт ДО подсчёта хеша

```python
    # ЗАПРЕТ ПОНИЖЕНИЯ ЗАЩИТЫ.
    #
    # Ключ задан — значит идёт доказательная приёмка, и в ней принимаются
    # ТОЛЬКО подписанные снимки. Отказ происходит ДО подсчёта хеша: иначе
    # мы посчитали бы обычный SHA-256 по подделанному файлу и признали его
    # сошедшимся. Ровно так дыра и работала.
    if ключ and защита != ПОДПИСЬ:
        raise ValueError(
            f"Снимок {путь} НЕ подписан (защита: «{защита}»), а ключ задан.\n"
            "Идёт доказательная приёмка — в ней принимаются только "
            "подписанные снимки.\n"
            "Так выглядела бы подмена: правим данные, переставляем тип "
            "защиты на обычный отпечаток и пересчитываем его без ключа.\n"
            f"Чтобы прочитать неподписанный снимок намеренно, уберите "
            f"переменную окружения {ПЕРЕМЕННАЯ_КЛЮЧА}.")
```

Требование аудита «обычный `sha256` в этой конфигурации обязан вызывать
`ValueError` **до вычисления хеша**» выполнено буквально: `raise` стоит
выше строки `стало = хеш(...)`.

### 3в. Версия формата тоже сверяется

Если правила подсчёта изменятся, старый файл сверять нечем. Молча
посчитать по новым правилам и сказать «не сходится» — сбить с толку;
сказать «сходится» — соврать. Поэтому отдельный отказ с объяснением.

### Проверено на том же сценарии

```
1. Понижение защиты + пересчёт обычного хеша: отвергнуто — Снимок ... НЕ подписан (защита: «sha256»), а ключ задан.
2. Простая правка данных без пересчёта:      отвергнуто — Снимок ... изменён после записи.
3. Нетронутый подписанный файл:              ПРИНЯТО (объём 0.01)
```

Третья строка важна не меньше первых двух: защита, которая отвергает и
честные файлы, — не защита, а поломка.

## 6. ЧТО ЭТО ЛОМАЕТ В ПОРЯДКЕ РАБОТЫ — И ЗАПИСАНО В ПРОТОКОЛ

Запрет понижения имеет прямое следствие для прогона, и о нём надо
предупредить заранее, а не после.

**Снимки этапа Б надо снимать с ключом с самого начала.** Если снять «до»
без ключа, а «после» с ключом, сверить их не выйдет: чтение
неподписанного снимка при заданном ключе теперь отказывает. Это записано
в `docs/ДЕМО_ПРИЁМКА.md` отдельным абзацем.

---

## 7. ЧЕГО ЭТО НЕ ДАЁТ

1. **Поведение у настоящего брокера.** Не проверено и здесь не
   проверяется.
2. **Стойкость ключа.** Он живёт в переменной окружения на той же
   машине. Кто имеет доступ к машине во время прогона, имеет и ключ.
   Аудит отдельно отмечал, что для сильного внешнего доказательства
   нужен неизменяемый носитель — подписанный коммит или архив, созданный
   до анализа результата. **Не сделано**, требует решения владельца о
   том, куда его класть.
3. **Подмену счёта в середине работы** барьер по-прежнему не ловит:
   разрешение выдаётся при запуске. Записано в `pretrade_gate.py` и в
   прошлом отчёте, аудит принял это как остаточное ограничение.
