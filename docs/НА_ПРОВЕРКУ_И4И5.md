## ЧАСТЬ 1. P1-ПРАВКА: НОМЕРА ЗАЯВОК СПИСКОМ ЧИСЕЛ (`8c528a0`)

### Что было

`main.py` записывал в инцидент склеенную строку:

```python
"не_закрылись": "; ".join(не_закрылись)
```

где каждый элемент — номер **вместе** с пояснением. Дальше сверка
вытаскивала оттуда «все цифры подряд». Из строки

```
12345 (неизвестно: ответ 10012 объём 0.01)
```

получалось **1234510012001** — число, которого не существует.

### Чем это било

Fail-open здесь не возникало: несуществующая заявка не находится, вердикт
выходит «не выяснено», то есть в безопасную сторону.

Било по другому: человек лишался **доказательного** ответа по реальной
незакрытой ноге и был вынужден снимать инцидент **принудительно** — ровно
то, ради отказа от чего писался И3.

### Что стало

| Поле | Что в нём |
|---|---|
| `заявка_без_ответа` | число |
| `тикеты_исполненных_ног` | список чисел |
| `тикеты_незакрытых_ног` | список чисел |
| `детали_незакрытых_ног` | список пояснений — **на числа не разбирается** |

Старые отметки по-прежнему читаются: из строки берётся **первое** число
куска (номер стоит первым). Но такой разбор помечается **ненадёжным** и
**никогда не даёт доказательного снятия** — неизвестно даже, те ли это
номера. Испорченный список (не список, нечисловой элемент) тоже
помечается ненадёжным.

Факты при этом собираются и показываются: они полезны человеку, даже
когда доказательства нет.

### Тесты

| Сценарий | Итог |
|---|---|
| **Строка из задания аудита** (`12345`, код `10012`, объём `0.01`) → запрашивается ровно `12345` | ✅ |
| Из старой записи доказательного снятия не бывает — даже когда вердикт сошёлся | ✅ |
| **Контроль:** списком чисел доказательство работает | ✅ |
| Пояснения на числа не разбираются | ✅ |
| Испорченный список помечается ненадёжным | ✅ |
| Торговый код пишет номера числами (разбор дерева, не текста) | ✅ |

**Проверка «наоборот».** Со старым разбором падают **пять** проверок, и
получается ровно предсказанное аудитом число:

```
СБОЙ  Взят именно номер заявки -> [1234510012001]
СБОЙ  А не склеенное число -> [1234510012001]
СБОЙ  И такой разбор помечен НЕнадёжным
```

## ЧАСТЬ 2. И4–И5: ПОЛИТИКА ОТВЕТОВ СЕРВЕРА (`efe6797`)

### Что было

Программа знала **четыре** кода из сорока с лишним: `DONE` и три
«повторите». Всё остальное сваливалось в один мешок «отказ».

Это плохо двумя разными способами.

**Первый, человеческий.** В журнале писалось «ошибка 10019», и владельцу
приходилось искать, что это. А это «на счёте не хватает свободных
средств» — понятно за секунду.

**Второй, опасный.** Незнакомый код считался **отказом**. Отказ разрешает
идти дальше и открывать следующую сделку. Но незнакомый код на то и
незнакомый, что неизвестно, исполнилась заявка или нет. Считать его
отказом — тот же порок, что разбирался в И1-C, только источник другой.

### Что стало

Новый модуль `retcodes.py`: таблица на **40 ответов**, у каждого класс и
объяснение по-русски.

| Класс | Что означает | Что делает программа |
|---|---|---|
| `ИСПОЛНЕНО` | заявка сработала целиком | учитывает сделку |
| `ЧАСТИЧНО` | сработала частью, остаток отменён | учитывает фактический объём |
| `ПОВТОРИТЬ` | отказ временный | пробует ещё раз |
| `ОКОНЧАТЕЛЬНО` | отказ настоящий | идёт дальше, не повторяя |
| `НЕОПРЕДЕЛЁННО` | неизвестно, что произошло | **сверяется с терминалом** |

Два разделения делают разную работу, и их важно не путать:

* **`ПОВТОРИТЬ` против `ОКОНЧАТЕЛЬНО`** — про поведение. Реквот стоит
  повторить, «рынок закрыт» повторять незачем.
* **`ОКОНЧАТЕЛЬНО` против `НЕОПРЕДЕЛЁННО`** — про безопасность. Первое
  разрешает идти дальше, второе не разрешает **ничего**, пока не
  сверились.

### Главное изменение: незнакомый код

**Незнакомый и нечитаемый код попадают в `НЕОПРЕДЕЛЁННО`, а не в
«отказ».**

Осторожность несимметрична намеренно: лишняя сверка стоит одного запроса
к терминалу, а неверный вывод «отказ» — неучтённой позиции.

Ложных остановок это почти не добавляет: если заявка правда отклонена,
сверка докажет это по её состоянию (И1-C), и остановки не будет.

### Примеры объяснений

```
10019 → на счёте не хватает свободных средств (код 10019)
10018 → рынок закрыт (код 10018)
10016 → стоп-лосс или тейк-профит слишком близко к цене (код 10016)
10008 → заявка размещена — это НЕ отказ, исполнение может произойти позже
10046 → встречные позиции по инструменту запрещены (код 10046)
```

Номер кода тоже показывается — чтобы при желании найти его в документации
брокера. Комментарий брокера сохраняется рядом.

### Тесты

| Сценарий | Итог |
|---|---|
| **Незнакомый код** (`12345`, `19999`, `0`, `-7`) → неопределённость, не отказ, повторять нельзя | ✅ |
| **Нечитаемый код** (строка, пусто) → тоже неопределённость | ✅ |
| Четыре класса разделены — 13 конкретных кодов проверены поимённо | ✅ |
| `PLACED` не считается отказом, и объяснение говорит это прямо | ✅ |
| Повторяются только временные отказы; молчание сервера — **нет** | ✅ |
| У каждого кода есть объяснение, и оно по-русски | ✅ |
| Объяснение доходит до итога заявки вместе с комментарием брокера | ✅ |
| Таблица согласована с разбором ответа | ✅ |
| Каждый код ровно в одном классе, кодов не меньше 35 | ✅ |
| **Структурно:** вбитого списка из трёх кодов в отправке не осталось | ✅ |

**Проверка «наоборот».** Если вернуть «незнакомое = отказ», падают
**двенадцать** проверок:

```
СБОЙ  Код 12345: неопределённость -> окончательный отказ
СБОЙ  И разбор ответа отвечает «неизвестно» -> отказ
СБОЙ  Положение дел считается невыясненным
```
