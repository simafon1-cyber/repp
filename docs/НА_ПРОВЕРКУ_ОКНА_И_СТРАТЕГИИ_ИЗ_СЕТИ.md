# ЧАСТЬ 1. ЧЁРНЫЕ ОКНА

## Дефект 1. Каждая внешняя команда открывала окно

### Почему так было

Программа собрана **оконной** (windowed): своей консоли у неё нет. Когда
такая программа запускает консольную команду, Windows обязана дать этой
команде консоль — и даёт: новое окно. На Windows 11 роль консоли
исполняет «Терминал», поэтому в панели задач появляются окна с этим
именем — ровно то, что на снимке владельца.

Одно окно мелькнуло бы и исчезло. Но команд несколько, и зовутся они
часто. Главная — `icacls`: права на файл настроек переписываются при
**каждом** сохранении.

### Как было (дословно, `safe_files.py`)

```python
        subprocess.run(
            ["icacls", path, "/inheritance:r", "/grant:r", f"{domain_user}:F"],
            capture_output=True, timeout=5, check=False,
        )
```

Ни `creationflags`, ни `startupinfo`. Так же было в `trade_journal.py`,
`manifest.py`, `mt5_install.py`, `updater.py` и в прогоне исследования —
**в шести местах из семи**.

### Как стало

Новый модуль `ai_scalper_standalone/quiet_run.py`:

```python
def без_окна() -> dict:
    if sys.platform != "win32":
        return {}
    добавка = {"creationflags": CREATE_NO_WINDOW}
    ...
    начало.wShowWindow = _SW_HIDE
    добавка["startupinfo"] = начало
    return добавка
```

и во всех шести местах — `**quiet_run.без_окна()`.

Флаг `CREATE_NO_WINDOW` говорит Windows: консоль команде дай, окно не
показывай. `STARTUPINFO` с `SW_HIDE` — на случай, если команда попробует
показать окно сама.

**Прячется ОКНО, а не ошибка.** Коды возврата, вывод и исключения
остались как были. Спрятать окно и спрятать ошибку — разные вещи.

### Единственное исключение, и оно названо вслух

Установщик новой версии (`updater.py`) запускается с `DETACHED_PROCESS`:
он обязан пережить закрытие самой программы, ради которого и
запускается. Microsoft прямо пишет, что `CREATE_NO_WINDOW` **нельзя**
сочетать с `DETACHED_PROCESS`. Консоли у отделённого процесса и так нет.
Исключение записано в тесте поимённо, а не «просто пропущено».

## Дефект 2. Команда могла ждать вечно (найден по дороге)

`trade_journal.ревизия()` и `run_h1_edge_study._ревизия()` звали
`git rev-parse` **без таймаута**:

```python
        return subprocess.check_output(
            ["git", "-C", ..., "rev-parse", "HEAD"],
            stderr=subprocess.DEVNULL).decode().strip()
```

`check_output` ждёт столько, сколько потребуется. Зависший `git` подвесил
бы всю программу — а ревизия нужна лишь как сведение для паспорта
выгрузки. Ради него ждать нельзя ни минуты.

Добавлен `timeout=10` в оба места, и на это есть отдельная проверка: ни
одна ждущая команда не имеет права остаться без предела.

# ЧАСТЬ 2. СТРАТЕГИИ ИЗ РЕПОЗИТОРИЯ

## Что сделано

Новый модуль `strategies_feed.py`. Программа раз в пять часов читает файл
`strategies_online.json` из **того же** репозитория, откуда берёт
обновления, и добавляет найденные стратегии в список выбора. Пересобирать
`.exe` ради новой стратегии больше не нужно.

Настройки: `STRATEGY_FEED_ENABLED = True`, `STRATEGY_FEED_HOURS = 5`.

## Главное: что файлу из сети ПОЗВОЛЕНО

Файл приходит из интернета. **Кто управляет файлом — управляет
настройками торговли.** Поэтому скачанная стратегия проходит четыре сита,
и каждое по отдельности отбрасывает её целиком:

| Сито | Что отсекает |
|---|---|
| 1. Настройка обязана уже существовать в программе | придумать новую настройку из интернета нельзя |
| 2. Запрещённые имена | список из `remote_settings.FORBIDDEN` — тот самый, что уже прошёл аудит: токены, пароли, пути, логины, обновление, предторговый барьер, зеркало |
| 3. Параметры риска | `PROTECTED_PARAMS`: размер сделки и лимиты убытка задаются профилем риска, а не файлом из сети |
| 4. Значение обязано быть простым | да/нет, число или строка. Ни списков, ни словарей |

Плюс: **ключ скачанной стратегии не может совпасть со встроенным.** Иначе
файл из сети переопределил бы «С-001» или «Зеркало», и человек нажал бы
не то, что думает. Проверка стоит **дважды** — в `strategies_feed` и в
`strategies.все()`: защита, которую снимает одна правка в другом файле, —
не защита.

## Чего файл из сети НЕ может

* **Включить стратегию сам.** Применяет её человек, нажатием в окне.
  На это есть отдельная проверка по дереву кода: в модуле подтягивания
  нет ни записи в настройки, ни переключения активной стратегии.
* Поменять размер сделки, лимиты убытка, номер счёта.
* Включить реальную торговлю или зеркало.
* Поменять репозиторий обновлений, токен, пароль, путь.

## Отдельного адреса нарочно нет

Список читается из `UPDATE_REPO` / `UPDATE_BRANCH`. Свой адрес означал бы
**вторую дверь**, которую можно подменить удалённо. Менять `UPDATE_REPO`
и `UPDATE_BRANCH` удалённо запрещено, и список стратегий наследует эту
защиту.

## Происхождение приписывается всегда

К предупреждению каждой скачанной стратегии программа сама дописывает:
«Загружена из репозитория, вместе с программой НЕ проверялась.
Прибыльность не обещана.» Убрать это из файла нельзя — текст добавляется
кодом, а не берётся из файла.

## Нет сети — работаем как раньше

Последний удачно скачанный список лежит в кэше рядом с программой.
Пустой ответ, битый файл, отказ сети — встроенные стратегии остаются на
месте. Проверено на пяти видах мусора.

## Чего эта работа НЕ проверяет — честно

1. **Что окон действительно не стало.** Здесь Linux, консолей Windows нет
   вовсе, и увидеть окно невозможно. Проверено, что флаг передаётся, — а
   не что Windows его послушалась. Убедиться может только владелец, на
   своей машине.
2. **Сеть не проверялась.** Файл в тестах подставляется текстом.
   Проверены разбор и защита, а не то, что GitHub ответит.
3. **Ничего не проверялось у настоящего брокера.** Пакет MetaTrader5
   работает только под Windows, терминала в облаке нет. Зелёные тесты с
   поддельным брокером **не являются** доказательством поведения у
   настоящего.
4. **Не проверено, что 20-30 окон были именно от этих команд.** Снимок
   экрана показывает окна «Терминал», а причина установлена по коду:
   шесть вызовов из семи запускались без флага. Это объяснение, которое
   сходится, но не измерение на машине владельца.

## Собственная ошибка, найденная по дороге

Полный прогон дал один сбой — в проверке мёртвого кода:

```
  СБОЙ Ни одной функции, которую никто не вызывает
       -> strategies_feed.py:обновить_если_пора
```

Я написал в модуле удобную обёртку `обновить_если_пора`, а окно подключил
к `пора()` и `обновить()` напрямую — обёртка осталась лежать без дела.
Функция, которую никто не зовёт, опасна не сама по себе: её никто не
проверяет, и однажды кто-то позовёт её, считая рабочей.

Обёртка удалена. Поведение программы от этого не изменилось ни на шаг —
окно как звало две функции, так и зовёт.

## Что сознательно не сделано

1. **Список стратегий в репозитории пока пуст.** Класть туда стратегию
   «на пробу» — значит предложить владельцу непроверенный вариант.
   Механизм готов; чем его наполнять — отдельный разговор.
2. **Скачанные стратегии не проходят через паспорт.** Паспорт заводится
   на версию, которую проверяют по регламенту. Скачанная стратегия —
   вариант настроек, а не версия; вместо паспорта у неё приписка о
   происхождении. Если понадобится проверять их по регламенту, это
   отдельная работа.
3. **Д-001 не начат** — владелец не назвал признак входа из шести.
4. **Отбор пар по ширине спреда не делался** — это напрашивается после
   работы по «Зеркалу», но требует своего паспорта: числа уже увидены.

## Что работа НЕ меняет

* Прибыльности не добавляет. Ожидание входа как было **−0,0244 R до
  издержек**, так и осталось.
* Риск, лот, стопы, тейк-профиты, индикаторы — не тронуты.
* Мартингейл, сетка, усреднение остаются запрещены полностью.
* Удалённо `LIVE_TRADING` по-прежнему можно ставить только `False`.
* Ни одна скачанная стратегия не включается сама.

Изменилось по существу два: окна консоли больше не открываются, и новые
стратегии можно добавлять, не пересобирая программу.
