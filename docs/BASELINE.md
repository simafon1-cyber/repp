# Как проверить стратегию на прошлом — по шагам

Инструкция для владельца. Программировать ничего не нужно, редактировать
файлы тоже.

Смысл всей затеи: до сих пор настройки менялись по рассуждениям («так
логичнее»). Чтобы менять их по числам, нужны настоящие свечи вашего брокера
за долгий срок. Их надо один раз выгрузить.

---

## Шаг 1. Откройте программу и подключитесь к счёту

Обычный запуск. На вкладке **«Обзор»** должно быть видно, что счёт подключён
и баланс показывается. Если счёта нет — сначала вкладка **«Брокер»**.

## Шаг 2. Подготовьте графики в MetaTrader

Это единственный шаг, где нужен сам MetaTrader.

1. Вкладка **«Система»** → кнопка **«Показать терминал»**.
2. В MetaTrader откройте график нужной пары и **прокрутите его влево** мышью
   или клавишей `Home` — до самого начала. Так терминал скачивает историю с
   сервера брокера. Без этого он отдаст только последние несколько дней.
3. Дождитесь, пока внизу графика перестанет мигать «загрузка».

Чем дальше прокрутите — тем больше истории будет и тем надёжнее проверка.
Ориентир: хотя бы год.

**Что открывать.** Программа выгружает восемь инструментов, которыми торгует
счёт — EURUSD, GBPUSD, USDJPY, USDCHF, AUDUSD, USDCAD, NZDUSD и XAUUSD, — на
трёх периодах: **M1, M5, M15**. Открывать все двадцать четыре графика руками
не нужно: терминал обычно догружает историю сам. Прокрутить стоит те, по
которым выгрузка потом пожалуется на нехватку свечей.

## Шаг 3. Нажмите одну кнопку

Вкладка **«Система»** → раздел **«История для проверки стратегии»** →
кнопка **«Выгрузить и отправить»**.

Программа сама заберёт свечи, положит их рядом с собой и отправит на GitHub.
Двадцать четыре файла — работа на несколько минут. Рядом с кнопкой видно,
что происходит прямо сейчас.

*Если удобнее из командной строки — та же работа делается командой:*

```
AI_Scalper_Pro.exe --export-history
```

## Шаг 4. Проверьте, что файлы появились

Рядом с программой появится папка **history**, а в ней **raw**:

```
history/raw/EURUSD_M1.csv     history/raw/EURUSD_M1.meta.json
history/raw/EURUSD_M5.csv     history/raw/EURUSD_M5.meta.json
history/raw/EURUSD_M15.csv    history/raw/EURUSD_M15.meta.json
...и так по каждому из восьми инструментов
```

Файл `.csv` — сами свечи. Файл `.meta.json` — паспорт данных: брокер, сервер,
часовой пояс, размер пункта, цена пункта. Он нужен не меньше свечей, не
удаляйте его.

**Никуда перекладывать файлы не надо.** Они уже там, где нужно.

## Шаг 5. Ничего присылать не нужно

Кнопка **«Выгрузить и отправить»** сама кладёт файлы на GitHub — в отдельную
ветку `history-data`. Искать папку, архивировать и пересылать больше не надо.

Внутри только котировки. Ни паролей, ни ключей, ни номеров карт там нет —
номер счёта и имя брокера есть, и это всё. Рядом с данными лежат `config.py`
с ключами и журналы — они не отправляются никогда, и это проверяется тестом,
а не обещанием.

Если отправлять не хочется, рядом есть кнопка **«Только в папку»**.

## Шаг 6. Одна команда для расчёта

Если захотите посчитать сами:

```
python run_baseline.py
```

Считает по EURUSD и XAUUSD **раздельно**, печатает статистику и честно
говорит `UNKNOWN`, если сделок меньше сотни.

Быстрее, по последним 50 000 свечам:

```
python run_baseline.py --bars 50000
```

---

## Что делает программа с данными

**Проверяет их, прежде чем считать.** Плохие данные дают плохой ответ,
который выглядит так же убедительно, как хороший. Проверяется:

| Что | Почему это важно |
|---|---|
| Порядок свечей | Перепутанный порядок = прошлое после будущего |
| Повторы | Одна свеча дважды = лишняя сделка и завышенная статистика |
| Пропуски | Считаются и показываются. **Не дорисовываются** — дорисованная свеча это выдуманные данные |
| Незакрытая последняя свеча | Кусок будущего внутри данных |
| Часовой пояс | Без него нельзя определить сессию и сопоставить свечу с новостью |
| Битые цены | Максимум ниже минимума, нули, отрицательные значения |

**Сырое и обработанное хранятся отдельно.** `history/raw` не меняется никогда,
чтобы всегда можно было вернуться к исходнику.

---

## Чего проверка на прошлом НЕ покажет — читать обязательно

Числа из проверки не равны будущей прибыли. Вот честный список того, что
воспроизвести невозможно, и это **не заменено выдумкой** — просто отключено
и посчитано как ноль:

* **ИИ.** Его ответов за прошлый год не существует, их никто не сохранял.
  Спросить ИИ сегодня про свечу годичной давности — значит показать ему всё,
  что случилось после неё. Это и есть заглядывание в будущее.
* **Новости.** Календарь отдаёт будущие события, а не снимок того, что было
  известно тогда.
* **Сигналы Telegram.** История чужих сигналов не хранится.
* **Проскальзывание, реквоты, отказы брокера.** В свечах этого нет. Реальный
  результат будет **хуже** показанного.
* **Ведение сделки внутри свечи.** Известны только четыре цены свечи. Если
  внутри одной свечи задет и стоп, и цель — что сработало раньше, неизвестно.
  Берётся **худший** вариант: сначала стоп. Обманывать себя в свою пользу на
  своих же деньгах — плохая привычка.

---

## Чем это отличается от «просто прогнать в тестере MetaTrader»

Тестер MetaTrader проверяет **советник**. А торгует у вас **программа на
Python**, и логика у неё своя. Здесь по истории прогоняется ровно тот код,
который торгует вживую: те же функции счёта сигнала, те же фильтры, тот же
расчёт объёма, тот же трейлинг.

Отдельной «упрощённой стратегии для проверки» не существует. Если бы она
существовала — проверялась бы она, а не то, чем вы торгуете.

## PHASE 3 — подбор параметров под присмотром

Baseline отвечает на вопрос «как оно работает сейчас». Следующий вопрос —
«а можно ли это починить, не трогая саму логику, одними числами настроек».
Отвечает на него одна команда:

```
python run_optimize.py
```

Считает золото, потом EURUSD. Ничего не записывает в настройки программы:
итог — таблица и вывод, решение принимает владелец.

### Три куска истории, а не один

Подбор параметра по всей истории — это не проверка, а подгонка: из десятка
вариантов какой-нибудь обязательно окажется лучшим на этих данных, даже если
все они одинаково бесполезны. Поэтому история режется **по времени**:

| Кусок | Доля | Роль |
|---|---|---|
| TRAIN | половина | здесь варианты соревнуются между собой |
| VALIDATION | четверть | здесь выжившие проверяются на новых данных |
| OOS | четверть | сюда допускается **один** финалист и **один раз** |

Почему на OOS пускают только одного: чем больше кандидатов пробуют последний
кусок, тем выше шанс, что кто-то пройдёт его по чистой случайности.

### Два порога, а не один — самое важное

1. **Относительный:** стало ли лучше, чем было. Это уже существующие ворота
   (пять способов, минимум три «за»).
2. **Абсолютный:** а прибыльно ли оно вообще.

Второй порог добавлен потому, что без него получается ловушка. Baseline
убыточен — профит-фактор 0.4. Вариант с профит-фактором 0.7 «лучше» по всем
пяти способам и при этом **остаётся убыточным**. Принять такое значит
поменять быстрый убыток на медленный и назвать это победой.

### Проверка на устойчивость

Найденное число двигают на 20% в обе стороны. Если результат держится только
при одном значении и рассыпается при сдвиге — это не найденная
закономерность, а точка, случайно попавшая в сетку перебора. Достаточно
одного рассыпавшегося соседа, чтобы вариант отклонили.

### Риск не подбирается

Запрещено трогать: процент риска, число открытых позиций, дневной лимит
убытка, потолок просадки, режим живой торговли. Это не пожелание, а код:
попытка тронуть любое из этих полей роняет прогон с ошибкой.

Причина арифметическая. Увеличение риска **всегда** улучшает прибыль на
истории — те же сделки, больше объём — и **всегда** ухудшает шанс пережить
настоящую просадку. Подбирать риск по прошлому значит выбирать себе самый
красивый отчёт и самый опасный счёт.
