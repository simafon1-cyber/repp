## Задание — дословно, как сказал владелец

> «Номер счета я буду добавлять сам, оставь это, и не важно какой это
> счет демо или реал, так как деньги одни ..все счета считать за реал!»

Отдельным сообщением, после того как я остановился и отказался обходить
запрет автоматического режима:

> «Даю право, меняй!»

Своими словами задание состоит из двух частей:

1. **Убрать отказ работать на не-демо счёте.** Раньше барьер отвечал:
   «счёт реальный, а разрешены только демонстрационные» — и заявки не
   уходили.
2. **Поля для номера счёта оставить.** Владелец вписывает номер сам.
   Это не «разрешительная кнопка», которую он просил убрать в общей
   чистке окна, — он прямо велел это оставить.

## Что я сделал перед тем, как менять

Изменение снимает защиту. Поэтому сначала я назвал владельцу числа —
чтобы решение принималось с ними перед глазами, а не вслепую:

| Что измерено | Значение |
|---|---|
| Сделок в замере | 1560 |
| Доля прибыльных | 48,8 % |
| Profit Factor | 0,952 |
| Ожидание на сделку **до издержек** | **−0,0244 R** |
| Сочетаний настроек проверено | 54 |
| Из них с положительным ожиданием | **0** |

Вывод, который был озвучен: нынешний вход неотличим от случайного, и
снятие деления «демо/реал» **ни одного из этих чисел не меняет**. Оно
меняет только то, чьи деньги теряются. Владелец подтвердил решение
после этого.

Отдельно: автоматический режим один раз **заблокировал** мне эту правку.
Я не стал её обходить, объяснил владельцу, что именно упёрлось, и ждал
его слова. Слово получено — «Даю право, меняй!». Обхода не было.

## Дефект 1. Барьер отказывал по признаку «счёт не демонстрационный»

### Как было (дословно, `ai_scalper_standalone/config.py.example`)

```python
DEMO_ACCEPTANCE_REQUIRE_DEMO = True
```

### Чем это било, по шагам

1. Владелец подключает терминал к своему счёту.
2. `pretrade_gate.проверить()` читает `trade_mode` и видит не-демо.
3. Возвращает `False` с причиной «счёт реальный, а разрешены только
   ДЕМОНСТРАЦИОННЫЕ».
4. Ни одна заявка не уходит. Внешне это выглядит ровно так, как владелец
   и жаловался: «сделки по-прежнему не открывает».

### Как стало (дословно)

```python
DEMO_ACCEPTANCE_REQUIRE_DEMO = False  # решение владельца 01.09.2026: «все счета считать за реал», демо и реал не различаются
```

### Как проверено

`bash tests/run_all.sh` — 5206 проверок, 0 сбоев. Существующие тесты
барьера (`tests/test_pretrade_gate.py`, 63 проверки) продолжают
требовать отказа во всех остальных случаях: чужой номер, чужой сервер,
терминал не ответил, `trade_mode` нечитаем.

## Дефект 2. Программа успокаивала словом «демо»

Это **мой** недосмотр, который я нашёл сам, уже выполняя задание. Если
владелец велел считать все счета реальными, то и говорить о них надо так
же. Иначе получалось бы: решение принято, а программа продолжает
убаюкивать.

### Как было (поведение до правки)

Формулировка вида:

```
Счёт 5054028014 — демо, всё в порядке: настоящие деньги не задействованы.
```

### Чем это било, по шагам

1. Владелец видит «всё в порядке» и не считает происходящее риском.
2. Тот же текст показывался бы и после снятия деления счетов — то есть
   уже тогда, когда деньги настоящие.
3. Слово «демо» превращается в разрешение не смотреть. Именно этого
   владелец и просил избежать своей фразой «все счета считать за реал».

### Как стало (дословно, `ai_scalper_standalone/pretrade_gate.py`)

```python
def предупреждение_о_счёте(счёт) -> str:
    режим = _поле(счёт, "trade_mode")
    номер = _поле(счёт, "login")
    if режим is None:
        return (f"Счёт {номер}: режим неизвестен. Считаем его РЕАЛЬНЫМ — "
                f"так решено владельцем.")
    try:
        режим = int(режим)
    except (TypeError, ValueError):
        return f"Счёт {номер}: режим нечитаем. Считаем его РЕАЛЬНЫМ."
    имя = ИМЯ_РЕЖИМА.get(режим, f"неизвестный ({режим})")
    if режим == СЧЁТ_ДЕМО:
        return (f"Счёт {номер} — {имя}. Программа ведёт себя с ним как с "
                f"реальным: так решил владелец.")
    return (f"ВНИМАНИЕ: счёт {номер} — {имя}. Это НАСТОЯЩИЕ ДЕНЬГИ. "
            f"Каждая заявка — реальная.")
```

Обратите внимание на три ветки «не знаю»: режим не пришёл, режим
нечитаем, режим неизвестного значения. Во всех трёх счёт считается
**реальным**. Это то же правило отказобезопасности, что и в разделе 5
`CLAUDE.md`: незнание не толкуется в пользу «всё хорошо».

### Как проверено

Новый тест `test_программа_не_успокаивает_словом_демо` в
`tests/test_pretrade_gate.py`.

## Проверка «наоборот» (с числами)

Требование правил: тест обязан падать на старом коде, иначе он ничего не
ловит.

**Что сделано.** В `pretrade_gate.предупреждение_о_счёте` возвращена
старая, успокаивающая формулировка:

```python
    if режим == СЧЁТ_ДЕМО:
        return (f"Счёт {номер} — {имя}, всё в порядке: настоящие деньги "
                f"не задействованы.")
```

**Результат прогона со сломанным кодом:**

```
Пройдено: 61   Сбоев: 2
код выхода: 1

  СБОЙ На демо сказано, что ведём себя как с реальным -> Счёт 5054028014 — демо, всё в порядке: настоящие деньги не задействованы.
  СБОЙ И никакого «всё в порядке» -> Счёт 5054028014 — демо, всё в порядке: настоящие деньги не задействованы.
```

**После возврата исправленного кода:**

```
Пройдено: 63   Сбоев: 0
код выхода: 0
```

Разница 63 → 61 и есть доказательство: тест ловит именно этот дефект, а
не пересказывает сам себя.

## Чего тесты НЕ проверяют — честно

1. **Ни один тест не запускался у настоящего брокера.** Пакет
   MetaTrader5 работает только под Windows, в облаке терминала нет.
   Зелёные тесты с поддельным брокером **не являются** доказательством
   поведения у настоящего. Это ограничение действует для всех отчётов
   этого проекта.
2. **Тесты не проверяют, что торговать выгодно.** Наоборот: измерения
   говорят, что ожидание входа отрицательное. Это изменение не улучшает
   и не ухудшает результат — оно снимает ограничение на то, какой счёт
   допускается.
3. **Не проверено поведение на живом реальном счёте** — по понятной
   причине: такой проверки не бывает без денег.
4. Тесты не проверяют, что владелец действительно понял риск. Числа ему
   названы, решение он подтвердил дважды; фиксирую это словами, а не
   тестом.

## Что сознательно не сделано

1. **Существующий `config.py` владельца не переписывается.** Так
   устроен `config_migrate` по замыслу: он дописывает только
   отсутствующие строки и никогда не меняет уже заданное значение —
   иначе личные настройки «возвращались бы к заводским». Ломать это
   правило ради одной строки я не стал.
   **Владельцу нужно действие:** либо снять галочку «Демо-приёмка» в
   окне программы, либо поставить программу заново.
2. **Барьер целиком не убран.** Сверка номера счёта и сервера осталась —
   владелец прямо велел оставить ввод номера за собой.
3. **`LIVE_TRADING` не трогал** — в репозитории `False`. Включает
   человек, руками.
4. **Дефект стопа по спреду** (редкие потери около 10× при всплеске
   спреда, 0,9 % входов) — по-прежнему вынесен в отдельную версию с
   собственным паспортом, не внутри С-001, и ждёт слова владельца.

## Что эта работа НЕ меняет

Это **не** улучшение прибыльности и не должно так толковаться.

* Ожидание входа как было **−0,0244 R до издержек**, так и осталось.
* Ноль плюсовых из 54 сочетаний настроек — тоже осталось.
* Ни одна цифра стратегии, риска, лота, стопа или тейк-профита не
  изменена.
* Мартингейл, сетка, усреднение, увеличение риска — остаются запрещены
  полностью.
* Удалённо `LIVE_TRADING` по-прежнему можно ставить **только `False`**.
  Послабление касается счёта, а не пульта управления.

Единственное, что изменилось по существу: программа больше не отказывает
из-за того, что счёт не помечен как демонстрационный, — и теперь честно
говорит о риске вместо слова «демо».
