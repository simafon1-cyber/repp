## 1. ЗАДАНИЕ СВОИМИ СЛОВАМИ

Аудит принял P1-E4 (одноразовость OOS) и **не закрыл P1-E3**.

Дословно: барьер OOS всё ещё ложный на предварительном пути. Я починил
узкое место — чтение среза внутри `сделки_среза`. Но `проверка_4_срезы`,
идущая **до** отметки об открытии OOS, звала
`unseen_split.посчитать(папка_h1, прежние)`, а тот читает **каждый
часовой файл целиком** и считает все 24 отпечатка срезов, включая OOS.

Требовалось: до отметки сверять только границы и отпечатки видимых
срезов; отпечатки OOS пересчитывать **после** отметки и до расчёта
сигналов; разделить функцию; инструментировать в тесте **все**
предмаркерные источники часовых данных; сделать отрицательный тест,
который падает именно из-за раннего доступа к OOS.

## 2. ЧТО БЫЛО НА САМОМ ДЕЛЕ

### Как было (дословно)

```python
def проверка_4_срезы(папка_h1: str) -> dict:
    """24 отпечатка срезов пересчитаны и сверены с файлом границ."""
    записано = json.loads(open(ГРАНИЦЫ, encoding="utf-8").read())
    ...
    посчитано = unseen_split.посчитать(папка_h1, прежние)     # <-- здесь
```

а внутри `unseen_split.посчитать`:

```python
        строки = _строки(путь)                # ВЕСЬ файл, включая OOS
        времена = [int(с.split(";")[0]) for с in строки]
        ...
        for часть in ЧАСТИ:                   # train, validation, OOS
            запись["части"][часть] = {..., "sha256": отпечаток_среза(...)}
```

### Чем это било по шагам

1. Прогон доходит до проверки 4 — это **до** отметки об открытии OOS.
2. `_строки(путь)` читает четырёхлетний часовой файл целиком, включая
   невиданную четверть.
3. Отпечаток среза OOS считается тут же — то есть невиданные строки не
   просто прочитаны, а разобраны по одной.
4. Всё это повторяется по восьми инструментам.
5. Заявление «невиданные данные физически не открываются до финального
   шага» было неверным — во второй раз подряд.

### Почему мой тест этого не увидел

Тест подменял `run_h1_edge_study._построчно` и считал выданные строки.
`unseen_split` этой функцией не пользовался — у него был свой `open()` и
`f.read()`. Счётчик показывал ноль строк OOS, а файл в это время
разбирался целиком.

**Я проверил один источник чтения и назвал это проверкой чтения.**

## 3. КАК СТАЛО

### 3.1. Один построчный источник на все часовые данные

В `unseen_split.py` появилась `построчно()`, и **все** чтения сведены к
ней:

```python
def _времена(путь) -> list:
    return [int(с.split(";")[0]) for с in _строки(путь)]


def _строки(путь) -> list:
    """ВЕСЬ файл списком строк. ... Идёт через построчно() намеренно."""
    return [с.strip() for с in построчно(путь) if с.strip()]
```

Своего `open()` в `unseen_split` больше нет нигде, кроме `построчно`.

### 3.2. Отпечаток куска без чтения того, что за ним

```python
def отпечаток_куска(путь_h1, пропустить, сколько, и_следующую=False) -> dict:
    """Читается ровно (пропустить + сколько) строк, а при и_следующую —
    на одну больше. Ни одной сверх этого: поток закрывается сразу."""
```

Считать по числу строк законно: невиданная часть — это **начало** файла
(бары раньше самой ранней уже сохранённой свечи), а train / validation /
OOS идут внутри неё подряд. Числа баров зафиксированы в
`preregistration/границы_h1.json`, чей sha256 записан в паспорте и
сверяется проверкой 2.

### 3.3. Проверка 4 разрезана надвое

**До отметки** — `проверка_4_видимые_срезы`:

* граница виденного выводится из **прежних M1/M5/M15** — часовых файлов
  не касается вовсе — и сверяется с записанной;
* сверяются **16** отпечатков: train и validation по восьми
  инструментам; чтение обрывается на последней строке validation.

**После отметки, до расчёта сигналов** — `проверка_7_срезы_oos`:

* сверяются оставшиеся **8** отпечатков OOS;
* подтверждается, что невиданная часть кончается ровно там, где
  записано: строка сразу за концом OOS обязана быть не раньше границы
  виденного (или файл обязан кончиться).

Второе перенесено за отметку не по лени: чтобы **увидеть** конец
невиданной части, надо дочитать OOS. До отметки это было бы той же
утечкой.

Вызова `unseen_split.посчитать()` в прогоне больше нет.

### Как проверено на настоящих данных

Механизм сверен с зафиксированными отпечатками на живом архиве — **только
по видимым срезам**, OOS не трогался:

```
сошлось 16, разошлось 0  (из 16 видимых отпечатков)
```

Отпечатки OOS будут посчитаны впервые внутри единственного прогона, после
отметки. Так и задумано.

## 4. ГРАНИЦА ЧЕСТНОСТИ: ЧТО ДО ОТМЕТКИ ВСЁ ЖЕ ЧИТАЕТСЯ

Говорю прямо, чтобы это не выглядело сокрытием.

`проверка_3_распаковка` распаковывает архив на диск. Байты невиданной
части при этом проходят через процесс — иначе файлов не появится вовсе.
Строки при этом **не разбираются**: архив берётся как непрозрачный файл,
как и разрешил аудит. Отпечаток архива `sha256` считается тем же образом
— чтением двоичных кусков, без разбора полей.

Проверяемое утверждение звучит так: **ни один путь исполнителя до отметки
не выдаёт ни одной строки часового файла с отметкой времени из OOS.**
Именно это и проверяется тестами, а не более сильное «байты не
касались диска».

### Восьмой случай подряд: тест снова прошёл при сломанном коде

Первая попытка сломать код предмаркерным `посчитать()` дала **73 из 73
без сбоев**, хотя утечка была ровно та, что нашёл аудит. Причина уже
описана в разделе 2: следилка стояла на одном источнике, а читал другой.

Свёл все чтения к одному источнику — поломка стала ловиться. Тут же
проверил следующий обход: вернул в `_строки()` свой `open()`. **Снова 73
из 73 без сбоев** — слежка за функцией обходится новым `open()`.

Поэтому добавлен тест, который не следит за строками вообще, а считает
**два независимых числа** до отметки: сколько раз любой `*_H1.csv`
открывался на чтение и сколько раз при этом входили в следимый источник.
Они обязаны совпасть.

```
СБОЙ И каждое открытие прошло через следимый источник
     -> открытий 12, входов в источник 8
```

Прежние семь случаев: подделка, игнорировавшая фильтр; тест, не
включённый в список запуска; проверка, не поймавшая расчёт по тику; два
инструмента вместо трёх; порча архива вместо записи в паспорте; «любой
ненулевой код» вместо конкретного; удалённая отметка, проверенная по
коду возврата вместо факта чтения.

Закономерность своя, и она уточнилась: **я проверяю один путь и называю
это проверкой свойства.** Один источник строк, одно последствие, один
вызов. Свойство «OOS не читался» держится не на одном пути, а на всех —
и проверять его надо так, чтобы новый путь не появился незамеченным.

## 7. ЧЕГО ЭТИ ТЕСТЫ НЕ ПРОВЕРЯЮТ

2. **Настоящие данные.** Все поведенческие тесты идут на синтетических

## 12. ЗАПРОС ПРИЁМКИ

Прошу проверить на точном хеше этой ревизии:

* отсутствие предмаркерного разбора OOS **на всех** путях, включая
  сверку срезов;
* что `unseen_split.посчитать()` до отметки не вызывается;
* перенос восьми отпечатков OOS за отметку — и что это не потеря
  проверки, а перенос;
* совпадение числа открытий часовых файлов с числом входов в общий
  источник;
* заново заверенный паспорт и порядок коммитов;
* полный набор тестов.

Прогон запущу **только после письменной приёмки** — один раз, и результат
покажу целиком, каким бы он ни был.
