## 1. ЗАДАНИЕ СВОИМИ СЛОВАМИ

Владелец переходит с Windows на Mac и хочет, чтобы **эта самая
программа** — не урезанная демонстрация — работала на Mac как обычное
приложение. Живая торговля должна быть возможна через мост до терминала,
потому что напрямую с Mac разговаривать с MetaTrader 5 нечем.

Владелец прямо потребовал **не делать всё одним неаудируемым коммитом**,
а работать этапами и после каждого показывать изменённые файлы и
результаты тестов, не переходя к следующему до приёмки.

**Это отчёт по этапу 1: «Аудит платформенных зависимостей и план
миграции».**

Что в этап 1 входит и что не входит:

| Входит | Не входит (этапы 2–5) |
|---|---|
| Установить, что именно мешает запуску на Mac | Мост до терминала |
| Перечислить **все** зависимости от Windows | Папки macOS и Связка ключей |
| Написать план переноса по этапам | Указатель состояния live в окне |
| Добиться, чтобы программа **запускалась** на машине без терминала и не могла отправить заявку | Сборка `.app`, автопроверки, документы для человека |

Последняя строка левой колонки — не «забежал вперёд». Без неё этап 2
нельзя даже испытать: до этой правки окно на Mac не открывалось вовсе,
и проверить было нечего.

## 2. ГЛАВНЫЙ ПРОВЕРЕННЫЙ ФАКТ

**Библиотеки MetaTrader5 под macOS не существует.**

Не «сложно поставить» — её нет. Проверено обращением к хранилищу
пакетов:

```
$ python3 -c "..."   # запрос к https://pypi.org/pypi/MetaTrader5/json
```

`win_amd64` — Windows, 64 бита. Больше в списке **ничего**: ни macOS, ни
Linux, ни исходников, из которых можно было бы собрать самому.

Полный разбор последствий и план переноса — в отдельном документе
`docs/MACOS_ПЛАН_ПЕРЕНОСА.md`. Он самодостаточен и читается без
репозитория.

## 3. ДЕФЕКТ 1: ПРОГРАММА НЕ ЗАПУСКАЛАСЬ ВООБЩЕ

### Как было

`ai_scalper_standalone/desktop_app.py`, порядок импортов в самом верху
файла:

```python
log = logging.getLogger("desktop_app")

import main as bot_engine
import dashboard_state as ds
...
import mt5_connector as mt5c
```

А в `main.py` строка 21 и в `mt5_connector.py` строка 18:

```python
import MetaTrader5 as mt5
```

### Чем это било, по шагам

1. Человек дважды щёлкает по программе на Mac.
2. Python доходит до `import main as bot_engine`.
3. `main.py` на своей 21-й строке пытается загрузить MetaTrader5.
4. Пакета нет и быть не может.
5. `ModuleNotFoundError` — процесс умирает **до создания окна**.
6. Человек видит: ничего не произошло. Ни окна, ни сообщения, ни
   объяснения. Программа выглядит сломанной без причины.

Пункт 5 — суть дефекта. Окно с объяснением не появлялось потому, что
программа умирала раньше, чем успевала его нарисовать.

### Как стало

Новый файл `ai_scalper_standalone/platform_support.py` и вызов **до**
торговых импортов:

```python
log = logging.getLogger("desktop_app")

# ГДЕ ЭТА ПРОГРАММА МОЖЕТ ТОРГОВАТЬ, А ГДЕ НЕТ.
#
# Делается ДО импорта торговых модулей и это принципиально: main и
# mt5_connector пишут `import MetaTrader5` наверху файла. Пакет собран
# только под Windows, поэтому на Mac этот импорт падает — и окно вообще не
# открывается, даже чтобы показать причину.
import platform_support
СОСТОЯНИЕ_ПЛАТФОРМЫ = platform_support.подготовить()
ТОРГОВЛЯ_ВОЗМОЖНА = not platform_support.почему_нельзя()
if not ТОРГОВЛЯ_ВОЗМОЖНА:
    log.warning("ТОРГОВЛЯ НЕДОСТУПНА. %s", СОСТОЯНИЕ_ПЛАТФОРМЫ)

import main as bot_engine
```

Порядок здесь — не оформление, а условие работы. Позвать слой после
`import main` бессмысленно: `import main` к тому моменту уже упадёт.

### Как проверено

`test_торговые_модули_импортируются` — отдельный процесс грузит
настоящие `main` и `mt5_connector` и печатает `ИМПОРТ-ОК`.

`test_оконный_модуль_готовит_платформу_до_торговых_импортов` — сверяет
**номера строк** по разобранному дереву кода: строка вызова
`подготовить()` обязана быть меньше строки `import main`. Разбор дерева,
а не поиск по тексту: поиск ловил бы собственные пояснения в
комментариях выше.

## 4. ДЕФЕКТ 2 (МОЙ СОБСТВЕННЫЙ): ЗАГЛУШКА КРИЧАЛА ТАМ, ГДЕ ДОЛЖНА БЫЛА ОТВЕТИТЬ «НЕ ВЫШЛО»

Это ошибка, которую я сделал сам в первой версии слоя, нашёл при запуске
окна и исправил. Прячу её не в примечание, а в отдельный раздел.

### Как было

`platform_support.py`:

```python
# Вызовы, которые ЧТО-ТО ДЕЛАЮТ с деньгами. Каждый бросает ошибку.
ТОРГОВЫЕ = ("order_send", "order_check", "order_calc_margin",
            "order_calc_profit", "initialize", "login", "shutdown")
```

### Чем это било, по шагам

1. Окно открывалось — то есть дефект 1 был исправлен.
2. Программа делала первую обычную вещь: пробовала подключиться,
   `mt5_connector.connect()` → `mt5.initialize(...)`.
3. Заглушка бросала `ТорговляНедоступна`.
4. Но `connect()` **не ждёт исключения** — он ждёт `False` и уже умеет
   превратить его в понятную фразу «Не удалось подключиться к MT5…».
5. Исключение пролетало мимо и обрывало вызывающий код.
6. Журнал запуска (`scalper.log`) при живой проверке под `xvfb` набрал
   **24 таких обрыва**.

Хуже всего пункт 4: код был готов обработать отказ красиво, а слой
подсунул ему то, чего он не ждёт. Программа выглядела сломанной там, где
на самом деле всё предусмотрено.

### Как стало

Вызовы разделены на **три** группы по одному признаку: **может ли вызов
создать или изменить позицию.**

```python
# ГРУППА 1. Вызовы, которые ДВИГАЮТ ДЕНЬГИ. Каждый бросает ошибку.
ТОРГОВЫЕ = ("order_send", "order_check")

# ГРУППА 2. Вызовы ПОДКЛЮЧЕНИЯ. Отдают False — «подключиться не удалось».
ПОДКЛЮЧЕНИЕ = ("initialize", "login")

# ГРУППА 2б. Завершение работы. Закрывать нечего — тихо ничего не делаем.
ЗАВЕРШЕНИЕ = ("shutdown",)

# ГРУППА 3. Вызовы, которые только СПРАШИВАЮТ. Отдают пустоту.
# order_calc_margin и order_calc_profit здесь, а не в ТОРГОВЫЕ: они
# ничего не отправляют брокеру, они только считают по его данным.
ЧИТАЮЩИЕ = (..., "order_calc_margin", "order_calc_profit")
```

**Почему `order_send` обязан именно кричать, а не молчать.** По разделу 5
`CLAUDE.md` пустой или нечитаемый ответ на заявку означает «исход
неясен»: остановка, запрет новых входов, разбирательство. Если бы
заглушка на Mac возвращала пустоту, программа расследовала бы заявку,
которой не было. Громкая ошибка исключает эту подмену.

**Почему `initialize` обязан именно вернуть `False`.** Потому что это
правда: подключиться действительно не удалось. Ровно так программа себя
ведёт, когда терминал закрыт на Windows. Никакой подделки здесь нет —
есть честный отрицательный ответ.

### Как проверено

`test_подключение_честно_не_удаётся` — `initialize()` и `login()`
обязаны вернуть **именно `False`**, `shutdown()` — `None`, и ни один не
имеет права бросить.

`test_подключение_даёт_понятный_отказ_а_не_обрыв` — отдельный процесс
зовёт настоящий `mt5_connector.connect()` и печатает, что получилось:
`ПОНЯТНЫЙ-ОТКАЗ` (ожидаемо) или `ОБРЫВ` (дефект).

## 4б. ДЕФЕКТ 3: ВКЛАДКА «ДИАГНОСТИКА» ПАДАЛА

Найден живым запуском окна под виртуальным экраном (`xvfb`), а не
чтением кода. Чтением его увидеть было нельзя.

### Как было

`diagnostics.py`, строка 61:

```python
present = importlib.util.find_spec(name) is not None
```

А заглушка создавалась так:

```python
m = types.ModuleType("MetaTrader5")
m._это_заглушка = True
```

### Чем это било, по шагам

1. Человек открывает вкладку «Диагностика» — самое естественное
   действие, когда что-то не работает.
2. `check_packages()` доходит до `MetaTrader5`.
3. `find_spec` требует у модуля паспорт (`__spec__`). Обычный модуль
   получает его от загрузчика; собранный руками — **не получает**.
4. Вместо ответа «есть» или «нет» вылетает
   `ValueError: MetaTrader5.__spec__ is None`.
5. Вкладка, к которой человек пришёл за объяснением, ломается сама.

### Как стало

```python
    # ПАСПОРТ МОДУЛЯ. Без него `importlib.util.find_spec("MetaTrader5")`
    # не отвечает «нет», а бросает ValueError: «__spec__ is None». Именно
    # так и случилось: вкладка «Диагностика» падала на проверке
    # установленных библиотек — там, где всего-то хотели узнать, есть
    # пакет или нет.
    m.__spec__ = importlib.machinery.ModuleSpec("MetaTrader5", None)
```

### Как проверено

`test_у_заглушки_есть_паспорт_модуля` — `find_spec("MetaTrader5")`
обязан ответить, а не бросить.

## 4в. ДЕФЕКТ 4: ПОЧИНЕННАЯ ДИАГНОСТИКА НАЧАЛА ВРАТЬ

Этот дефект **создала предыдущая правка**. Пишу это прямо: починив
падение, я на один шаг сделал хуже.

### Как было (после починки дефекта 3)

Паспорт появился — и `find_spec("MetaTrader5")` стал честно отвечать
«модуль есть». Ведь заглушка занимает место пакета полноценно, иначе не
запустилось бы ничего.

### Чем это било, по шагам

1. Человек открывает «Диагностику» на Mac.
2. Читает: **`MetaTrader5 — ok, связь с терминалом`**.
3. Делает вывод, что связь есть и дело в чём-то другом.
4. А связи нет и быть не может.

Падающая вкладка была плоха. Вкладка, которая уверенно сообщает
неправду, — хуже: она уводит человека в сторону.

### Как стало

Диагностика спрашивает **не список модулей, а сам слой платформы**:

```python
def _есть_на_самом_деле(name: str) -> bool:
    """Установлен ли пакет ПО-НАСТОЯЩЕМУ.
    ...
    Но в ОТЧЁТЕ ЧЕЛОВЕКУ это была бы ложь: связи с терминалом нет и быть
    не может. Поэтому здесь спрашивается сам слой, а не список модулей."""
    if name == "MetaTrader5":
        try:
            import platform_support
            return platform_support.настоящий_терминал_есть()
        except Exception:  # noqa: BLE001
            pass
    return importlib.util.find_spec(name) is not None
```

И подсказка тоже изменилась. Было бы `pip install MetaTrader5` — совет
поставить пакет, которого не существует. Стало — настоящая причина.

Что видит человек сейчас (настоящий вывод):

```
fail  MetaTrader5    недоступен на этой системе (связь с терминалом)
      | На Linux торговля через MetaTrader 5 невозможна: MetaTrader5
        собран только под Windows (win_amd64).
ok    pandas         расчёт индикаторов
ok    numpy          расчёт индикаторов
```

### Как проверено

`test_диагностика_не_выдаёт_заглушку_за_терминал` — отдельный процесс
зовёт настоящую `diagnostics.check_packages()` и проверяет четыре вещи:
она доработала до конца; MetaTrader5 помечен `fail`; совета
`pip install MetaTrader5` **нет**; настоящая причина названа.

## 6б. ЖИВОЙ ЗАПУСК ОКНА

Тесты грузят модули. Отдельно окно поднималось по-настоящему — на
виртуальном экране (`xvfb`), настоящим `desktop_app.py`, и журнал
разбирался построчно.

Состояний было три, и в таблице они разделены — иначе цифры смешались бы
и «до» означало бы разное в разных строках.

| Что смотрели | Было до слоя | С первой (ошибочной) версией слоя | Сейчас |
|---|---|---|---|
| Окно вообще открылось | нет, процесс умирал на импорте | да | **да**, процесс живёт |
| Обрывов `ТорговляНедоступна` в журнале | — (журнала не было) | **24** | **0** |
| Падение вкладки «Диагностика» | — | есть (`__spec__ is None`) | **нет** |
| Диагностика про MetaTrader5 | — | сказала бы «ok» | **«недоступен на этой системе»** |
| Сказано ли человеку, что торговли не будет | нет | да | **да**, первой же строкой журнала |

Первая строка журнала запуска:

```
[WARNING] desktop_app: ТОРГОВЛЯ НЕДОСТУПНА. На Linux торговля через
MetaTrader 5 невозможна: MetaTrader5 собран только под Windows
(win_amd64). Ни одна заявка брокеру отсюда уйти не может.
```

**Что при этом всплыло и НЕ исправлено.** Торговый цикл зовёт
`connect()`, получает понятный отказ, поток завершается — и сторож
поднимает цикл заново. За 25 секунд: 2 попытки. На Windows это
правильно (терминал могли просто закрыть, человек его откроет). На Mac
следующая попытка не удастся **никогда**. Это не «сломано», а
«неуместно», и чинить это надо вместе с мостом: правильное поведение
звучит как «жду мост», а не «пытаюсь ещё раз». Вынесено в этап 2,
записано в план, раздел 2.6.

## 7. ЧЕГО ЭТИ ТЕСТЫ НЕ ПРОВЕРЯЮТ

Честный список.

1. **Поведение у настоящего брокера.** Зелёные тесты с поддельным
   брокером **не являются** доказательством поведения на реальном счёте.
   Это ограничение относится ко всей работе.
2. **Запуск на настоящем Mac.** Проверка шла на Linux — там ровно та же
   картина: MetaTrader5 отсутствует, ветка кода одна и та же. Но это
   Linux, а не macOS. Живой запуск `.app` — этап 4.
3. **Само окно — автоматически не проверяется.** Тесты грузят модули и
   проверяют вызовы; окна они не открывают и кнопок не нажимают. Живой
   запуск из раздела 6б делался **руками** и в `run_all.sh` не входит:
   он требует виртуального экрана, которого на машине владельца нет.
   Значит, повторяемость раздела 6б держится на моём слове, а не на
   прогоне. Автоматический запуск окна — задача этапа 4 вместе со
   сборкой `.app`.
4. **`os.startfile`.** Дефект найден и записан в план (`desktop_app.py`,
   строки 4937 и 4944, без защиты платформой), но **не исправлен** —
   это этап 2. Теста на него пока нет.
5. **Мост до терминала.** Его ещё нет. Ничего, связанного с живой
   торговлей через мост, здесь не проверяется.
6. **Установка зависимостей на Mac.** Найдено, что `requirements.txt`
   оборвёт `pip install` на строке `MetaTrader5>=5.0.45` — записано в
   план, не исправлено.
7. **Поведение сторожа без терминала.** Найдено живым запуском (раздел
   6б), записано в план, **не исправлено** и тестом не закрыто.

## 11б. МОИ ОШИБКИ ПО ДОРОГЕ

Правило проекта: собственные ошибки в отчёт, отдельным разделом, а не в
примечание.

**1. Неверно разделил вызовы.** Отнёс `initialize`, `login`, `shutdown`,
`order_calc_margin` и `order_calc_profit` к денежным. Окно после этого
открывалось, но журнал запуска набрал 24 обрыва там, где код честно ждал
`False`. Разобрано в разделе 4, закрыто тестом и проверкой «наоборот 1».

**2. Починил падение и создал ложь.** Дав заглушке паспорт модуля, я
починил падение вкладки «Диагностика» — и тем самым заставил её
уверенно сообщать «MetaTrader5 — ok». Падающая вкладка плоха; вкладка,
которая врёт, хуже. Разобрано в разделе 4в, закрыто тестом и проверкой
«наоборот 5».

**3. Запустил окно из рабочей копии, не сохранив правки.** Программа
умеет обновлять сама себя из GitHub. При живой проверке она это и
сделала: скачала версии файлов из ветки и **затёрла мои несохранённые
правки** в `desktop_app.py` и `diagnostics.py`, оставив рядом `.bak`.
Правки восстановлены из `.bak`, состояние проверено прогоном (52 из 52),
после чего работа сразу закоммичена.

Это не только моя оплошность, но и **факт о программе, который стоит
знать**: запуская её из папки с исходниками, можно потерять несохранённые
изменения. К переносу на macOS отношения не имеет, в этап 1 чинить не
берусь — но записываю, чтобы это не всплыло неожиданно у кого-то ещё.
