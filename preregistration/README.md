# ПРЕДРЕГИСТРАЦИЯ ГИПОТЕЗ

Здесь лежат паспорта гипотез — условия исследования, записанные **до**
прогона.

## Зачем эта папка отдельная и почему она в репозитории

Разница между предрегистрацией и подгонкой не в намерениях, а в порядке
действий:

* **предрегистрация** — сначала записал условия, потом посмотрел результат;
* **подгонка** — сначала посмотрел результат, потом записал условия.

Постфактум эти два отчёта выглядят одинаково. Отличить их можно только по
времени.

Поэтому паспорта лежат **в репозитории**, а не в папке результатов
(`research/`, которая не отслеживается). Коммит с паспортом обязан быть
**раньше** коммита с результатами. Это единственное, что нельзя
подделать, не переписав историю.

## Как проверяющему убедиться

```
git log --oneline -- preregistration/manifest_h1.json   # когда появился паспорт
git log --oneline -- docs/                              # когда появились результаты
```

Первый коммит должен быть раньше второго.

Каждый паспорт заверен хешем своего содержимого. Прогон отказывается
работать, если паспорт изменился после заверения:

```
python3 -c "import sys; sys.path.insert(0,'ai_scalper_standalone'); \
            import research_manifest as m; \
            print(m.описание(m.прочитать('preregistration/manifest_h1.json')))"
```

## Что обязано быть в паспорте

Список из требований внешнего аудита: гипотеза, на чём основана, версия
данных с контрольной суммой, инструменты, таймфрейм, правила входа, смысл
сигнала, фиксированный выход, сценарий издержек, **критерий успеха
числом**, критерий провала, разделение истории, OOS и минимум сделок.

Незаполненное поле — это не «пока не решили». Недостающее условие всегда
можно дописать после того, как результат увиден, поэтому прогон по
неполному паспорту отвергается.
