# AI Scalper Standalone

Самостоятельная (не MQL5) программа на Python — торгует **сразу по списку
инструментов**, подключаясь напрямую к уже открытому терминалу MetaTrader 5.
Вся логика 1:1 портирована из проекта "AI Scalper Pro" (MQL5 EA, v8.0, папка
[`ai_scalper_pro/`](ai_scalper_pro/)): профили риска, авто-адаптация под
инструмент, режим рынка (тренд/флэт), Break Even/трейлинг/Profit Lock,
дневные лимиты и серии убытков, плюс AI-сигнал (Claude/ChatGPT) — встроен
напрямую, без отдельного HTTP-моста.

Оригинальный MQL5-советник **не тронут** и продолжает жить отдельно — это
независимый проект.

### Несколько торговых счетов

Программа умеет работать с несколькими счетами: список хранится в
`accounts.json`, пароли зашифрованы тем же механизмом, что и остальные
секреты (Fernet + PBKDF2, ключ из пароля входа).

Важно понимать ограничение MetaTrader: **один терминал может торговать
только одним счётом одновременно**. Поэтому:

- счёт, которому указан путь к своей копии `terminal64.exe`, получает
  отдельный процесс и работает **параллельно** с остальными;
- счета без своей копии обслуживаются **по очереди** одним процессом —
  программа сама предупредит об этом при запуске.

Чтобы счета работали по-настоящему параллельно, установите отдельную копию
терминала на каждый счёт (портативный режим) и укажите путь в настройках
счёта.

Модули: `accounts.py` (список и шифрование), `account_supervisor.py`
(процессы счетов, сбор состояния, команды закрытия).

## Desktop-приложение (.exe) — рекомендуемый способ запуска

Помимо запуска через `python main.py` из консоли, есть настоящее Windows-
приложение с окном — **всё внутри одной программы, браузер не нужен**.

При запуске сначала показывается **экран входа** (логин/пароль —
`DASHBOARD_LOGIN`/`DASHBOARD_PASSWORD` из `config.py`, те же, что и у
веб-дашборда) — без верного пароля окно программы не откроется. Галочка
**«Запомнить пароль»** сохраняет пароль на этом компьютере (зашифрован через
Windows DPAPI, привязан к учётной записи Windows — при переносе программы на
другой компьютер не расшифруется, придётся ввести пароль заново) — при
следующем запуске поле пароля уже предзаполнено, остаётся нажать «Войти».
Число попыток входа не ограничено. После входа торговый цикл **запускается
сам** (не нужно жать «Старт» руками) — кнопки Старт/Стоп остаются для ручной
остановки/перезапуска. В правом нижнем углу окна — подпись «made by
Viacheslav.Y.».

Два режима интерфейса (переключаются на вкладке «Обзор», хранится в
`UI_MODE` в `config.py`):

- **Простой** — Обзор / Символы / Сделки / Лог / **Настройка** / Как
  пользоваться. Минимум лишнего, максимум понятности.
- **Продвинутый** (ручной режим) — плюс Брокер / Equity / Новости / Chat AI.

Вкладки **«Настройка»** и **«Как пользоваться»** видны ВСЕГДА в обоих режимах —
специально, чтобы настройки и инструкцию нельзя было "не найти" в простом режиме.

Вкладки:

- **Обзор** — Старт/Стоп/Полный выход, счёт, статистика, переключатель
  Простой/Продвинутый, экспорт в Excel одной кнопкой.
- **Брокер** *(продвинутый)* — сервер/логин/пароль ЛЮБОГО MT5-брокера (не
  обязательно держать терминал открытым и залогиненным заранее — программа
  сама подключится), плюс кнопка проверки подключения.
- **Символы** — добавление/удаление символов прямо из интерфейса (без правки
  `config.py` руками), score/AI/режим/автообучение по каждой паре; двойной
  клик включает/выключает пару, задаёт фиксированный лот или открывает
  мини-график цены по этому символу.
- **Сделки** — ВСЕ открытые позиции счёта (не только этого бота, но и открытые
  вручную в терминале MT5 — колонка «Источник»: Бот/Ручная): тикет, тип, лот,
  **цена входа и текущая цена**, SL/TP, профит, **время открытия**; закрытие
  по кнопке работает для любой строки.
- **Лог** — верхняя таблица: журнал этого бота (свои сделки со score).
  Нижняя таблица — **синхронизация с MetaTrader**: история закрытых сделок
  напрямую из MT5 (`history_deals_get`), обновляется раз в минуту, включает
  ВСЕ сделки счёта за последние 30 дней (и открытые вручную тоже), со
  статистикой (винрейт/профит-фактор/вал. прибыль-убыток), которая на 100%
  совпадает с реальной историей у брокера.
- **Equity** *(продвинутый)* — график баланса.
- **Настройка** (видна всегда) — сверху быстрые переключатели (профиль
  риска / режим торговли / пауза / звук и всплывающие уведомления), ниже —
  полный паритет с окном "Inputs" MQL5-советника: ~90 входных параметров
  сгруппированных как в `config.py` (индикаторы, price action, объём,
  автонастройка под инструмент, защитные проверки, AI-сигнал, режим/контекст
  рынка, score-фильтр, стопы/TP, Break Even, трейлинг, Profit Lock,
  просадка/серии убытков, издержки, новости, автообучение, автообновление,
  часы торговли, лот, частичное закрытие), плюс отдельный редактор каждого
  профиля риска (`RISK_PROFILES`) и корреляций контекста рынка
  (`MARKET_CONTEXT`) по каждому символу. Кнопки "Сохранить" пишут прямо в
  `config.py` (атомарно, с бэкапом) и применяются сразу же через hot-reload —
  без перезапуска программы.
- **Источники** — одно место, где включаются и выключаются все источники
  данных: календарь MetaTrader 5, Finnhub и каналы/боты Telegram. Снял
  галочку — источник перестал использоваться. Видна всегда, в обоих режимах
  интерфейса: прятать единственный выключатель нельзя.
- **Календарь** — расписание работы бота: торгует он сейчас или нет и почему,
  график ближайших 12 часов с зонами блокировки, таблица «что и когда
  остановит торговлю» и спокойные окна. Подробнее — ниже.
- **Новости** *(продвинутый)* — полный список предстоящих событий. Настройка
  источников — на вкладке «Источники». Архитектура универсальная: новые
  источники добавляются в `news_providers.py` и сами появляются в списке.
- **Сигналы TG** *(продвинутый)* — что распознано из каналов и ботов Telegram.
- **Chat AI** *(продвинутый)* — чат с Claude прямо в программе, для вопросов
  по рынку/настройкам без переключения на другое окно.
- **Как пользоваться** (видна всегда) — подробная пошаговая инструкция по
  всем вкладкам и функциям программы, прямо внутри приложения.

Звуковые и всплывающие уведомления показываются при открытии/закрытии сделки
и при паузе после серии убытков (можно выключить на вкладке «Настройка»).

Значок в трее, автозапуск с Windows — тоже есть. Веб-дашборд в браузере
остался как отдельная возможность — **только для доступа с телефона** по
Wi-Fi, на самом компьютере он не нужен.

Собирается один раз в `.exe` (и по желанию — в установщик с ярлыками), после
этого Python на машине уже не нужен. См. **`BUILD.md`** — как собрать
`AI_Scalper_Pro.exe` и `AI_Scalper_Setup.exe` за два запущенных файла.

### Подключение к брокеру

По умолчанию (`MT5_LOGIN = 0` в `config.py`) — как и раньше, нужен уже открытый
и залогиненный терминал MT5. Если на вкладке **Брокер** ввести сервер/логин/
пароль и нажать «Сохранить» — программа будет сама запускать терминал и
логиниться этими данными при каждом старте, для **любого брокера с MT5-счётом**
(не обязательно SwitchMarkets — сервер и логин просто те, что дал твой
брокер при регистрации счёта, как при входе в MetaTrader 5). Пароль хранится
в `config.py` в открытом виде (как и пароль дашборда) — файл лежит только на
твоём компьютере, никуда не отправляется.

## Новости: бесплатный календарь MetaTrader 5

Экономический календарь MT5 (`CalendarValueHistory`) — это MQL5-only API,
python-пакет `MetaTrader5` его не отдаёт. Раньше из-за этого фильтр новостей в
программе работал только через сторонний API с ключом.

Теперь разрыв закрыт сервисом **`CalendarExport`** (`mql5/CalendarExport.mq5`):
он читает встроенный календарь терминала и раз в несколько минут кладёт его в
файл `MQL5/Files/calendar_export.json`, а программа этот файл читает. Путь она
находит сама через `terminal_info().data_path` — прописывать руками ничего не
нужно.

Что это даёт: **полностью бесплатный источник новостей** — без API-ключа, без
регистрации, без лимитов запросов. Это те же данные, что видны во вкладке
«Календарь» в самом терминале.

### Установка

1. Запустить `install/install-calendar.bat`.
2. В MetaEditor (F4): `Services` → `CalendarExport.mq5` → **F7** (компиляция).
3. В терминале: Навигатор (Ctrl+N) → **Сервисы** → правой кнопкой по
   `CalendarExport` → «Добавить сервис» → ОК → правой кнопкой → «Запустить».

Проверка: во вкладке «Журнал» терминала появится строка
`CalendarExport: записано событий: N`.

Сервис **ничего не торгует** и не занимает график. Разрешение на автоторговлю
ему не нужно.

### Цепочка источников

`NEWS_PROVIDER_CHAIN = ["mt5", "finnhub"]` — источники опрашиваются по порядку,
берётся первый, который ответил. Они закрывают слабые места друг друга:

| Источник | Плюс | Минус |
|---|---|---|
| `mt5` | Бесплатно, без ключа, без лимитов | Нужен открытый терминал с запущенным сервисом |
| `finnhub` | Работает, даже когда терминал закрыт | Нужен бесплатный ключ, есть лимиты тарифа |

Пустой список событий **не считается отказом** — на выходных новостей
действительно нет, и переключаться на другой источник из-за этого
неправильно. Переход дальше по цепочке происходит только при ошибке.

Файл календаря старше часа считается несвежим, и программа честно скажет об
этом, а не выдаст протухшие данные за актуальные: молча пропущенный выход NFP
опаснее, чем видимая ошибка.

### Часовые пояса — почему это важно

Календарь MT5 отдаёт время события в поясе **торгового сервера** (у многих
брокеров UTC+2/+3). Сервис пишет в файл смещение сервера относительно UTC, а
программа переводит время в местное. Без этого пересчёта фильтр блокировал бы
торговлю на несколько часов мимо реального выхода новости.

## Вкладка «Источники» — где всё включается и выключается

Одно место на все источники данных. Снял галочку — источник перестал
использоваться:

| Группа | Источники |
|---|---|
| Календарь новостей | Календарь MetaTrader 5, Finnhub (+ поле для ключа) |
| Сигналы Telegram | Каналы и боты (+ api_id, api_hash, роль сигнала) |

Рядом с каждым источником — его состояние: «файл обновлён 3 мин назад»,
«нужен ключ», «не установлена библиотека telethon». То есть видно не только
что включено, но и работает ли оно на самом деле.

Кнопка «Сохранить всё» пишет обе группы разом. Если снять галочку с Telegram,
чтение останавливается сразу, не дожидаясь перезапуска. Если выключить
**все** источники, программа переспросит: бот продолжит торговать, но
перестанет останавливаться перед выходом важных новостей.

Вкладка видна всегда, в обоих режимах интерфейса — прятать единственное
место, где источники выключаются, было бы неправильно.

Вкладки «Новости» и «Сигналы TG» теперь только показывают данные, настроек
там нет: раньше их приходилось искать по разным вкладкам, и легко было
поменять в одном месте, а действовало другое.

## Сигналы из Telegram (вкладка «Сигналы TG»)

### Почему нельзя просто подключить бота

Telegram **запрещает ботам видеть сообщения других ботов** — это не обход
настройки, а правило платформы: *«Bots will not be able to see messages from
other bots regardless of mode»* ([Bots FAQ](https://core.telegram.org/bots/faq)).
Сигналы от чужого бота-сигнальщика приходят **в ваш личный чат с ним**, и
прочитать их может только клиент, вошедший под вашим аккаунтом.

Поэтому используется Telethon (клиентский API Telegram). Нужны:

1. `api_id` и `api_hash` — бесплатно на
   [my.telegram.org](https://my.telegram.org) → **API development tools**;
2. одноразовый вход по номеру телефона и коду (кнопка «Войти в Telegram»).

После первого входа создаётся файл сессии, код больше не спрашивают. Файл
сессии в `.gitignore`, `api_hash` шифруется в `config.py` так же, как пароль
MT5 и ключи AI.

### Что чужой сигнал может и чего не может

Автор сигнала не знает ни вашего депозита, ни ваших лимитов, ни уже открытых
позиций. Поэтому границы жёсткие:

| Может | Не может |
|---|---|
| Добавить баллы к оценке, если совпал с направлением, которое программа выбрала **сама** | Открыть сделку |
| Запретить вход, противоречащий сигналу | Увеличить лот или риск |
| | Отодвинуть стоп-лосс |
| | Отменить дневной лимит или любой фильтр |

Это то же правило, что для ИИ-сигнала, и оно взято прямо из вашего исходного
задания: «ИИ и любые адаптивные правила никогда не могут: увеличить риск;
расширить уже установленный Stop Loss; отменить дневной лимит; открыть сделку
в обход локальных фильтров».

Надбавка ограничена **в коде**, а не только настройкой: даже если вписать в
`TELEGRAM_MAX_SCORE_BONUS` число 500, сигнал даст не больше 15 баллов. Самый
мягкий порог входа в профилях — 45, так что чужой сигнал физически не может
протолкнуть сделку в одиночку.

### Каналы и боты

В поле «Каналы и боты» на вкладке «Источники» пишутся имена через запятую:

```
@signals_channel, @my_crypto_signalsbot
```

Работают и каналы, и боты — читаются они одинаково. Разница одна: **на
закрытый канал нужно быть подписанным** вашим аккаунтом. Публичный канал
читается и без подписки.

### Если вход не проходит

Порядок такой:

1. **Установите библиотеку** — в командной строке: `pip install telethon`.
   Если её нет, программа так и напишет на вкладке «Источники».
   В собранном `.exe` она уже включена.
2. **Впишите `api_id` и `api_hash`** на вкладке «Источники» и нажмите
   «Сохранить всё». Без них кнопка входа откажет и подскажет, где их взять.
   Галочку «Читать сигналы из Telegram» при этом ставить необязательно —
   войти можно и до включения чтения.
3. **Нажмите «Войти в Telegram»**, введите номер в международном формате
   (`+79991234567`), затем код из приложения Telegram.
4. Если у аккаунта включена двухфакторная защита — программа спросит
   облачный пароль.

Ошибки теперь приходят по-русски: «Неверный код подтверждения», «Код
устарел», «Неверные api_id / api_hash», «Telegram временно ограничил попытки
входа, подождите N мин».

**Файл сессии переносить между компьютерами нельзя.** Telegram это замечает и
отзывает ключ. Если появилась ошибка про `telegram_session` — удалите этот
файл рядом с программой и войдите заново.

### Три режима (`TELEGRAM_ROLE`)

| Режим | Что делает |
|---|---|
| `show` — **по умолчанию** | Только показывает сигналы в программе. На торговлю не влияет вообще |
| `veto` | Плюс к показу: запрещает вход, противоречащий сигналу |
| `score` | Плюс к вето: совпавший сигнал добавляет баллы (с потолком) |

По умолчанию и само чтение выключено (`TELEGRAM_ENABLED = False`).
Подключение источника не должно молча менять поведение бота — включать роль
вы решаете сами.

### Ещё две вещи, которые стоит знать

**Молчание источника — не запрет.** Если сигналов нет, бот торгует как
обычно. Иначе отключение канала останавливало бы торговлю целиком.

**Протухший сигнал не применяется.** Через `TELEGRAM_SIGNAL_TTL_MIN` (по
умолчанию 30 минут) сигнал перестаёт учитываться: рекомендация часовой
давности к текущему рынку отношения уже не имеет.

**Чужие уровни не берутся.** Из сообщения читается только инструмент и
направление. Предложенные вход, стоп и цель игнорируются — свои уровни
программа считает от собственного ATR и вашего риска.

Если `telethon` не установлен или вход не выполнен, программа работает как
обычно, просто без сигналов, и пишет причину в журнал. Торговля не должна
зависеть от стороннего источника.

## Вкладка «Календарь» — когда бот работает, а когда нет

Отвечает на вопрос «почему сейчас нет сделок» и «когда он остановится
дальше». Три части:

**1. Строка состояния.** Зелёным «Сейчас: торгует» или красным «Сейчас: не
входит» с причиной: выходной, вне разрешённых часов, или конкретная новость —
с названием, списком затронутых пар и временем, когда вход откроется.

**2. График на 12 часов.** Засечка на каждое событие, подпись валюты и
заштрихованные красным зоны, в которых торговля заблокирована.

**3. Таблица «Что и когда остановит торговлю».** По каждому событию: окно
(с какого по какое время), что бот сделает, название новости, валюта и
затронутые пары. Идущее прямо сейчас окно подсвечено красным и помечено
«(идёт)». Внизу — **спокойные окна**: промежутки, в которые бот точно
свободен, чтобы это не приходилось вычитать в уме.

Показываются только события, затрагивающие **ваши** пары. Выход японской
статистики человеку, торгующему EURUSD и золотом, — это шум, в котором
теряется важное.

### Почему расписанию можно верить

`trading_schedule.py` — не второй, параллельный набор правил. Он повторяет
ровно те проверки, что стоят на входе в сделку, и читает **те же настройки**:
окно блокировки берётся из `NEWS_HARD_BLOCK_WINDOW_MIN`, разбор символа — той
же функцией, что у фильтра новостей, часы торговли — по той же логике, включая
диапазон через полночь.

Тесты сверяют оба места напрямую: расписание и настоящий фильтр входа
сравниваются во все 24 часа суток для четырёх вариантов настройки часов, и на
девяти смещениях вокруг новости (−45…+45 мин). Если кто-то поменяет фильтр
входа и забудет поменять расписание — тесты это поймают.

Что расписание **не делает**: не торгует, не меняет настройки и ни на что не
влияет. Это справочная вкладка.

Остальное (скальпинг-паттерн, риск-менеджмент, авто-адаптация под инструмент,
AI-сигнал, мульти-символьность) работает полноценно.

## Приватный режим — свои ключи прямо в репозитории

Обычно секреты в `config.py` шифруются паролем входа, а сам `config.py` в git
не попадает. Но это упирается в неудобство: **шифрование держится на пароле
входа.** Как только вход отключён (`REQUIRE_LOGIN = False`), получается тупик —
ключи в файле есть, а открыть их нечем.

Приватный режим убирает тупик честно: он не делает вид, что шифрует, а прямо
говорит, что защита теперь одна — **закрытый репозиторий и ваш компьютер**.

### Как включить

1. **Сначала** сделайте репозиторий приватным на GitHub:
   `Settings` → `General` → вниз до `Danger Zone` → `Change repository
   visibility` → `Make private`.
2. Запустите `install/enable-private-mode.bat`. Скрипт переспросит, приватный
   ли уже репозиторий, и только потом:
   - поставит `PRIVATE_MODE = True` в `config.py`;
   - уберёт `config.py` из `.gitignore`, чтобы git начал его сохранять.
3. Впишите свои ключи в программе (вкладки «Источники», «Брокер»).
4. Сохраните: `git add -A`, `git commit -m "Мои настройки"`, `git push`.

Отменить: `install/disable-private-mode.bat`.

### Что режим открывает и что нет

| Файл | В приватном режиме |
|---|---|
| `config.py` — настройки, ключи AI, ключ Finnhub, `api_hash`, пароль MT5 | **Сохраняется в git** |
| `telegram_session` — живой пропуск в ваш Telegram | Вне git **всегда** |
| `accounts.json` — логины и пароли счетов MT5 | Вне git **всегда** |
| `scalper.log`, `trades_log.csv` — номера счетов и балансы | Вне git **всегда** |
| `learning_state.json` — ваша личная статистика | Вне git **всегда** |

Почему не всё: `telegram_session` — это действующий пропуск, кто получит файл,
войдёт в ваш Telegram **без кода подтверждения**. Закрытый репозиторий не
повод класть туда живые пропуска: доступ к нему получают соавторы, интеграции
и сборочные скрипты. Тесты проверяют, что эти файлы физически не могут попасть
в переключаемый блок `.gitignore`.

### Что важно понимать

**Приватность не действует задним числом.** Всё, что уже попало в историю
git, пока репозиторий был публичным, там и осталось — закрытие репозитория
это не отменяет. Ключи, которые успели побывать в публичной истории, надо
считать скомпрометированными и заменить.

**Перед каждым `git push` проверяйте `git status`.** В списке не должно быть
`telegram_session`, `accounts.json` и файлов `.log`. Если они там появились —
значит `.gitignore` кто-то поправил лишнего.

## Безопасность

Программа рассчитана на то, что её можно перенести на другой компьютер, и при
этом посторонний, получивший доступ к файлам, не должен просто открыть
`config.py` в блокноте и увидеть пароли/ключи.

- **Шифрование секретов** (`secure_store.py`). MT5-пароль, ключи Claude/OpenAI
  и ключи новостных API хранятся в `config.py` НЕ открытым текстом, а в виде
  `"enc:..."` — зашифрованы паролем ВХОДА в программу (тем же, что вводится на
  экране входа desktop-приложения / в HTTP Basic Auth веб-дашборда). Сам
  пароль входа тоже не хранится напрямую — только его необратимый PBKDF2-хэш
  (`DASHBOARD_PASSWORD_HASH`). Расшифровка происходит один раз в памяти при
  входе — на диске секреты остаются зашифрованными всегда. Если скопировать
  `config.py` на другой компьютер без пароля — секреты бесполезны.
  При первом запуске новой версии происходит **автоматическая одноразовая
  миграция** старого (открытого) формата в новый — ничего вручную делать не
  нужно, сработает само на пароле, который уже стоит в файле. Если забыл
  пароль входа — секреты восстановить нельзя (осознанный компромисс), придётся
  вписать значения (пароль MT5, ключи AI/новостей) заново через интерфейс
  программы после смены пароля.
- **Экран входа** — без ограничения числа попыток (по явному решению
  пользователя), но неверный пароль просто не открывает окно программы.
- **Безопасная работа с файлами** (`safe_files.py`):
  - config.py переписывается атомарно (временный файл + подмена оригинала
    одной ОС-операцией) с проверкой синтаксиса ПЕРЕД заменой — сбой посреди
    записи (антивирус, отключение питания) не портит файл;
  - перед каждой перезаписью делается резервная копия (`config.py.bak1` ..
    `.bak5`, ротация);
  - `trades_log.csv` дозаписывается с немедленным flush+fsync (данные не
    теряются в кэше ОС при аварийном завершении) и сверяется по SHA-256 при
    каждом запуске программы — если файл менялся снаружи неё с прошлого
    раза, в лог и уведомления попадает предупреждение;
  - `config.py`, `trades_log.csv` и `scalper.log` при каждом запуске
    получают Windows ACL, ограничивающий доступ ТОЛЬКО текущим пользователем
    Windows (остальные локальные учётки этого компьютера доступа не имеют).
- Всё это — best-effort по отношению к торговле: если какой-то шаг защиты не
  удался (например, на сетевом диске нет ACL), программа не падает и не
  останавливает торговлю — просто пишет предупреждение в лог.

## Полный паритет с MQL5-советником (вкладка «Параметры»)

По просьбе пользователя добавлены недостающие входные параметры, которые
были в MQL5-советнике, но отсутствовали в первой версии Python-порта —
теперь их можно включить/настроить прямо на вкладке «Параметры», без правки
кода:

- **Часы торговли** (`USE_TRADING_HOURS`, `TRADING_START_HOUR`,
  `TRADING_END_HOUR`) — опциональное ограничение торговли определённым
  диапазоном часов (время сервера MT5), поддерживает диапазон через полночь
  (например 22–6). По умолчанию выключено — торгуем круглосуточно, как раньше.
- **Лот без риск-расчёта** (`USE_RISK_BASED_LOT`, `LOT_FALLBACK`) —
  переключатель "выключить расчёт лота по проценту риска" (как в советнике):
  если выключить — всегда торгуем фиксированным `LOT_FALLBACK`, зажатым в
  допустимый диапазон брокера.
- **Раздельные окна новостей** (`NEWS_HARD_BLOCK_WINDOW_MIN`,
  `NEWS_SOFT_PENALTY_POINTS`) — жёсткий блок входа рядом с высоковажной
  новостью и мягкий (настраиваемый) штраф score теперь используют раздельные
  окна времени, как в оригинале, вместо одного общего окна на оба случая.
- **Таймаут AI-запроса** (`AI_SIGNAL_TIMEOUT_MS`) — сколько миллисекунд
  ждать ответ Claude/OpenAI, прежде чем считать сигнал недоступным
  (fail-open, score не меняется).
- **Частичное закрытие позиции** (`USE_PARTIAL_CLOSE`,
  `PARTIAL_CLOSE_TRIGGER_POINTS`, `PARTIAL_CLOSE_PERCENT`) — при достижении
  профита в пунктах (авто-адаптируется под ATR инструмента, как и остальные
  пороги) закрывается часть позиции один раз за сделку, остаток продолжает
  вестись обычным Break Even/трейлингом/Profit Lock.

## Хедж-режим (только профиль «Истеричка») — ОТКЛЮЧЁН по умолчанию

При срабатывании сигнала профиль «Истеричка» умеет вместо выбора одной
стороны (BUY или SELL) по большему score открывать СРАЗУ ОБЕ — как только
хотя бы одна сторона прошла порог входа. Дальше каждая нога ведётся
совершенно ОБЫЧНО, теми же механизмами, что и любая другая сделка: свой
стоп-лосс, свой Break Even/трейлинг/Profit Lock/частичное закрытие.

**По факту реальных сделок пользователя выключено по умолчанию**
(`hedge_both_directions=False`): скриншот истории показал, что во флэте (цена
топчется на месте) ОБЕ ноги теряют на спреде одновременно — например,
nzdjpys buy и sell закрылись одна за другой обе с убытком около -100. Хедж
не «бесплатная подстраховка»: он гарантированно платит двойной спред за обе
стороны, а выигрывает только когда рынок уже явно направлен — то есть именно
тогда, когда открывать вторую (лишнюю) сторону не имело смысла. Идея была
опробована по просьбе пользователя, но по факту реальных убытков он же
попросил отключить.

Переключатель остался (не удалён) — при желании включается обратно вручную
на вкладке «Настройка» (поле «Хедж: при сигнале открывать сразу BUY и SELL»)
или прямо в `RISK_PROFILES` в `config.py`. В MQL5-советнике — тот же
переключатель, `g_effHedgeBothDirections` в `RiskManager.mqh` (сейчас `false`
и там же), тоже только для `PROFILE_HYSTERIC`.

**Если всё же включаешь** — учти: это агрессивная стратегия с реальными
деньгами, а не «бесплатный» способ удвоить сделки: гарантированно платится
спред по обеим ногам, риск ограничен только обычным стоп-лоссом каждой
стороны, а не отсутствием риска вовсе.

## Порог входа «Истерички» поднят с 30 до 45

По факту тех же реальных сделок: порог score 30 из 100 пропускал почти любой
рыночный шум, из-за чего BUY-score и SELL-score по одному символу нередко

Агрессивного (55) и Сбалансированного (62) — частота сделок остаётся
высокой, просто отсекаются сигналы нулевого качества.

## КРИТИЧНО: гарантия Risk:Reward минимум 1:3

По факту реальных сделок пользователя (скриншот истории: сделки закрывались
в плюс всего на +$1, при этом убытки были -$30…-$111+, счёт в минусе) была
найдена и устранена причина: денежная цель прибыли профиля
(`target_profit_money`, например у «Истерички» — $1) была фиксированной
константой, никак не привязанной к РЕАЛЬНОМУ денежному риску сделки (который
растёт вместе с `risk_percent × equity`, т.е. на депозите ~$100 000 стоп-лосс
0.1% ≈ $100). Итог — TP был примерно в 100 РАЗ меньше SL, обратное соотношение
риск/прибыль. Именно это соответствует картине на скриншоте.

Исправлено двумя независимыми механизмами (работают вместе):

1. **`USE_MAX_PROFIT_RIDE = True`** — фиксированного TP вообще нет, прибыль
   тянется трейлингом/Break Even/Profit Lock, пока цена не развернётся (см.
   раздел «Максимальная прибыль» ниже) — верхней границы прибыли нет вовсе.
2. **`MIN_RISK_REWARD_RATIO = 3.0`** (новая настройка, `config.py` и вкладка
   «Настройка» → «Стопы / TP») — жёсткий пол: даже если `USE_MAX_PROFIT_RIDE`
   выключат, а денежная цель профиля (`target_profit_money`) окажется меньше
   риска, TP всё равно НИКОГДА не будет меньше `SL × MIN_RISK_REWARD_RATIO`
   (реализовано в `risk_manager.apply_min_risk_reward_floor()`, применяется в
   обеих функциях расчёта TP — `calc_tp_distance` и `calc_tp_distance_money`).
   `RISK_REWARD_RATIO` (используется, когда TP считается не в деньгах) тоже
   поднят с 1.2 до 3.0.

Логика Risk:Reward 1:3, которую предложил пользователь, верна: если TP всегда
минимум в 3 раза больше SL, то даже при одном убыточном трейде на три
прибыльных (винрейт 25%) счёт остаётся в плюсе — то есть боту не обязательно
угадывать направление чаще, чем в половине случаев, чтобы зарабатывать.
Дословные примеры пользователя (на депозите $10 000: риск 0.5% → SL $50 / TP
$150; риск 1% → SL $100 / TP $300; SL $200 / TP $600) — арифметически верны и
именно так это теперь и считается в коде (пропорция TP = SL × 3, при разных
% риска на сделку абсолютные суммы SL и TP разные, но соотношение 1:3 — одно
и то же).

Заодно исправлен смежный баг в `trade_manager.execute_market_order`: при
`tp_dist=0` (нет TP, см. `USE_MAX_PROFIT_RIDE`) раньше по ошибке считалось
`tp = цена входа` (TP «прямо на входе» — сделка закрывалась бы мгновенно в
районе нуля) вместо правильного для MT5 `tp=0.0` («TP не выставлен вообще»).

**В MQL5-советнике этот блок НЕ менялся** — пользователь просил доработки по
максимальной прибыли/риск-реворду именно в программу (Python), советник как
отдельный инструмент это не затрагивает.

## Максимальная прибыль (`USE_MAX_PROFIT_RIDE`)

По просьбе пользователя «тянуть максимальную прибыль сколько возможно»:
вместо фиксированного Take Profit сделка ведётся ТОЛЬКО Break Even + ATR-
трейлингом + Profit Lock (см. `tm.manage_open_positions`) — закрывается,
когда цена разворачивается и выбивает трейлинг-стоп, а не по заранее
посчитанному TP. Включается/выключается на вкладке «Настройка» → «Стопы / TP»
(`USE_MAX_PROFIT_RIDE`). При выключении TP считается как раньше — но не может
опуститься ниже пола `MIN_RISK_REWARD_RATIO` (см. выше).

## Profit Lock отдавал рынку почти весь пик прибыли — исправлено

Жалоба пользователя (со скринами реальных сделок): позиция держала пиковый
плавающий профит $300-360, а закрывалась в районе $10-150 — почти вся
прибыль отдавалась обратно рынку при развороте цены. Диагноз: Profit Lock
фиксировал ФИКСИРОВАННЫЕ 50% от пика, а до того как сделка дорастала до
порога срабатывания (`PROFIT_LOCK_START_POINTS`), её защищал только крошечный
Break Even (10+ пунктов) — при быстром развороте между полными проходами
бота по всем парам это давало результат намного хуже 50%. Исправлено тремя
изменениями сразу (Python и MQL5-советник, обе копии):

- **`PROFIT_LOCK_PERCENT` 50 → 70.** Даже без ступенчатой фиксации базовый %
  теперь выше.
- **Ступенчатая (ratchet) фиксация — `USE_TIERED_PROFIT_LOCK`/
  `UseTieredProfitLock` (вкл. по умолчанию).** Чем выше КОГДА-ЛИБО достигнутый
  пик прибыли по сделке — тем больший % от него запирается стопом: 40% на
  пороге срабатывания, 55% при пике ×2 от порога, 70% при ×4, 85% при ×8
  (пороги — множители от эффективного, авто-масштабированного под ATR
  `PROFIT_LOCK_START_POINTS`). В Python задаётся списком `PROFIT_LOCK_TIERS`
  в `config.py` (тонкая настройка — руками в файле); в MQL5 — четырьмя парами
  input `ProfitLockTier1..4Mult/Pct`. Используется самый старший тир, до
  которого дорос пик.
- **Быстрый мониторинг открытых позиций — `POSITION_MONITOR_SECONDS`
  (Python-only, по умолчанию 1 сек).** MQL5-советник и так ведёт позиции на
  КАЖДОМ тике (`OnTick()` → `ManageOpenPositions()`), а Python-программа
  раньше подтягивала SL только раз за полный проход по всем парам
  (`POLL_SECONDS`, по умолчанию 5 сек) — при нескольких одновременно
  торгуемых парах сам проход не мгновенный (сетевые запросы к MT5), и резкий
  разворот между проходами оставался незамеченным. Теперь между полными
  проходами `_fast_position_monitor()` (см. `main.py`) каждые
  `POSITION_MONITOR_SECONDS` дополнительно подтягивает SL уже открытых
  позиций по последнему известному ATR — без дорогого повторного запроса
  баров у MT5.

## Profit Lock стартовал РАНЬШЕ безубытка — второй скрин, углублённый фикс

Даже после фикса выше пользователь прислал новый скрин (xauusd/btcusd,
профиль "Истеричка"): позиции закрывались за 1-9 СЕКУНД после открытия с
мелким плюсом ($10-97), а убыточные — за 1-2 секунды с полным убытком
($68-99), итог по группе сделок в минус. Более глубокий диагноз: порог
запуска Profit Lock (`PROFIT_LOCK_START_POINTS`, доля от ATR) СОВСЕМ НЕ
учитывал, насколько узкий стоп-лосс у конкретного профиля. У "Истерички"
(`atr_sl_multiplier=0.5` — самый узкий стоп из всех профилей) порог
срабатывания оказывался на уровне ~30% от риска сделки — РАНЬШЕ, чем даже
безубыток. Из-за этого на волатильном золоте обычный тик-шум (не разворот
тренда!) уже пересекал порог, и сделка фиксировалась в крошечный плюс
почти мгновенно; убыточная сторона тем временем отрабатывала стоп на всю
дистанцию — отсюда системная асимметрия "мелкие плюсы, крупные минусы".

Исправление (Python и MQL5-советник, обе копии): порог запуска Profit Lock
теперь не может быть меньше `PROFIT_LOCK_START_R_FRACTION` (по умолчанию
1.0) от **риска самой сделки** — расстояния между ценой входа и её
изначальным стоп-лоссом при открытии ("1R"), а не только от ATR. При
значении 1.0 фиксация прибыли вообще не стартует, пока сделка не отобьёт
свой собственный риск целиком; дальше уже работает ступенчатая фиксация
(см. выше) — чем выше пик, тем больше запирается. Изначальный риск
запоминается один раз при первом же взгляде на позицию (`update_position_
risk()` в `trade_manager.py` / `UpdatePositionRisk()` в `TradeManager.mqh`,
парный массив `g_posRiskPoints[]` в MQL5), до того как BE/трейлинг успеют
подтянуть SL ближе к цене.

## Собственная стратегия программы (`custom_strategy.py` / `CustomStrategy.mqh`)

Независимый модуль (`custom_strategy.py` в программе, `CustomStrategy.mqh` в
советнике — версия в докстринге/шапке файла, с CHANGELOG для будущих правок),
считает свой отдельный score 0..100 из четырёх факторов: импульс цены,
ускорение импульса, согласованность направления последних баров и расширение
диапазона (волатильности). Результат подмешивается к основному score с
ограниченным весом (`CUSTOM_STRATEGY_WEIGHT`/`CustomStrategyWeight`, по
умолчанию 15) — так же, как подмешивается AI-сигнал, а не заменяет основную
логику. Включается/выключается `USE_CUSTOM_STRATEGY`/`UseCustomStrategy`.
Текущее значение видно на вкладке «Символы» (колонка «Своя стратегия») и на
панели советника. По просьбе пользователя перенесена и в советник — раньше
была только в Python-программе, теперь синхронизирована в обеих версиях.

## Умнее score под режим рынка (`USE_ADAPTIVE_SCORE_WEIGHTS` / `UseAdaptiveScoreWeights`)

Вместо фиксированных весов компонентов score (Тренд20/Откат20/.../RSI5) — веса
подстраиваются под уже посчитанный режим рынка (тренд/флэт): в подтверждённом
ТРЕНДЕ структурные сигналы (тренд со старшего ТФ + паттерн pullback+breakout)
усиливаются (×1.15), в мин-реверсии (RSI запас хода) — ослабляются (×0.7); во
ФЛЭТЕ — наоборот, структурные сигналы ослабляются (×0.75), а RSI усиливается
(×1.6). Выключается флагом `USE_ADAPTIVE_SCORE_WEIGHTS`/`UseAdaptiveScoreWeights
= False` — тогда веса фиксированные, без изменений. По просьбе пользователя
перенесена и в советник — синхронизирована в обеих версиях (Python и MQL5).

## Хедж в обе стороны — ОТКЛЮЧЁН по умолчанию (`hedge_both_directions` / `HedgeBothDirections`)

Реальные сделки показали: во флэте/боковике одновременное открытие BUY и SELL
на один сигнал гарантированно платит спред на ОБЕИХ ногах — и если рынок не
делает явного движения, ОБЕ ноги проигрывают спреду одновременно (это видно
на скрине истории — например nzdjpy buy и sell потеряли по ~$100 в одно и то
же время). Поэтому хедж отключён по умолчанию в профиле «Истеричка»
(`hedge_both_directions=False`) в обеих версиях — это переключатель, фича не
удалена, просто выключена по умолчанию.

## Порог входа «Истерички» поднят с 30 до 45 (`min_score_to_trade` / `MinScoreToTrade`)

Порог 30 пропускал почти любой рыночный шум как «сигнал». Поднят до 45 —
вход только при более уверенном совпадении факторов score. Изменено в
обеих версиях (`config.py` и `RiskManager.mqh`, профиль HYSTERIC).

## Анти-«зеркало» фильтры входа

Жалоба пользователя: «каждую сделку он открывает в зеркале — когда вроде бы
хочет заработать, разворачивается, и получается убыток». Диагноз:
подтверждение свечи (price action) раньше было лишь мягким бонусом +15 к
score, а не обязательным условием — вход был возможен на уже истощённой/
разворачивающейся свече. Добавлены три независимых фильтра (каждый со своим
переключателем, включены по умолчанию по выбору пользователя «всё вместе»):

- **Жёсткий PA-фильтр** (`USE_PA_HARD_GATE`/`UsePAHardGate`, вкл. по умолч.) —
  если свеча сигнала не является настоящей бычьей/медвежьей подтверждающей
  свечой, score для этого направления принудительно = 0 (раньше — просто не
  получала бонус +15, но вход всё равно был возможен).
- **Блок входа во ФЛЭТЕ** (`BLOCK_ENTRY_IN_RANGE`/`BlockEntryInRange`, вкл. по
  умолч.) — раньше режим RANGE давал лишь штраф к score
  (`REGIME_RANGE_PENALTY`), теперь при включении вход в этом режиме
  блокируется полностью (действует даже для «Истерички», у которой
  `ignore_soft_filters=True` — это фильтр качества сигнала, а не
  издержек/исполнения).
- **Фильтр перегретой свечи** (`USE_EXHAUSTION_FILTER`/`UseExhaustionFilter`,
  вкл. по умолч., порог `EXHAUSTION_RANGE_ATR_RATIO`/`ExhaustionRangeATRRatio`
  = 2.0) — если диапазон (high-low) свечи сигнала больше чем в 2 раза
  превышает средний ATR, вход блокируется: слишком растянутая свеча часто
  означает, что движение уже исчерпано и вот-вот развернётся.

Реализовано и синхронизировано в Python (`signal_engine.py`) и в MQL5
(`SignalEngine.mqh`, `AI_Scalper_Pro.mq5`, обе копии советника).

## Доп. подтверждение классическими индикаторами (`USE_MULTI_INDICATOR` / `UseMultiIndicator`)

По просьбе пользователя «используй как можно больше индикаторов и торговых
стратегий» — третье независимое мнение (наряду с AI-сигналом и своей
стратегией): модуль `multi_indicator.py` / `MultiIndicator.mqh` считает
score 0..100 из трёх классических индикаторов:

- **MACD** (0..40) — согласованность линии MACD и сигнальной линии с
  направлением сделки + знак гистограммы (усиливающийся импульс).
- **Bollinger Bands / %B** (0..30) — положение цены внутри полос в СТОРОНУ
  сделки, но не у самого края канала (риск разворота у экстремума).
- **Stochastic %K/%D** (0..30) — классический разворотный сигнал: пересечение
  %K и %D при выходе из зоны перепроданности/перекупленности.

Подмешивается к основному score с ограниченным весом
(`MULTI_INDICATOR_WEIGHT`/`MultiIndicatorWeight`, по умолчанию 12) — той же
формулой, что и AI-сигнал и своя стратегия, не заменяет основную логику.
Включается/выключается `USE_MULTI_INDICATOR`/`UseMultiIndicator`. Текущее
значение видно на вкладке «Символы» (колонка «Индикаторы») и на панели
советника. Реализовано и синхронизировано в обеих версиях (в Python — расчёт
вручную через pandas в `indicators.py`; в MQL5 — через встроенные хендлы
`iMACD`/`iBands`/`iStochastic`).

## Кнопки «Закрыть прибыльные» / «Закрыть убыточные»

На вкладке «Сделки», рядом с «Закрыть ВСЕ сделки» — ещё две кнопки: **«Закрыть
прибыльные»** закрывает рынком ВСЕ позиции счёта с текущим плавающим профитом
≥ 0 (и бота, и открытые вручную), **«Закрыть убыточные»** — все с профитом < 0.
Обе — с подтверждением перед выполнением, как и «Закрыть все».

## Синхронизация с MetaTrader

По просьбе пользователя программа теперь показывает и сверяет данные
напрямую с MT5, а не только со своим внутренним журналом:

- **Все позиции счёта.** Вкладка «Сделки» и веб-дашборд показывают ВСЕ
  открытые позиции счёта — не только те, что открыл этот бот (magic number),
  но и открытые вручную в терминале MT5. Колонка «Источник» (Бот/Ручная)
  показывает, откуда взялась каждая сделка. Кнопка «Закрыть» работает для
  любой строки.
- **Полная история сделок.** Раз в `HISTORY_SYNC_SECONDS` (по умолчанию 60)
  программа подтягивает историю ЗАКРЫТЫХ сделок из MT5 (`history_deals_get`)
  за последние `HISTORY_SYNC_DAYS` (по умолчанию 30) дней — по ВСЕМ magic
  number, значит сюда попадают и сделки, открытые вручную. Показывается на
  вкладке «Лог» (нижняя таблица) отдельно от собственного журнала бота, со
  статистикой (винрейт, профит-фактор, валовая прибыль/убыток), которая
  всегда на 100% совпадает с реальной историей у брокера. Эта же история
  попадает в экспорт в Excel отдельным листом «История MT5».
- Всё это — только для показа/статистики/экспорта, НЕ влияет на торговые
  решения бота (пауза после серии убытков и автообучение по-прежнему
  считаются только по сделкам самого бота — так и задумано).

## Диагностика «сделки не открываются»

Если бот считает сигналы (видны score/AI на вкладке «Символы»), но ни одна
сделка не открывается — почти всегда дело не в логике бота, а в разрешениях
самого MT5. На вкладке «Обзор» появляется красное предупреждение, если
обнаружена одна из типичных причин (`mt5_connector.trading_permission_status()`,
проверяется каждую итерацию главного цикла):

- в терминале MetaTrader 5 выключена кнопка **«Algo Trading»** (AutoTrading) на
  панели инструментов — должна быть зелёной;
- торговля запрещена **на уровне счёта** (инвесторский/read-only пароль, либо
  брокер временно ограничил торговлю);
- в терминале выключено **«Разрешить автоматическую торговлю»**
  (Сервис → Настройки → Советники).

Предупреждение показывается, только пока проблема реально есть — как только
её устранишь, оно само пропадает при следующем обновлении вкладки.

## Закрыть все сделки одной кнопкой

На вкладке «Сделки» кнопка **«Закрыть ВСЕ сделки»** — закрывает АБСОЛЮТНО ВСЕ
открытые позиции счёта по рынку, и бота, и открытые вручную в терминале MT5,
с запросом подтверждения (показывает количество позиций). Работает так же
безопасно, как закрытие одной сделки — заявка кладётся в очередь и
исполняется в главном потоке бота (единственном, кто трогает MT5 API).

## Синхронизация торговых пар со списком брокера

На вкладке «Символы» поле «Добавить символ» — теперь выпадающий список
(`Combobox`), заполняемый РЕАЛЬНЫМИ символами брокера (`mt5.symbols_get()`,
обновляется раз в 5 минут). Рядом подпись показывает, сколько пар реально
доступно у брокера. Поле остаётся редактируемым (можно ввести символ,
которого ещё нет в кэше), но если вписанного символа нет в списке брокера —
программа предупредит и предложит похожие варианты (частая причина «добавил
пару, а она не работает» — опечатка или неверный суффикс, например `XAUUSD`
вместо `XAUUSDs`). Добавленные пары сохраняются в `config.py` (`SYMBOLS`) как
и раньше и подключаются на лету, без перезапуска.

## Скорость главного цикла

Главный цикл теперь делает **один** запрос открытых позиций и один запрос
информации по счёту за итерацию (вместо отдельного запроса на каждый
символ) — это самая частая причина задержки в 100+ мс при нескольких
торгуемых парах. Уже полученные данные передаются во все функции, которые
раньше сами обращались к MT5 (сопровождение позиций, подсчёт открытого
риска, обработка заявок на закрытие, снимок для интерфейса). Оставшееся
время цикла — это, по сути, сетевой обмен с терминалом MT5 и (если включён)
запрос к AI-провайдеру; сам Python-код между ними работает практически
мгновенно.

## Сколько тестировать перед реальными деньгами

Короткий ответ: **не по времени, а по числу сделок.** Ориентир — **не меньше
100 сделок на демо, лучше 200–300.** По календарю при 2–4 сделках в день на
пару это примерно **1,5–3 месяца**.

Почему не «неделю»: 20 сделок ничего не доказывают. Даже монетка выпадает
орлом 13 раз из 20 примерно в одном случае из семи. При 100 сделках и
винрейте 55% доверительный интервал — примерно **45–65%**, то есть результат
всё ещё может оказаться убыточным. Только на 300 сделках интервал сжимается
до ±6% и картина становится честной.

Отдельно: **программа не тестируется на истории.** Она подключается к живому
терминалу и работает только вперёд по времени. Тестер стратегий MetaTrader к
ней неприменим — прогнать «год за 10 минут» не получится. Это цена того, что
логика на Python, а не в советнике. Если нужен прогон по истории — для этого
есть MQL5-версия [`ai_scalper_pro/`](../ai_scalper_pro/), у неё та же логика,
и её можно гонять в тестере.

Разумный порядок:

| Этап | Сколько | Что проверяем |
|---|---|---|
| 1. Холостой ход (`LIVE_TRADING = False`) | 2–3 дня | Сигналы вообще появляются, программа не падает, в `trades_log.csv` идут строки `[DRY-RUN] OPEN`. Ордера при этом НЕ отправляются |
| 2. Демо, первый счёт | ~2 недели, 20–30 сделок на пару | Ордера реально доходят до брокера, стопы ставятся, автообучение накопило окно и включилось |
| 3. Демо, накопление | до 100–300 сделок суммарно | Появляется честная статистика: математическое ожидание, просадка, как ведут себя новые механизмы фиксации прибыли |
| 4. Реал, минимальный риск | ещё месяц | `RISK_PERCENT` в 2–4 раза меньше обычного. Реальное исполнение отличается от демо: проскальзывание, реквоты, реальный спред на новостях |

Про автообучение конкретно: подстройка **не включается вообще**, пока по
символу не наберётся `AUTO_LEARNING_MIN_TRADES` сделок (по умолчанию 5), а
полное окно — `AUTO_LEARNING_WINDOW` (20). То есть первые 5 сделок по каждой
паре бот работает на базовых настройках, и только к 20-й сделке цель прибыли
выучена по достаточной выборке. Гонять меньше 20 сделок на пару — значит
вообще не увидеть, как работает обучение.

Выученное **сохраняется между запусками** — в файл `learning_state.json`
рядом с программой, сразу после каждой закрытой сделки. Можно спокойно
выключать компьютер на ночь: статистика продолжится с того места, где
остановилась. Удалить этот файл = сбросить обучение и начать заново.

## Вкладка «Система» — мост, проверки, обновление

### Мост для советников — встроен

Советники MQL5 спрашивают у моста режим рынка по HTTP. Раньше мост был
отдельной программой: своя папка, свои зависимости (`fastapi`, `uvicorn`),
отдельная установка и отдельный запуск. Теперь он живёт **внутри программы**.

Сделан на встроенном в Python `http.server`: эндпоинта всего два, и тянуть
ради них десятки мегабайт зависимостей, которые пришлось бы ставить
отдельно, незачем.

- Слушает **только `127.0.0.1`** — адрес прибит в коде, настройки для него
  нет, наружу мост не открывается ни при какой конфигурации.
- Ответ моста — **ограничитель**: `risk_multiplier` зажат в 0.0–1.0, им
  советник может только **уменьшить** объём. Запрет торговли обнуляет
  множитель. Любой непонятный ответ модели превращается в безопасный отказ,
  а не в догадку.
- Включается галочкой на вкладке «Система», поднимается сам при запуске.

Один раз в терминале нужно разрешить обращение: **Сервис → Настройки →
Советники → «Разрешить WebRequest для»** и добавить `http://127.0.0.1:8080`.

### Проверка компьютера

Таблица «Что установлено на этом компьютере»: Python, терминал MetaTrader,
MetaEditor, советники, право записи в папку, свободное место, мост и все
библиотеки. У каждой строки — состояние (**есть / внимание / НЕТ**) и, если
что-то не так, **подсказка что делать**.

Полезно при переносе на другой компьютер: сразу видно, чего не хватает, а не
приходится гадать, почему «не работает».

### Обновление из GitHub — без переустановки

Правки кода уезжают на GitHub, программа скачивает их сама.

| Что | Когда применяется |
|---|---|
| Советники и сервис (`.mq5`, `.mqh`) | **Сразу**, без перезапуска — это обычные файлы, программа их ставит и пересобирает |
| Сама программа (`.exe`) | При следующем запуске: работающий файл Windows держит, поэтому подмена делается на старте |

Настройки: репозиторий в виде `владелец/название`, ветка, и токен GitHub —
он нужен **только для закрытого репозитория** (Settings → Developer settings
→ Personal access tokens → Fine-grained, права `Contents: Read-only`). Токен
шифруется наравне с ключами API.

**Обновление никогда не ставится молча.** Даже при автоматической проверке
программа спрашивает согласие. Подменять торгового робота, пока у вас открыты
позиции, без ведома человека недопустимо.

Если скачалась только часть файлов — установка **отменяется целиком**. Смесь
старых и новых файлов даёт советник, который не собирается.

## Установка одним файлом — ничего отдельно ставить не нужно

Собранный `AI_Scalper_Setup.exe` содержит **всё**: сам Python, все библиотеки
(включая `telethon` для Telegram) и исходники советников. На компьютере не
нужен ни Python, ни `pip install`, ни ручное копирование файлов в MetaTrader.

**При первом запуске программа сама:**

1. Находит все установленные терминалы MetaTrader 5 — и обычные, и портативные.
2. Копирует в каждый:
   - `AI_Scalper_Pro.mq5` и его заголовки → `MQL5/Experts`
   - `DualGuardEA.mq5` → `MQL5/Experts`
   - `CalendarExport.mq5` → `MQL5/Services`
3. **Компилирует их** — MetaEditor умеет собирать из командной строки, поэтому
   жать F7 вручную не нужно.

Всё это происходит в фоне, окно не замирает. Повторно программа не лезет:
если сервис календаря уже на месте, установка считается сделанной.

Заново запустить можно кнопкой **«Установить в MetaTrader»** на вкладке
«Источники» — например, если поставили новый терминал.

### Если что-то не вышло

Программа скажет причину словами, а не промолчит:

| Сообщение | Что делать |

Папка [`install/`](../install/) с отдельными `.bat` осталась как запасной
путь — на случай, если автоматическая установка почему-то не сработала.

## Веб-дашборд — просмотр и управление с телефона

При старте программа поднимает локальный веб-сервер (`USE_WEB_DASHBOARD = True`
в `config.py`, порт `DASHBOARD_PORT`, по умолчанию 5000).

1. Телефон должен быть в **той же Wi-Fi сети**, что и компьютер с ботом.
2. В консоли при запуске увидишь строку вида
   `Веб-дашборд запущен: http://192.168.1.23:5000` — открой этот адрес в
   браузере на телефоне.
3. На странице видно:
   - баланс/эквити счёта, режим (LIVE/DRY-RUN), текущий профиль риска и режим торговли;
   - мини-график equity (обновляется вместе со статусом, копится в памяти пока работает бот);
   - статистика: винрейт, профит-фактор, валовый профит/убыток, P/L за день %, просадка %;
   - таблица по каждому символу: score BUY/SELL, режим рынка (тренд/флэт), AI-сигнал,
     до какого времени пауза после серии убытков, причина последнего отказа от входа;
   - открытые сделки (символ/тип/лот/цена/SL/TP/профит) с кнопкой закрытия;
   - лог сделок (последние 50) с направлением, ценой, SL/TP, лотом, score и профитом.
   Всё обновляется само каждые 4 секунды.
4. Кнопка **"Пауза"** останавливает открытие НОВЫХ сделок — уже открытые
   продолжают вестись (трейлинг/Break Even/Profit Lock не отключаются).
   У каждой открытой сделки есть кнопка **"Закрыть"**.
5. Профиль риска и режим торговли можно менять прямо на странице (выпадающие
   списки + кнопка "Применить") — действует немедленно, **без перезапуска**
   `python main.py`. Если ничего не менять — используются значения из
   `config.py` (`RISK_PROFILE`/`TRADING_MODE`) как обычно.
6. В таблице символов — галочка **вкл/выкл пары** (выключает только НОВЫЕ
   входы, открытые сделки продолжают вестись) и поле **лота**: если вписать
   число и нажать "Ок" — бот торгует этим фиксированным лотом вместо расчёта
   по риск-профилю; 0 (или пусто) — снова авторасчёт по риску.
7. Колонка **"Автообучение"** показывает, что происходит с адаптацией по
   символу: пока сделок мало — "копит данные", дальше — текущий винрейт
   последних сделок (см. ниже).

Вся страница (не только кнопки) закрыта логином/паролем —
`DASHBOARD_LOGIN` / `DASHBOARD_PASSWORD` в `config.py`. При первом заходе
браузер на телефоне покажет системное окно входа и запомнит его до закрытия
браузера. Не пробрасывай порт наружу через роутер — доступ рассчитан только
на локальную Wi-Fi сеть.

## Автообучение (`auto_learning.py`)

Без "чёрной магии" — просто плавная подстройка по факту закрытых сделок,
отдельно на каждый символ:

- Берутся последние `AUTO_LEARNING_WINDOW` сделок по символу (по умолчанию 20).
  Пока их меньше `AUTO_LEARNING_MIN_TRADES` (по умолчанию 5) — подстройки нет,
  используются обычные настройки профиля.
- Винрейт выше 50% → бот **немного больше доверяет AI-сигналу** (множитель веса
  растёт к `AI_WEIGHT_MULT_MAX`, по умолчанию x1.5) и **немного охотнее входит**
  (порог score снижается, минимум на `SCORE_THRESHOLD_ADJUST_MIN`, по умолчанию -10).
- Винрейт ниже 50% → наоборот: меньше веса AI (до `AI_WEIGHT_MULT_MIN`, x0.5) и
  строже порог входа (выше на `SCORE_THRESHOLD_ADJUST_MAX`, по умолчанию +15).
- Всё в жёстких границах — бот не может полностью "разучиться" или стать
  неконтролируемо агрессивным. Выключается флагом `USE_AUTO_LEARNING = False`.

### Обучение цели прибыли (`USE_TP_LEARNING`)

Бот запоминает, **на сколько пунктов каждая закрытая сделка успевала уйти в
плюс до разворота** — то есть сколько рынок реально даёт по этой паре, а не
сколько нам хотелось бы. Берётся **медиана** этих пиков за последние сделки,
и тейк-профит ставится на `TP_LEARN_FRACTION` от неё (по умолчанию 70%) —
чтобы выходить **до** разворота, а не смотреть, как прибыль тает.

Медиана, а не среднее: одна аномальная сделка на новостях (+5000 пунктов)
сдвинула бы среднее и заставила бота ждать недостижимой цели во всех
остальных сделках. Медиана к таким выбросам нечувствительна.

Пока сделок меньше `AUTO_LEARNING_MIN_TRADES`, цель берётся от ATR
(`TP_TIGHTEN_START_ATR`). Выученная цель зажата между `TP_LEARN_MIN_POINTS`
и `TP_LEARN_MAX_POINTS`.

### Обучение сохраняется между запусками (`USE_LEARNING_PERSISTENCE`)

Раньше окно обучения жило только в памяти процесса: при каждом запуске
программы статистика обнулялась. Для того, кто выключает компьютер на ночь,
это означало, что **самообучение не работало вообще** — бот вечно оставался
в фазе «копит данные» и ни разу не доходил до `AUTO_LEARNING_MIN_TRADES`.

Теперь оба окна (результаты сделок и пики прибыли) пишутся в
`learning_state.json` рядом с программой — **сразу после каждой закрытой
сделки**, а не при выходе: аварийное завершение или отключение питания не
должны стирать накопленное. Запись атомарная, испорченного файла посреди
сохранения не бывает.

Файл — обычный JSON, его можно открыть блокнотом и посмотреть, чему бот
научился. Удалить файл = сбросить обучение. В `.gitignore` он внесён: это
ваша личная статистика, в репозиторий она не попадает.

Если файл повреждён или сделан другой версией — это не ошибка: программа
запишет предупреждение в журнал и начнёт копить статистику заново.
Уменьшили `AUTO_LEARNING_WINDOW` между запусками — восстановятся только
последние записи, по новому размеру окна.

## Фиксация прибыли: подтягивание тейк-профита

Раньше при `USE_MAX_PROFIT_RIDE = True` сделка открывалась **вообще без
тейк-профита** — её вёл только трейлинг стопа, и закрывалась она лишь тогда,
когда цена разворачивалась и выбивала стоп. Это давало максимум прибыли на
сильном движении, но означало долгое сидение в сделке.

Теперь работает `USE_TP_TIGHTEN`. Правило зеркально правилу для стоп-лосса:

> **Тейк-профит можно только приближать к цене. Никогда не отодвигать дальше.**

Почему именно так: отодвинутый TP — это скрытое увеличение риска. Сделка
висит дольше, дольше платит своп и дольше подставляется под разворот.
Приближённый TP только ускоряет фиксацию, хуже сделке от этого стать не может.

Как это выглядит:

1. Цель прибыли берётся из выученной статистики (см. выше) или, пока данных
   мало, из ATR: `TP_TIGHTEN_START_ATR × ATR` (по умолчанию 1.5 × ATR).
2. Если у сделки TP ещё не было — он выставляется.
3. Дальше цель **ужимается со временем**: каждую минуту жизни сделки на
   `TP_TIGHTEN_SHRINK_PER_MINUTE` (по умолчанию 10%), но не ниже
   `TP_TIGHTEN_MIN_FRACTION` от стартовой (25%). Чем дольше сделка «не едет»,
   тем скромнее становится цель — так позиция не зависает на весь день.
4. TP при этом **никогда не оказывается в убытке**: не ближе
   `TP_TIGHTEN_MIN_PROFIT_POINTS` от цены входа и не ближе минимальной
   дистанции, которую разрешает брокер.
5. Перенос мельче `TP_TIGHTEN_STEP_POINTS` не отправляется — сервер зря не
   дёргается.

Возраст сделки считается **по часам самой программы**, а не по времени
сервера брокера: `position.time` в MT5 — это время торгового сервера, у
многих брокеров UTC+2/+3, и разница в три часа превратила бы только что
открытую сделку в «висит три часа». Побочный эффект: для позиции, открытой
до запуска программы, отсчёт начинается с момента, когда программа её
впервые увидела — то есть ошибка всегда в безопасную сторону (цель сожмётся
позже, а не раньше времени).

## Спасение убыточной сделки в безубыток (`USE_BREAK_EVEN_RESCUE`)

Сделка, которая заметно ушла в минус и вернулась к нулю, уже показала, что
вход был неудачным: рынок сходил против неё. Ждать от такой сделки полной
цели — значит чаще всего отдать обратно и этот возврат.

Условия включения (все три сразу):

- просадка была глубже `BE_RESCUE_MIN_DRAWDOWN_POINTS` (по умолчанию 20 пт);
- сделка висит дольше `BE_RESCUE_AFTER_MINUTES` (по умолчанию 10 минут);
- цена вернулась к `BE_RESCUE_EXIT_POINTS` (по умолчанию +3 пт — «ноль» с
  запасом на спред и комиссию).

Тогда сделка закрывается. Если она ещё в минусе — тейк-профит просто
переносится на уровень безубытка, и сделка закроется сама, как только рынок
её туда вернёт, даже если программа в этот момент занята другими символами.

**Чего этот механизм НЕ делает — важно:**

- не трогает стоп-лосс, не отодвигает и не отменяет его;
- не увеличивает объём и не открывает встречных сделок;
- не удерживает убыточную позицию дольше обычного.

Это **только дополнительный выход раньше**. Если рынок не вернёт сделку к
нулю — её закроет обычный стоп-лосс на своей исходной дистанции, ровно как и
до появления этой настройки.

## Автообновление

- **Конфиг на лету**: если поправить `config.py` вручную, пока `python main.py`
  работает — изменения подхватываются сами (без перезапуска), проверка раз в
  `CONFIG_RELOAD_CHECK_SECONDS` (по умолчанию 15 сек). Новые символы из
  `SYMBOLS` подключаются автоматически. Исключение: не меняй `MAGIC_NUMBER`
  на лету — тогда бот перестанет видеть уже открытые им позиции. Выключается
  флагом `USE_CONFIG_HOT_RELOAD = False`.
- **Автопереподключение к MT5**: если терминал закрылся/разлогинился, бот сам
  пробует переподключиться после `RECONNECT_AFTER_FAILURES` неудачных опросов
  подряд (по умолчанию 5), не требуя ручного перезапуска. Выключается флагом
  `USE_AUTO_RECONNECT = False`.
- **Защита от падения цикла**: неожиданная ошибка на одной итерации логируется
  и не убивает процесс целиком — бот продолжает работать на следующем опросе.

## Выбор пары и лота (с дашборда)

Без правки кода, прямо со страницы дашборда:
- галочка на пару — включает/выключает открытие НОВЫХ сделок по ней (уже
  открытые позиции продолжают вестись как обычно);
- поле лота — фиксированный размер лота вместо расчёта по риск-профилю;
  0 или пусто = снова авторасчёт по риску профиля.

## Desktop-приложение подробнее (`desktop_app.py`)

Окно на Tkinter (без сторонних зависимостей для интерфейса) поверх того же
торгового движка:

- **Экран входа** перед открытием окна — логин/пароль как у веб-дашборда
  (`DASHBOARD_LOGIN`/`DASHBOARD_PASSWORD`).
- **Автозапуск бота вместе с программой** — торговый цикл стартует сам сразу
  после входа, вручную жать «Старт» не нужно. Кнопки Старт/Стоп/Полный выход
  остаются для ручного управления. Веб-дашборд поднимается один раз при
  старте программы и работает независимо от Старт/Стоп бота.
- В окне сразу видно баланс/эквити, режим, профиль, винрейт, P/L и просадку —
  то же самое, что и на веб-дашборде, но без открытия браузера.
- **Полный выход** — отдельная кнопка и пункт в трее: останавливает бота и
  гарантированно завершает процесс (`os._exit`), ничего не остаётся в
  Диспетчере задач (в отличие от простого закрытия окна, которое сворачивает
  программу в трей).
- Кнопки **"Открыть дашборд"**, **"Открыть логи"**, **"Открыть config.py"**,
  **"Экспорт в Excel"** (сделки + статистика в один .xlsx файл, `openpyxl`).
- Звуковые + всплывающие уведомления о сделках (открытие/закрытие, серия
  убытков) — можно выключить на вкладке «Настройки».
- Мини-график цены по каждому символу — двойной клик на названии символа
  на вкладке «Символы».
- Галочка **"Запускать бота вместе с Windows"** — автозапуск через реестр
  (`HKCU\...\Run`), без прав администратора.
- Значок в системном трее (если установлены `pystray`+`Pillow` — они уже в
  `requirements.txt`): закрытие окна сворачивает в трей, а не завершает бота;
  из меню трея — Старт/Стоп/Показать окно/Полный выход.
- Логи пишутся в `scalper.log` рядом с программой (при сборке `--windowed`
  консольного окна нет, поэтому весь вывод — в файл и в само окно).

Сборка в `.exe` и установщик Windows — см. **`BUILD.md`**.

## Новости (`news_calendar.py` + `news_providers.py`)

MT5 не даёт доступа к своему экономическому календарю из Python, поэтому
новости берутся из внешнего API. Архитектура — универсальная/плагинная:
`news_providers.py` хранит реестр `PROVIDERS = {"finnhub": fetch_finnhub, ...}`,
чтобы добавить новый источник — достаточно написать одну функцию
`fetch_<name>(api_key, from_date, to_date)` и зарегистрировать её; вкладка
«Новости» и вся логика фильтра подхватят её автоматически, без правки
остального кода. Провайдер и ключ задаются на вкладке «Новости» (или в
`NEWS_API_PROVIDER`/`NEWS_API_KEYS` в `config.py`). Пока ключ не задан —
всё работает как раньше: fail-open, новости не блокируют и не влияют на вход.
Учти: у бесплатных тарифов есть лимиты на частоту запросов, поэтому ответы
кэшируются на 10 минут.

## Структура проекта

- `main.py` — точка входа, мульти-символьный цикл, hot-reload конфига, автопереподключение.
- `desktop_app.py` — настольное Windows-приложение (окно, трей, Старт/Стоп) — точка входа для .exe/установщика.
- `build_exe.bat` / `installer.iss` / `BUILD.md` — сборка `.exe` и установщика Windows.
- `config.py` — все настройки (аналог `Config.mqh`), включая автообучение и автообновление.
- `auto_learning.py` — адаптивный вес AI и порог входа по недавнему винрейту символа.
- `mt5_connector.py` — обёртка над пакетом `MetaTrader5`.
- `indicators.py` — EMA/ATR/ADX/RSI/price-action на pandas (аналог `Indicators.mqh`).
- `market_regime.py` — тренд/флэт (аналог `MarketRegime.mqh`).
- `market_context.py` — сверка с коррелирующими инструментами (аналог `MarketContext.mqh`).
- `signal_engine.py` — единый score (аналог `SignalEngine.mqh`).
- `risk_manager.py` — профили риска, лот (с учётом override с дашборда), TP/SL, лимиты (аналог `RiskManager.mqh`).
- `trade_manager.py` — Break Even/трейлинг/Profit Lock, отправка ордеров (аналог `TradeManager.mqh`).
- `news_calendar.py` — фильтр/пробой по новостям, реальные данные через `news_providers.py`.
- `news_providers.py` — универсальный реестр источников экономического календаря (сейчас Finnhub).
- `secure_store.py` — шифрование секретов config.py паролем входа (PBKDF2 + Fernet), хэш пароля дашборда.
- `safe_files.py` — атомарная запись, резервные копии, проверка целостности (SHA-256), Windows ACL.
- `ai_signal.py` — интеграция Claude/OpenAI напрямую (аналог `bridge_ai_market_analysis.py`, но без Flask).
- `state.py` — рантайм-состояние (по счёту в целом и по каждому символу отдельно, включая окно автообучения и мини-график цены).
- `web_dashboard.py` — Flask-страница для просмотра/управления с телефона.
- `dashboard_state.py` / `control.py` — потокобезопасный обмен между главным
  циклом торговли, веб-дашбордом и desktop-приложением (снимок состояния,
  очередь команд, вкл/выкл пар, override лота, профиль/режим "на лету",
  очередь уведомлений о сделках).
- `list_symbols.py` — разовый скрипт: покажет точные названия символов у твоего брокера.

## Что проверено

Логика прогнана сквозным smoke-тестом (синтетические котировки, все модули
импортируются и отрабатывают без ошибок: расчёт индикаторов, score,
риск-фильтры, открытие/сопровождение позиции, обработка закрытой сделки).
Это НЕ заменяет тест на реальном демо-счёте — обязательно прогони минимум
несколько дней на демо с `LIVE_TRADING=False`, прежде чем включать реальные ордера.
